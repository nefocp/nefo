# Программное обеспечение

Nefo ничего не устанавливает, пока вы не выберете. Страница **Программы** устанавливает и удаляет каждый необязательный компонент и показывает, сколько примерно памяти он расходует: веб-сервер, PHP с 5.6 по 8.6 и ionCube Loader, MariaDB или MySQL, PostgreSQL, Redis, Memcached, Node.js, Python, Java, Docker, веб-брандмауэр и ClamAV. Панель не позволяет удалить то, чем ещё что-то пользуется.

Здесь описано, что можно установить, когда удаление запрещено, что остаётся после удаления, а также настройки PHP, Node.js, Python, Java и Redis. Небольшой сервер остаётся лёгким, если на нём есть только то, чем пользуются его сайты.

Установка и удаление выполняются как задачи с журналом в реальном времени. Панель выполняет одну задачу за раз. Программы устанавливаются из пакетов вашего дистрибутива, если на этой странице не сказано иное.

## Что можно установить {#what-you-can-install}

На каждой карточке показано, сколько примерно памяти занимает элемент во время работы. Вверху страницы эти значения суммируются для установленных элементов.

| Раздел | Элемент | Память, примерно |
|---|---|---|
| **Nginx, Apache или OpenLiteSpeed** | Nginx | около 15 MB |
| | Apache | около 40 MB |
| | OpenLiteSpeed | около 26 MB |
| **Версии PHP** | PHP 7.4, 8.0, 8.1, 8.2, 8.3, 8.4, 8.5 и 8.6 (и более новые, когда они появятся в репозитории PHP), а в разделе **Старые версии** — 5.6, 7.0, 7.1, 7.2 и 7.3 | около 25 MB каждая |
| | ionCube Loader | собственной памяти не занимает: он загружается в процессы PHP |
| **Базы данных и кэш** | MariaDB (из вашего дистрибутива или 11.4, 11.8 либо 12.3 LTS из репозитория MariaDB) или вместо неё MySQL 8.4 LTS | MariaDB: её буферный пул плюс около 100 MB (см. [Базы данных](./databases#how-mariadb-is-tuned)). MySQL: её буферный пул плюс около 150 MB или плюс около 300 MB, если оперативной памяти примерно от 3,5 GB (см. [Базы данных](./databases#how-mysql-is-tuned)) |
| | PostgreSQL | около 30–40 MB в простое, растёт до `shared_buffers` плюс около 40 MB (см. [PostgreSQL](./postgresql#how-postgresql-is-tuned)) |
| | Redis | до 64, 128 или 256 MB в зависимости от объёма памяти сервера |
| | Memcached | до 64, 128 или 256 MB в зависимости от объёма памяти сервера; несколько MB, пока он пуст |
| | Adminer (интерфейс баз данных) | нисколько в простое |
| | phpMyAdmin (интерфейс баз данных) | нисколько в простое |
| **Среды выполнения** | Node.js | нисколько в простое |
| | Приложения Python | нисколько в простое |
| | Java (OpenJDK) | нисколько в простое; Java-программа сайта-приложения занимает столько, сколько нужно её куче |
| **Контейнеры** | Docker | около 90 MB плюс ваши контейнеры |
| **Безопасность** | Веб-брандмауэр (ModSecurity) | около 40 MB |
| | Антивирус ClamAV | около 15 MB и около 1,4 GB свободной памяти во время проверки |
| **Инструменты** | Composer | нисколько, он запускается только по вызову |
| | WP-CLI | нисколько, он запускается только по вызову |

## Установка элемента {#install-an-item}

1. Откройте **Программы**.
2. Нажмите **Установить** на карточке элемента.
3. Следите за журналом. Когда задача завершится, на карточке появятся **Установлено** и версия.

После этого на некоторых карточках есть ссылка: **Открыть базы данных**, **Открыть PostgreSQL**, **Открыть Redis**, **Открыть Memcached**, **Открыть Adminer**, **Открыть phpMyAdmin** или **Открыть Docker**.

## Удаление элемента {#uninstall-an-item}

1. Нажмите **Удалить** на карточке элемента. У версии PHP эта команда находится в меню версии.
2. Прочитайте в диалоге, что сделает удаление.
3. Для MariaDB, MySQL, PostgreSQL и Docker можно отметить флажок, чтобы удалить и их данные. Тогда для подтверждения нужно ввести название элемента.
4. Нажмите **Удалить**.

### Когда удаление запрещено {#when-an-uninstall-is-refused}

Панель никогда не удаляет программы, которые ещё что-то использует. Если элемент нельзя удалить, на его карточке вместо рабочей кнопки показана причина.

| Элемент | Удаление запрещено, пока |
|---|---|
| Веб-сервер | Существует хотя бы один сайт — в панели или в виде файла конфигурации в папке сайтов веб-сервера |
| Версия PHP | Её использует какой-либо сайт или это единственная установленная версия PHP (она нужна для настройки веб-сервера и для Adminer). Поддерживаемая версия (7.4 или новее) также остаётся, пока она единственная рядом со [старыми версиями](#older-php-versions) |
| Composer | Скрипт развёртывания из Git запускает `composer` |
| WP-CLI | Есть сайты на WordPress: инструменты WordPress запускают его для них |
| MariaDB или MySQL | В нём есть хотя бы одна база данных, кроме его собственных системных баз. Панель спрашивает сам сервер баз данных, поэтому учитываются и базы, созданные вручную или другим инструментом. Если сервер остановлен, а его папка данных перенесена, панель не может это проверить и запрещает удаление |
| PostgreSQL | В PostgreSQL есть хотя бы одна база данных, кроме `postgres`, `template0` и `template1`, по данным самого PostgreSQL, или он остановлен, так что панель не может это проверить |
| Node.js | Сайты-приложения используют Node.js сервера по умолчанию, или `node` в `/usr/local/bin` установлен не панелью |
| Строка в **Версии Node.js** | Это версия сервера по умолчанию, или её выбрал какой-либо сайт-приложение |
| Приложения Python | Сайты-приложения работают на Python |
| Java (OpenJDK) | Какой-либо сайт-приложение работает на Java. Отдельную версию Java нельзя удалить, пока её использует сайт-приложение |
| Docker | Сайты используют Docker-приложения, существуют проекты Compose или в Docker есть контейнеры, работающие или остановленные |

Redis, Memcached, Adminer, phpMyAdmin, ionCube Loader, веб-брандмауэр и ClamAV можно удалить всегда.

| Версия PHP | | Версия, её расширения и библиотеки, которые были нужны только им |

При повторной установке MariaDB использует её | Пакеты сервера и клиента, настройки MariaDB от панели, а также репозиторий MariaDB с его ключом, если MariaDB была установлена оттуда |
| MySQL | Папка данных `/var/lib/mysql`, если вы не отметите **Также удалить каталог данных (/var/lib/mysql)** и не введёте `mysql`. При повторной установке MySQL использует её | Пакеты сервера и клиента, настройки MySQL от панели и репозиторий Oracle с его ключом |
| PostgreSQL | Данные в `/var/lib/postgresql` и настройки кластера в `/etc/postgresql`, если вы не отметите **Также удалить данные и настройки (/var/lib/postgresql и /etc/postgresql)** и не введёте `postgresql`. Пакеты удаляются без очистки (purge), и при повторной установке PostgreSQL запускается тот же кластер | Пакеты PostgreSQL, а также репозиторий apt.postgresql.org с его ключом (`/etc/apt/sources.list.d/panel-pgdg.list` и `/etc/apt/keyrings/panel-pgdg.gpg`), если их добавила панель |
| Redis | | Redis, его расширение PHP и всё, что хранилось в Redis. PHP-FPM перезапускается |
| Memcached | | Memcached, его расширение PHP и всё содержимое кэша. PHP-FPM перезапускается |
| Adminer | Ваши базы данных | Файлы Adminer и его внутренний сайт |
| phpMyAdmin | Ваши базы данных | Файлы phpMyAdmin, его временные файлы, внутренний сайт и настройки |
| Node.js | Другие версии Node.js. Также папка версии по умолчанию, если её выбрал какой-либо сайт-приложение | `node`, `npm` и `npx` в `/usr/local/bin` и выпуск, на который они указывают |
| Приложения Python | Сам `python3`, который нужен системе, и виртуальные окружения в папках старых приложений | Пакеты venv и pip |
| Java (OpenJDK) | | Все установленные версии Java вместе с пакетами, которые были нужны только им |
| ionCube Loader | | Загрузчик во всех версиях PHP и `/usr/local/lib/ioncube`. PHP-FPM перечитывает конфигурацию, а закодированные PHP-файлы перестают работать |
| Docker | Образы, тома и кэш сборки в `/var/lib/docker`, если вы не отметите **Также удалить все образы, тома и кэш сборки (/var/lib/docker)** и не введёте `docker`. При повторной установке Docker находит их | Docker и его плагин Compose |
| Веб-брандмауэр | Журнал брандмауэра | ModSecurity и правила OWASP. Веб-сервер перезапускается |

Удаление данных MariaDB, MySQL, PostgreSQL или Docker нельзя отменить. Убедитесь, что у вас есть резервная копия всего, что ещё нужно.
:::

## Меню показывает, что установлено {#the-menu-shows-what-is-installed}

Левое меню скрывает страницы программ, которые не установлены:

- **Docker** появляется после установки Docker.
- **WordPress** появляется, когда появляется сайт на WordPress.
- На странице **Базы данных** вкладки **PostgreSQL**, **Redis** и **Memcached** появляются после установки соответствующей программы, а **Медленные запросы** — после установки MariaDB или MySQL.

**Сайты**, **Базы данных** и **Программы** видны всегда, потому что на них предлагается установка. Открытая вами страница остаётся видимой.

## Веб-сервер {#web-server}

Панель использует один веб-сервер за раз и настраивает под него каждый сайт:

- Nginx — самый лёгкий. PHP работает в PHP-FPM.
- Apache читает файлы `.htaccess`, которые есть у некоторых PHP-приложений, и расходует немного больше памяти.
- OpenLiteSpeed читает правила перезаписи из файлов `.htaccess` и имеет встроенный LiteSpeed Cache для WordPress. Он устанавливается из собственного репозитория пакетов LiteSpeed.

Вместе с веб-сервером устанавливается версия PHP из вашего дистрибутива с PHP-FPM. Если брандмауэр ufw включён, панель открывает порты 80 и 443, а для OpenLiteSpeed также 443/udp для HTTP/3.

Панель не позволяет установить второй веб-сервер, пока установлен другой, потому что обоим нужны порты 80 и 443.

Чтобы перейти на другой веб-сервер:

1. Сначала удалите все сайты. Создайте их резервные копии, если они понадобятся позже.
2. Нажмите **Удалить** на карточке текущего веб-сервера и для подтверждения введите его название (`nginx`, `apache` или `openlitespeed`).
3. Установите другой веб-сервер.

О настройке сайтов см. [Сайты](./websites).

## Версии PHP {#php-versions}

Можно установить несколько версий PHP рядом и выбрать одну для каждого сайта в **Сайты** → (сайт) → **PHP**.

- Версия, которая входит в ваш дистрибутив, устанавливается из его пакетов. Остальные версии берутся из репозитория Ondřej Surý `packages.sury.org/php` — одинаково на Ubuntu и Debian. Панель спрашивает разрешения, прежде чем добавить этот репозиторий на сервер, и принимает только его ключ подписи с отпечатком `15058500 A0235D97 F5D10063 B188E2B6 95BD4743`.
- Каждая версия устанавливается с расширениями fpm, cli, mysql, curl, gd, mbstring, xml, zip, intl, bcmath и opcache. Начиная с PHP 8.5 OPcache входит в сам PHP, поэтому у 8.5 и более новых версий нет отдельного пакета opcache. Если установлен Redis или Memcached, добавляется и расширение redis или memcached.
- До PHP 8.0 json — отдельный пакет, и он тоже добавляется. PHP 5.6 также получает mcrypt, если он есть в репозитории.
- Панель переключает пул PHP-FPM версии по умолчанию на процессы, запускаемые по требованию (on-demand), поэтому версия, которую не использует ни один сайт, почти не занимает памяти.

Список версий следует за репозиторием PHP. Когда `packages.sury.org/php` уже есть на сервере (он добавляется вместе с первой версией PHP, которой нет в вашем дистрибутиве), страница предлагает версии, которые есть в репозитории для вашей системы, по спискам пакетов apt. Новая версия PHP, например PHP 8.7, появляется сама, как только репозиторий её опубликует и списки пакетов обновятся (каждая установка выполняет `apt-get update`, как и ежедневное задание apt вашей системы). Версия, которой нет в репозитории, не предлагается. Пока репозиторий не добавлен, страница предлагает версии, известные Nefo, — с 7.4 по 8.6. Установленные версии, версия вашего дистрибутива и **Старые версии** показываются всегда.

Нажмите **Управление** у установленной версии, чтобы открыть её **Расширения** и **Настройки**.

### Версии без обновлений безопасности {#end-of-life}

Каждая версия PHP получает обновления безопасности от PHP до определённой даты (см. [php.net/supported-versions.php](https://www.php.net/supported-versions.php)): 8.1 — до 31 декабря 2025 года, 8.2 — до 31 декабря 2026 года, 8.3 — до 31 декабря 2027 года, 8.4 — до 31 декабря 2028 года, 8.5 — до 31 декабря 2029 года и 8.6 — до 31 декабря 2030 года. У 7.4 и 8.0 их уже нет. После этой даты версия из `packages.sury.org` получает значок **Поддержка окончена — обновлений безопасности нет** и строку с датой — на странице **Программы**, в её окне **Управление** и в меню версий PHP у сайтов. Панель сравнивает дату с сегодняшней, поэтому значок появляется сам.

Версия PHP из самого дистрибутива (8.1 на Ubuntu 22.04, 8.3 на 24.04, 8.5 на 26.04, 8.2 на Debian 12, 8.4 на Debian 13) никогда не получает этот значок: команда безопасности дистрибутива выпускает для неё исправления всё время, пока выпуск дистрибутива поддерживается.

По возможности переводите сайты с версии, у которой есть этот значок. Её по-прежнему можно установить без дополнительного подтверждения; подтверждение запрашивают только [старые версии](#older-php-versions).

### Старые версии PHP {#older-php-versions}

PHP 5.6, 7.0, 7.1, 7.2 и 7.3 находятся в разделе **Старые версии**, свёрнутом под остальными версиями. Они нужны для сайтов, перенесённых с другого сервера (cPanel, aaPanel…), которые пока не работают на более новом PHP.

::: danger Поддержка окончена: обновлений безопасности нет
PHP прекратил выпускать обновления безопасности для этих версий много лет назад: для 5.6 — в 2018 году, для 7.3 — в 2021 году (см. [php.net/eol.php](https://www.php.net/eol.php)). Их известные уязвимости никогда не будут исправлены, поэтому сайт на такой версии легче взломать. Используйте их только для того, чтобы старый сайт продолжал работать, пока вы его обновляете, а затем переведите его на поддерживаемую версию. Не используйте их для новых сайтов.
:::

- У каждой из них есть значок **Поддержка окончена — обновлений безопасности нет** — на странице **Программы** и в меню версий PHP у сайтов.
- При установке такой версии панель сначала просит подтвердить этот риск.
- Сначала должна быть установлена поддерживаемая версия (7.4 или новее), а последнюю поддерживаемую версию нельзя удалить, пока установлены старые. Поэтому старая версия никогда не бывает единственным PHP на сервере: для настройки веб-сервера, Adminer, Composer и инструментов панели остаётся поддерживаемая.
- У магазина приложений свои минимальные версии: WordPress нужен PHP 7.4, остальным приложениям — новее. Инструменты WordPress по-прежнему управляют сайтом на WordPress на старой версии, но не обновляют там сам WordPress, потому что текущему WordPress нужен PHP 7.4. Плагины и темы они по-прежнему обновляют; WP-CLI пропускает обновления, которым нужен более новый PHP.
- Пул PHP-FPM сайта и настройки php.ini такие же, как на новых версиях: каждая настройка, которую пишет панель, существует в PHP 5.6.

В `packages.sury.org/php` есть PHP с 5.6 по 7.3 для Ubuntu 22.04, 24.04 и 26.04 и Debian 12 и 13, на amd64 и arm64. Установка также проверяет это через apt и отказывается, указывая причину, если версии в репозитории нет.

### Серверы, на которых использовался PPA ondrej/php {#ondrej-php-ppa}

Ранние версии панели брали дополнительные версии PHP на Ubuntu из `ppa:ondrej/php`. Этот PPA заморожен и больше не получает обновлений: его сопровождающий теперь публикует пакеты для Ubuntu в `packages.sury.org/php` (см. объявление на [launchpad.net/~ondrej/+archive/ubuntu/php](https://launchpad.net/~ondrej/+archive/ubuntu/php)).

Когда панель запускается на сервере Ubuntu, где ещё есть этот PPA, она один раз переводит сервер на новый репозиторий так, как описано в объявлении PPA:

1. Добавляет `packages.sury.org/php` с закреплённым ключом (`/usr/share/keyrings/sury-php.gpg` и `/etc/apt/sources.list.d/sury-php.list`), если источника для него ещё нет.
2. Перемещает файл источника PPA из `/etc/apt/sources.list.d`, а также ключ PPA `/etc/apt/trusted.gpg.d/ondrej-ubuntu-php.gpg`, если он есть, в `apt-backup` в папке данных панели (`/var/lib/nefo/apt-backup`). Этому ключу доверяли для всех репозиториев, и он больше ничему не нужен. Другие PPA, даже того же сопровождающего, не затрагиваются.

Ничего не устанавливается, не удаляется и не откатывается к старой версии, и при запуске панель не выполняет `apt-get update`. Следующее обновление (проверка обновлений панелью, установка или ваш собственный `apt update`) прочитает новый источник, и установленные пакеты PHP будут получать из него следующие обновления. В журнале панели сказано, что она изменила. Если ключ не удаётся скачать, PPA остаётся, и панель пробует снова при следующем запуске. Строка PPA в самом `/etc/apt/sources.list` или в файле, где перечислены и другие репозитории, не редактируется: журнал просит заменить её вручную.

### Расширения {#extensions}

На вкладке **Расширения** перечислены необязательные расширения, для которых есть пакет для этой версии. Нажмите **Установить** или **Удалить**, и PHP-FPM перечитает конфигурацию.

Необязательные расширения: apcu, gmp, igbinary, imagick, imap, ldap, memcached, mongodb, msgpack, pgsql, redis, soap, sqlite3, ssh2, tidy, xdebug, xsl и yaml.

xdebug замедляет все сайты на этой версии PHP. Не оставляйте его установленным на рабочем сервере.
:::

### Настройки php.ini {#php-ini-settings}

Вкладка **Настройки** задаёт значения php.ini для всех сайтов на этой версии PHP. Оставьте поле пустым, чтобы использовать значение PHP по умолчанию, затем нажмите **Сохранить**.

| Настройка | По умолчанию | Допустимые значения |
|---|---|---|
| `date.timezone` | UTC | Название часового пояса, например `Europe/Berlin` |
| `max_input_vars` | 1000 | от 100 до 100000 |
| `max_input_time` | 60 | от -1 до 3600 |
| `default_socket_timeout` | 60 | от 1 до 600 |
| `session.gc_maxlifetime` | 1440 | от 60 до 2592000 |
| `realpath_cache_size` | 4096K | Число, при необходимости с K или M |
| `display_errors` | Off | On или Off |
| `expose_php` | Off | On или Off |
| `allow_url_fopen` | On | On или Off |
| `short_open_tag` | Off | On или Off |
| `opcache.enable` | 1 | 1 или 0 |
| `opcache.memory_consumption` | 128 | от 32 до 2048 |
| `opcache.max_accelerated_files` | 10000 | от 1000 до 1000000 |
| `opcache.validate_timestamps` | 1 | 1 или 0 |
| `opcache.revalidate_freq` | 2 | от 0 до 3600 |

Значения записываются в `/etc/php/<version>/fpm/conf.d/99-panel.ini` и проверяются командой `php-fpm -t`. Если PHP-FPM их не принимает, возвращается прежний файл, и ничего не меняется. Лимиты памяти, размера загрузки и времени задаются для каждого сайта в его настройках.

### ionCube Loader {#ioncube}

Карточка **ionCube Loader** под версиями PHP позволяет выполнять PHP-файлы, закодированные с помощью ionCube Encoder. Он нужен некоторым коммерческим PHP-скриптам, например WHMCS и другим программам для биллинга или лицензирования, и часто — сайтам, перенесённым с cPanel.

1. Сначала установите версии PHP, которые используют ваши сайты.
2. На карточке **ionCube Loader** нажмите **Установить**.

Панель скачивает загрузчики с сайта ionCube (`downloads.ioncube.com`) по HTTPS. Она устанавливает один закреплённый выпуск, 15.5.1, и сверяет скачанный файл с контрольной суммой SHA-256, которая есть у панели, потому что ionCube не публикует ни контрольных сумм, ни подписей. Если файл не совпадает, он отклоняется, и ничего не меняется. Загрузчик работает на серверах amd64 и arm64.

Загрузчики помещаются в `/usr/local/lib/ioncube` вместе с лицензией ionCube (`LICENSE.txt`). Для каждой установленной версии PHP, которую поддерживает загрузчик, панель записывает `00-ioncube.ini` в `/etc/php/<version>/fpm/conf.d` и `/etc/php/<version>/cli/conf.d`, чтобы загрузчик загружался раньше OPcache, как требует ionCube. Панель проверяет, что `php<version> -v` запускается с загрузчиком, и затем PHP-FPM перечитывает конфигурацию. Если PHP с ним не запускается, панель снова убирает файл, так что эта версия продолжает работать без загрузчика, а задача сообщает, какая версия не прошла проверку.

Карточка перечисляет все установленные версии PHP и показывает, что делает для каждой загрузчик:

| Состояние | Значение |
|---|---|
| **загружен** | Загрузчик загружается для PHP-FPM и командной строки |
| **не загружен** | Загрузчик для этой версии есть, но не загружается. Нажмите **Загрузить во все версии** на карточке |
| **ionCube не выпускает загрузчик для этой версии** | PHP 8.0: ionCube так и не выпустил для неё загрузчик |
| «пока недоступен для PHP 8.6» | Версия PHP новее, чем загрузчики, которые устанавливает панель (15.5.1 поддерживает версии до PHP 8.5) |

В закреплённом выпуске есть загрузчики для PHP 5.6, с 7.0 по 7.4 и с 8.1 по 8.5. Версия PHP, которую вы установите позже, тоже получит загрузчик, если он для неё существует. При удалении версии PHP удаляется и её `00-ioncube.ini`.

Кнопка **Удалить** убирает загрузчик из всех версий PHP, PHP-FPM перечитывает конфигурацию, а `/usr/local/lib/ioncube` удаляется. После этого закодированные PHP-файлы перестают работать.

Чтобы проверить сайт, положите в его папку файл такого вида и откройте его, а потом удалите файл:

```php
<?php var_dump(extension_loaded('ionCube Loader'));
```

::: tip
ionCube Loader можно использовать бесплатно, но это не программа с открытым исходным кодом. Лицензия ionCube ([ioncube.com/legal/loaders/eula](https://www.ioncube.com/legal/loaders/eula)) разрешает бесплатное использование. Панель скачивает его с сайта ionCube при установке и не распространяет его сама.
:::

## Node.js {#node-js}

Карточка **Node.js** устанавливает новейший LTS-выпуск с nodejs.org, проверенный по опубликованной контрольной сумме SHA-256. Он устанавливается в `/opt/node-v<version>-linux-<arch>`, а `node`, `npm` и `npx` ссылками добавляются в `/usr/local/bin`. Это Node.js сервера по умолчанию; его используют сайты-приложения, в которых версия не выбрана.

### Несколько версий Node.js {#several-node-js-versions}

После установки Node.js карточка **Версии Node.js** показывает три новейшие LTS-ветки и все установленные ветки. Нажмите **Установить**, чтобы добавить ветку рядом с остальными. Версию по умолчанию это не меняет.

Ветку для сайта-приложения выбирают в **Сайты** → (сайт) → **Среда выполнения**. Ветку, которую используют сайты-приложения, и версию по умолчанию нельзя удалить с этой карточки. Версию по умолчанию удаляют на карточке **Node.js**.

Список берётся с nodejs.org, поэтому, чтобы его показать, серверу нужен доступ в интернет.

::: warning
Удаление Node.js по умолчанию ломает также задания cron и фоновые программы, которые вызывают `node`.
:::

## Python {#python}

Карточка **Приложения Python** устанавливает `python3-venv` и `python3-pip`, чтобы сайты-приложения могли работать на Python (Django, Flask, FastAPI…). Каждый сайт-приложение на Python получает собственное виртуальное окружение в `app/.venv`. Инструменты сборки, такие как `build-essential` и `python3-dev`, не устанавливаются, поэтому пакет, у которого нет готового wheel и который нужно компилировать, не установится, пока вы не добавите их через `apt`.

При удалении удаляются venv и pip. Сам `python3` остаётся, потому что он нужен системе.

## Java {#java}

Карточка **Java (OpenJDK)** устанавливает OpenJDK из вашего дистрибутива для сайтов-приложений на Java, например приложения Spring Boot, которое запускается командой `java -jar`. Это JDK без графических компонентов (`openjdk-<version>-jdk-headless`): `java`, а также `javac`, `jar` и другие инструменты, которые нужны сборке в скрипте [развёртывания из Git](./git-deploy), без частей для рабочего стола. Он устанавливается в `/usr/lib/jvm/java-<version>-openjdk-<arch>` и получает обновления безопасности вместе с остальной системой.

Кнопка **Установить** на карточке устанавливает новейшую версию с долгосрочной поддержкой (LTS), которая есть в вашем дистрибутиве. Набор версий зависит от системы:

| Система | Версии Java |
|---|---|
| Ubuntu 22.04 | 17, 21, 25 |
| Ubuntu 24.04 | 17, 21, 25 |
| Ubuntu 26.04 | 17, 21, 25 |
| Debian 12 | 17 |
| Debian 13 | 21, 25 |

### Несколько версий Java {#several-java-versions}

После установки Java карточка **Версии Java** показывает LTS-версии, которые предлагает ваш дистрибутив, и все установленные версии. Нажмите **Установить**, чтобы добавить версию рядом с остальными. Более новая LTS-версия появляется сама, когда она появится в дистрибутиве.

Версию для сайта-приложения выбирают в **Сайты** → (сайт) → **Среда выполнения** (см. [Сайты-приложения на Java](./websites#java-app-websites)). Версию, которую используют сайты-приложения, удалить нельзя, и карточка показывает, что её используют приложения. Кнопка **Удалить** на карточке **Java (OpenJDK)** удаляет все установленные версии; это запрещено, пока хотя бы один сайт-приложение работает на Java.

Каждая версия вместе со скачанными пакетами занимает примерно от 390 до 480 MB на диске. Пока её не использует ни один сайт, ничего не работает.

## Redis {#redis}

Redis — это кэш в памяти. WordPress может использовать его через плагин объектного кэша Redis.

При установке Redis панель:

- устанавливает `redis-server` и расширение redis для каждой установленной версии PHP;
- ограничивает память Redis под сервер: 64 MB при оперативной памяти меньше 1,5 GB, 128 MB от 1,5 GB, 256 MB от 3 GB;
- задаёт политику `allkeys-lru`, чтобы при заполнении Redis удалял ключи, которые дольше всего не использовались, как обычный кэш;
- оставляет Redis слушать `127.0.0.1:6379`, так что он доступен только с этого сервера.

Чтобы заглянуть в Redis, откройте **Базы данных** → **Redis**. См. [Базы данных](./databases#redis-key-browser).

Прежде чем удалять Redis, выключите плагин кэша на своих сайтах. Без кэша они продолжат работать, только немного медленнее.

## PostgreSQL {#postgresql}

Карточка **PostgreSQL** устанавливает версию из вашего дистрибутива или другую основную версию из репозитория проекта PostgreSQL (apt.postgresql.org) — что вы выберете в диалоге установки. Панель настраивает его под память сервера в дополнительном файле `conf.d`, разрешает ему слушать только localhost и пишет `pg_hba.conf`, который требует пароль от всех, кроме системного пользователя `postgres` на локальном сокете. Его базы данных находятся в **Базы данных** → **PostgreSQL**. О версиях, обновлении, удалённом доступе, правилах импорта и резервных копиях см. [PostgreSQL](./postgresql).

Если он установлен из apt.postgresql.org, на карточке написано **Из apt.postgresql.org**, иначе — **Из дистрибутива**. При удалении удаляется и этот репозиторий, если его добавила панель.

Если установлен Adminer, панель добавляет расширение PHP `pgsql` для версии PHP, на которой работает Adminer, чтобы Adminer открывал и базы данных PostgreSQL. Это расширение добавляется только вместе с PostgreSQL.

## Memcached {#memcached}

Memcached — это небольшой кэш в памяти для сессий PHP и кэшей приложений (например, драйвера кэша `memcached` в Laravel).

При установке Memcached панель:

- устанавливает `memcached` и расширение memcached для каждой установленной версии PHP и добавляет это расширение в версии PHP, которые вы установите позже;
- пишет `/etc/memcached.conf`: Memcached слушает только `127.0.0.1:11211` по TCP, UDP выключен (`-U 0`), поэтому его нельзя использовать для усиления атак;
- ограничивает его память под сервер: 64 MB при оперативной памяти меньше 1,5 GB, 128 MB от 1,5 GB, 256 MB от 3 GB, и разрешает 512 подключений при памяти меньше 1,5 GB и 1024 начиная с этого объёма.

Когда память заполнена, Memcached удаляет элементы, которые дольше всего не использовались. Чтобы увидеть его показатели, откройте **Базы данных** → **Memcached**.

Прежде чем удалять Memcached, перенесите сессии и кэш своих сайтов в другое место: приложение, у которого драйвер кэша — Memcached, без него перестанет работать.

## Сервер баз данных, Adminer и phpMyAdmin {#mariadb-and-adminer}

Карточка **Сервер баз данных** устанавливает MariaDB или MySQL 8.4 LTS, настроенные под память сервера и доступные только с этого сервера. На сервере может быть только один из них.

Пока ни один не установлен, карточка предлагает выбор, где отмечен **MariaDB**: он легче, и на нём работают WordPress и большинство PHP-приложений.

- В разделе **MariaDB** можно выбрать версию, если в собственном репозитории MariaDB есть более новая LTS-серия, чем в вашем дистрибутиве: версию дистрибутива (по умолчанию, например «10.11, версия дистрибутива») или **11.4 LTS от MariaDB**, **11.8 LTS от MariaDB** или **12.3 LTS от MariaDB** (на Ubuntu 26.04 и Debian 13 — только 12.3). У каждой указано, до какого срока MariaDB её поддерживает. См. [Версии MariaDB](./databases#mariadb-versions).
- **MySQL 8.4 LTS** устанавливается из репозитория Oracle и предлагается на Ubuntu 22.04, 24.04 и 26.04 и Debian 12 и 13, только на серверах amd64. В остальных случаях карточка объясняет, почему он не предлагается.

Когда один из них установлен, карточка показывает, какой именно, его версию и откуда он установлен (**из пакетов дистрибутива**, **из репозитория MariaDB** или **из репозитория Oracle**), оценку памяти, число баз данных, **Открыть базы данных** и **Удалить**. Кроме того, на ней есть:

- **Обновить версию** — для MariaDB, когда предлагается более новая LTS-серия: см. [Обновление MariaDB](./databases#upgrade-mariadb).
- Другой сервер как альтернатива — **Вместо этого: MySQL 8.4 LTS** или **Вместо этого: MariaDB** — с кнопкой для перехода: панель переносит базы данных, их пользователей и пароли, а если что-то не удаётся, возвращает всё как было. См. [Переход между MariaDB и MySQL](./databases#switch-between-mariadb-and-mysql).
- **Сохранённые дампы**: экспорты, сделанные при обновлении или переходе, с их папкой, размером и кнопкой удаления. См. [Дампы при обновлениях и переходах](./databases#dumps-from-upgrades-and-switches).

Adminer и phpMyAdmin показывают ваши базы данных в браузере и доступны только через вход в панель. Обоим нужны веб-сервер и PHP, и оба работают с MariaDB и MySQL. См. [Базы данных](./databases#phpmyadmin).

## Docker {#docker}

Карточка **Docker** устанавливает `docker.io` из вашего дистрибутива вместе с плагином Compose, если он доступен. После этого появляется пункт меню **Docker**.

Порты, которые публикуют контейнеры Docker, обходят брандмауэр ufw. Поэтому панель публикует порты контейнеров только на 127.0.0.1, а доступ к ним идёт через сайт. См. [Docker](./docker).

## Веб-брандмауэр и ClamAV {#web-firewall-and-clamav}

- **Веб-брандмауэр (ModSecurity)** устанавливает ModSecurity с OWASP Core Rule Set. Ему нужен веб-сервер. После установки включите его для каждого сайта в **Сайты** → (сайт) → **Веб-брандмауэр (WAF)**. Если в дистрибутиве нет модуля ModSecurity для вашего веб-сервера, карточка объясняет причину и не предлагает установку: в Ubuntu 22.04 его нет для Nginx. Apache и OpenLiteSpeed там работают, а Nginx — начиная с Ubuntu 24.04.
- **Антивирус ClamAV** — необязательный дополнительный движок для проверок на вредоносные программы. Его антивирусные базы скачиваются сразу после установки, поэтому проверки смогут использовать его через несколько минут. Он подходит для серверов с 2 GB оперативной памяти и больше.

Об обоих см. [Безопасность](./security).

## Инструменты: Composer и WP-CLI {#tools}

В группе **Инструменты** показаны два инструмента командной строки, которые панель устанавливает, когда они чему-то нужны. На каждой карточке видно, установлен ли инструмент, его версия, откуда он взят и что его использует. Кнопка **Обновить** устанавливает последний официальный выпуск инструмента. Панель скачивает его по HTTPS вместе с контрольной суммой, которую проект публикует рядом с ним, и отклоняет загрузку, которая не совпадает: тогда установленный инструмент остаётся прежним. Новый файл заменяет старый за один шаг.

### Composer {#composer}

Composer — менеджер пакетов PHP. Он устанавливается при установке Laravel или Drupal из магазина приложений, и его могут запускать также скрипты развёртывания из Git и терминал.

- **Установить** устанавливает пакет `composer` из вашего дистрибутива, который получает обновления безопасности вместе с остальной системой.
- **Обновить** устанавливает последний стабильный выпуск с getcomposer.org в `/usr/local/bin/composer`, проверенный по опубликованной контрольной сумме SHA-256. Он стоит первым в `PATH`, поэтому его используют `composer` в терминале, скрипты развёртывания из Git и собственные установки Laravel и Drupal панелью. Пакет из дистрибутива остаётся установленным.
- **Удалить** удаляет оба. Удаление запрещено, пока скрипт развёртывания из Git запускает `composer`. Сайты на Laravel и Drupal ему не мешают: Composer нужен им только для установки, и без него они продолжают работать. Повторная установка одного из них возвращает Composer.

### WP-CLI {#wp-cli}

WP-CLI управляет WordPress из командной строки. [Инструменты WordPress](./wordpress) используют его для обновлений, режима обслуживания, паролей и тестовых копий и устанавливают его, когда он впервые понадобится.

- **Установить** и **Обновить** скачивают последний выпуск с GitHub в `/usr/local/lib/panel/wp-cli.phar`, проверенный по контрольной сумме SHA-512, которую публикует выпуск.
- **Удалить** запрещено, пока есть сайты на WordPress.
