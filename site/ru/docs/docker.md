# Docker

Nefo устанавливает Docker из вашего дистрибутива и управляет контейнерами, проектами Compose и образами на странице **Docker**, с терминалом в каждом контейнере. Порты контейнеров панель публикует только на 127.0.0.1, так что доступ к ним идёт через сайт, и не принимает проекты Compose, которые ослабили бы защиту сервера, например привилегированные контейнеры или порты, открытые в интернет.

На этой странице описана каждая вкладка, проверки безопасности, которые панель выполняет для проектов Compose, место Docker-приложений из магазина приложений и то, как сделать контейнер доступным снаружи через сайт.

## Установка Docker {#install-docker}

Откройте **Программы** → **Docker** и нажмите **Установить**. Панель установит `docker.io` из вашего дистрибутива вместе с плагином Compose, если он доступен. Пункт меню **Docker** появляется после установки Docker.

Если плагина Compose позже не окажется, панель установит его при первом запуске проекта Compose.

Об удалении Docker см. [Программное обеспечение](./software#when-an-uninstall-is-refused). Удаление не выполняется, пока существуют контейнеры, проекты Compose или Docker-приложения.

## Почему порты остаются на 127.0.0.1 {#why-ports-stay-on-127-0-0-1}

Порты, которые публикует Docker, обходят брандмауэр ufw: контейнер, опубликованный на всех адресах, доступен из интернета, что бы ни говорили правила ufw. Поэтому панель:

- публикует запускаемые ею контейнеры только на `127.0.0.1`;
- не принимает проекты Compose, которые публикуют порт на любом другом адресе.

Чтобы сделать контейнер доступным снаружи, поставьте перед ним сайт. См. [Публикация контейнера на сайте](#put-a-container-on-a-website).

## Контейнеры {#containers}

На вкладке **Контейнеры** перечислены все контейнеры сервера, работающие и остановленные, с образом, состоянием и портами. Здесь же видны контейнеры проектов Compose и приложений из магазина приложений.

В строке каждого контейнера есть кнопка **Запустить** или **Остановить**, остальные действия находятся в его меню:

| Действие | Что делает |
|---|---|
| **Запустить** / **Остановить** | Запускает или останавливает контейнер |
| **Терминал** | Открывает оболочку внутри контейнера. Только для работающих контейнеров |
| **Перезапустить** | Перезапускает контейнер |
| **Журналы** | Показывает последние 200 строк его вывода с отметками времени |
| **Удалить** | Удаляет контейнер, даже если он работает |

::: warning
**Удалить** уничтожает данные контейнера, если они не хранятся в томе.
:::

### Запуск контейнера {#run-a-container}

1. На вкладке **Контейнеры** нажмите **Запустить контейнер**.
2. Заполните поля:
   - **Образ**, например `nginx:alpine`;
   - **Имя контейнера**, например `my-app`;
   - **Порт на этом сервере** (от 1024 до 65535) и **Порт в контейнере**, если контейнер что-то обслуживает;
   - **Переменные окружения (по одной NAME=value в строке)**, например `TZ=UTC`.
3. Нажмите **Запустить**.

Панель при необходимости скачивает образ и запускает контейнер с политикой перезапуска `unless-stopped`, поэтому он снова запускается после перезагрузки. Порт публикуется только на `127.0.0.1`.

### Терминал в контейнере {#terminal-in-a-container}

Нажмите **Терминал**, чтобы открыть оболочку внутри работающего контейнера. Панель использует `bash`, если он есть в образе, иначе `sh`. Сеанс завершается, когда вы закрываете окно или после 30 минут без ввода.

## Проекты Compose {#compose-projects}

Проект Compose — это файл `compose.yaml`, который запускает несколько контейнеров вместе. Панель хранит каждый проект в `/var/lib/panel-compose/<name>/compose.yaml`, доступном для чтения только root, и запускает его как проект Compose `panel-<name>`.

### Создание проекта {#create-a-project}

1. Откройте **Docker** → **Compose** и нажмите **Новый проект**.
2. Введите **Имя проекта**: строчные латинские буквы, цифры и дефисы, не больше 40 символов. Контейнеры получают имена `panel-<name>-<service>-1`.
3. Напишите файл в поле `compose.yaml`. **Вставить пример** подставляет небольшой рабочий пример.
4. Нажмите **Создать и запустить**.

Панель проверяет файл, сохраняет его и запускает контейнеры, скачивая нужные образы. Относительные пути в файле, например `./data:/data`, отсчитываются от папки проекта.

Минимальный проект:

```yaml
services:
  web:
    image: traefik/whoami
    restart: unless-stopped
    ports:
      - "127.0.0.1:8081:80"
```

Размер `compose.yaml` — до 64 KB.

### Изменение проекта {#edit-a-project}

Откройте меню проекта и выберите **Изменить**. Измените файл и нажмите **Сохранить и применить**. Панель проверяет новый файл, сохраняет его и пересоздаёт контейнеры, конфигурация которых изменилась. Контейнеры сервисов, которые вы убрали из файла, тоже удаляются.

### Действия с проектом {#project-actions}

| Действие | Что делает |
|---|---|
| **Запустить** | Проверяет файл и запускает контейнеры |
| **Остановить** | Останавливает контейнеры |
| **Перезапустить** | Перезапускает контейнеры |
| **Обновить образы** | Проверяет файл, скачивает более новые образы и пересоздаёт контейнеры |
| **Удалить контейнеры** | Останавливает и удаляет контейнеры. Тома и `compose.yaml` сохраняются |
| **Журналы** | Последние 200 строк каждого контейнера |
| **Удалить** | Удаляет контейнеры, сети и папку проекта вместе с `compose.yaml`. Чтобы удалить и тома, отметьте **Также удалить его тома (данные в них будут потеряны)**. Образы сохраняются |

### Проверки безопасности {#safety-checks}

Перед сохранением проекта, а также перед каждым запуском и обновлением панель запрашивает у Compose итоговую конфигурацию, в которой уже раскрыты include, extends и переменные. Она не принимает проект, который ослабил бы защиту сервера:

| Не допускается | Почему |
|---|---|
| `privileged: true` | Привилегированный контейнер полностью управляет сервером |
| `network_mode`, `pid`, `ipc`, `userns_mode` или `cgroup` со значением `host` | Контейнер разделял бы собственное пространство имён сервера |
| Любой `cap_add` | Дополнительные привилегии контейнера |
| Любые `devices` или `device_cgroup_rules` | Контейнеру передаются устройства сервера |
| `security_opt`, отличный от `no-new-privileges` | Параметры вроде `seccomp=unconfined` или `apparmor=unconfined` ослабляют изоляцию контейнера |
| Любые `sysctls` | Параметры ядра |
| Порт, у которого адрес на сервере не `127.0.0.1` и не `::1`, например `"8080:80"`, или порт без опубликованного номера | Docker слушал бы на всех адресах в обход брандмауэра |
| bind-монтирование `/etc`, `/root`, `/boot`, `/proc`, `/sys`, `/dev` или чего-либо внутри них | Системные папки дают контейнеру управление сервером |
| bind-монтирование сокета Docker, `/var/run/docker.sock` или `/run/docker.sock`, или папки, которая его содержит, например `/`, `/var`, `/var/run` или `/run` | Сокет даёт контейнеру управление Docker, а значит, и сервером |
| Именованный том, у которого параметр `device` — такой путь, а также secrets или configs, читаемые из такого пути | Те же папки, смонтированные другим способом |

Пути проверяются как в записанном виде, так и после раскрытия символических ссылок. `/etc/localtime` и `/etc/timezone` можно монтировать только для чтения (`:ro`), чтобы контейнер использовал часовой пояс сервера.

Если проверка не пройдена, редактор показывает, какой сервис и какой параметр отклонены. Ничего не сохраняется и не запускается.

## Образы {#images}

На вкладке **Образы** перечислены локальные образы с размером, датой создания и контейнерами, которые их используют (**Используется**).

- **Удалить** удаляет образ. Если его используют контейнеры, панель называет их и переспрашивает, прежде чем всё равно удалить образ.
- **Удалить неиспользуемые** удаляет все образы, которые не использует ни один контейнер. При необходимости они будут скачаны заново.

Отдельной кнопки для скачивания образа нет. Образы скачиваются, когда вы запускаете контейнер, запускаете проект Compose или нажимаете **Обновить образы**.

## Docker-приложения из магазина приложений {#docker-apps-from-the-app-store}

[Магазин приложений](./apps) устанавливает Docker-приложения, например Ghost, Uptime Kuma, n8n и Gitea. Они работают как проекты Compose, которые панель составляет по рецепту каждого приложения:

- Их файлы и данные находятся в `/var/lib/panel-apps/<name>`, а проект Compose называется `panelapp-<name>`. На вкладке **Compose** их нет, но их контейнеры видны на вкладке **Контейнеры**.
- Они проходят те же проверки безопасности, что и ваши собственные проекты.
- Каждое Docker-приложение получает свой сайт. У приложений-сервисов, таких как PostgreSQL, MongoDB и Ollama, сайта нет, и они слушают только на `127.0.0.1`.

Управляйте этими приложениями в разделе **Магазин приложений** → **Установленные**: там их запускают, останавливают, обновляют и создают их резервные копии. Об их удалении см. [Магазин приложений](./apps), о резервных копиях — [Резервные копии](./backups#app-backups).

## Публикация контейнера на сайте {#put-a-container-on-a-website}

Сайт может передавать своих посетителей на порт контейнера на `127.0.0.1`. Тогда веб-сервер работает как обратный прокси, а сайту можно выдать SSL-сертификат.

1. Опубликуйте порт контейнера на `127.0.0.1`, например `127.0.0.1:8081:80` в `compose.yaml` или **Порт на этом сервере** `8081` в форме **Запустить контейнер**.
2. Откройте **Сайты** и нажмите **Добавить сайт**.
3. Введите **Домен**, например `app.example.com`.
4. В поле **Тип** выберите **Приложение (Node.js, Python, Java…) за прокси**.
5. В поле **Порт, который слушает приложение (127.0.0.1)** введите тот же порт, `8081`.
6. Оставьте **Команда запуска (необязательно)** пустым: приложение запускает Docker.
7. Нажмите **Создать сайт**.

Порт должен быть от 1024 до 65535 и не совпадать с портом панели, 3306 (MariaDB), 6379 (Redis) или 7809 (приёмник вебхуков Git). Два сайта-приложения не могут использовать один порт.

Затем получите сертификат для сайта, см. [SSL-сертификаты](./ssl). Остальные настройки сайта описаны на странице [Сайты](./websites).

Для контейнера подходит и тип **Обратный прокси на другой адрес**: он передаёт запросы на любой адрес, например `http://127.0.0.1:8081`, с параметрами для заголовка Host, WebSocket и времени ожидания. См. [Сайты с обратным прокси](./websites#reverse-proxy-websites).
