# Проверка безопасности

Проверка безопасности появилась в v0.24.0. Она выполняет 22 быстрые проверки сервера: SSH, который принимает пароли; выключенный брандмауэр; ожидающие обновления безопасности; база данных или Redis, доступные из интернета; порты Docker в обход ufw; файлы сайтов, которые может скачать кто угодно; сертификаты, срок которых истекает; настройки PHP. У каждой находки есть серьёзность и кнопка, которая ведёт на страницу, где проблему исправляют.

Проверка выполняется, когда вы её запускаете, и по умолчанию раз в день. Она ничего не отправляет за пределы вашего сервера. Откройте **Проверка безопасности** в группе **Безопасность** левого меню.

## Запуск проверки {#run-the-check}

1. Нажмите **Запустить проверку**. Это занимает несколько секунд.
2. Прочитайте находки на вкладке **К исправлению**. У каждой есть серьёзность:
   - **Критично**: исправьте сейчас. Например, root может войти по SSH с паролем или сайт отдаёт дамп базы данных.
   - **Предупреждение**: исправьте в ближайшее время. Например, брандмауэр выключен или ожидают установки обновления безопасности.
   - **Примечание**: полезно знать, часто всё и так в порядке. Например, SSH слушает порт 22.
3. Нажмите кнопку находки, например **Перейти: Брандмауэр и SSH**, чтобы открыть место, где это исправляется. Затем запустите проверку снова.

Счётчики вверху показывают, сколько находок ещё открыто в категориях **Критично**, **Предупреждения** и **Примечания**, и сколько проверок **Пройдено**. Нажмите **Пройдено** внизу страницы, чтобы увидеть все проверки, которые не нашли ничего, что нужно исправить. Проверки, которые к серверу не относятся (нет Redis, нет сайтов, нет Docker…), перечислены в строке «Неприменимо к этому серверу».

## Что входит в проверку безопасности? {#what-is-checked}

| Проверка | Серьёзность | Где исправить |
|---|---|---|
| root может войти по SSH с паролем | Критично | **Брандмауэр и SSH** → SSH |
| SSH принимает пароли для других учётных записей | Предупреждение | **Брандмауэр и SSH** → SSH |
| SSH слушает порт 22 | Примечание | **Брандмауэр и SSH** → SSH |
| Брандмауэр (ufw) не установлен или выключен | Предупреждение | **Брандмауэр и SSH** |
| fail2ban не установлен, не работает или не следит за SSH (нет jail `sshd`) | Предупреждение | **Брандмауэр и SSH** → fail2ban или **Службы** |
| К панели обращаются без HTTPS | Критично | `/etc/nefo/config.json` (см. ниже) |
| Панель использует свой самоподписанный сертификат | Примечание | **Настройки** |
| У учётной записи панели нет двухфакторного входа | Критично | **Учётная запись** |
| Ожидают установки обновления безопасности | Предупреждение | **Система** |
| Проверка обновлений выполнялась больше недели назад или ни разу | Примечание | **Система** |
| Автоматические обновления безопасности выключены | Предупреждение | **Система** |
| Для завершения обновлений нужна перезагрузка | Примечание | **Настройки** |
| У учётной записи, кроме root, идентификатор пользователя 0 | Критично | **Терминал** |
| У учётной записи пустой пароль | Критично | **Терминал** (`passwd -l <account>`) |
| MariaDB, MySQL, PostgreSQL, Redis, Valkey, Memcached или MongoDB слушает адрес, отличный от 127.0.0.1 | Критично, если брандмауэр пропускает к порту всех, иначе Примечание | **Базы данных** |
| У Redis нет пароля | Критично на публичном адресе, который пропускает брандмауэр; Предупреждение на другом публичном адресе; Примечание, если Redis слушает только на этом сервере | **Базы данных** → Redis |
| Контейнер Docker публикует порты на всех адресах | Предупреждение | **Docker** |
| У сайта нет HTTPS | Предупреждение | **Сайты** → (сайт) → **SSL / HTTPS** |
| У сайта есть сертификат, но нет перенаправления на HTTPS | Примечание | **Сайты** → (сайт) → **SSL / HTTPS** |
| Срок действия сертификата истёк | Критично | **Сайты** → (сайт) → **SSL / HTTPS** |
| Сертификат истекает через 14 дней или раньше | Предупреждение | **Сайты** → (сайт) → **SSL / HTTPS** |
| Сайт отдаёт файлы, которые должны быть закрыты | Критично для секретов, Предупреждение для копий и архивов | **Файлы** |
| У сайта есть файлы или папки, доступные на запись всем | Предупреждение | **Файлы** |
| PHP показывает ошибки посетителям (`display_errors`) | Предупреждение | **Программы** → PHP → **Управление** |
| PHP сообщает свою версию (`expose_php`) | Примечание | **Программы** → PHP → **Управление** |
| Ожидают установки обновления ядра, плагинов или тем WordPress | Предупреждение | **Сайты** → (сайт) → **WordPress** |
| Включён режим отладки WordPress (`WP_DEBUG`) | Предупреждение | **Сайты** → (сайт) → **WordPress** |

Подробнее:

- **Базы данных в сети**: проверка смотрит, какие адреса слушает каждая программа. Для публичного адреса она смотрит на брандмауэр: если брандмауэра нет или правило пропускает к порту всех, это критично. Порт, который брандмауэр открывает только для некоторых адресов (например, через **Удалённый доступ** базы данных) или не открывает вовсе, — это примечание. Адрес частной сети (10.x, 172.16–31.x, 192.168.x) — тоже примечание.
- **Docker** записывает свои правила брандмауэра раньше правил ufw, поэтому ufw не блокирует порт, который публикует контейнер. Публикуйте порт на `127.0.0.1` (например, `127.0.0.1:8080:80`), если его использует только сайт на этом сервере.
- **Файлы, которые отдаёт сайт**: проверка просматривает верхний уровень папки `public` каждого сайта и запрашивает у веб-сервера файлы, которые никогда не должны быть публичными: файлы `.env`, папки `.git`, `.svn` и `.hg`, `.htpasswd`, дампы баз данных (`.sql`, `.sql.gz`, `.dump`, `.sqlite`…), копии `wp-config.php`, резервные копии файлов (`.bak`, `.old`, `.orig`, `.save`, `.swp`, имена, оканчивающиеся на `~`), `phpinfo.php` и `info.php`, а также архивы, имя которых похоже на копию сайта (со словами «backup», «www», «site», «wordpress» или именем домена). Находка означает, что веб-сервер отдал файл. Конфигурация Nginx от Nefo скрывает файлы с точкой в начале имени, поэтому на Nginx файл `.env` обнаруживается, но в отчёт не попадает. Сайты, которые приостановлены, перенаправляют в другое место, требуют пароль или являются приложениями за прокси, не опрашиваются.
- **Файлы, доступные на запись всем**: проверка обходит папку сайта (`/var/www/<domain>`), не переходя по символическим ссылкам. Папка со sticky-битом, например общая `tmp`, — это нормально. Используйте права 644 для файлов и 755 для папок.
- **PHP**: проверка читает файлы `php.ini` и `conf.d` каждой версии PHP, а также пулы PHP-FPM, где `display_errors` может быть включён для отдельного сайта.
- **WordPress**: сведения об обновлениях берутся из последней проверки на странице **WordPress** (или на вкладке **WordPress** сайта). Сама проверка безопасности никогда не запускает wp-cli. После того как вы обновите сайт, следующая проверка на нём покажет, что осталось.
- **Панель без HTTPS**: Nefo включает HTTPS при установке. Если HTTPS выключен, задайте `"enabled": true` в разделе `"tls"` файла `/etc/nefo/config.json` и выполните `systemctl restart nefo`. Панель, которая слушает только 127.0.0.1, в отчёт не попадает.

## Сколько времени занимает проверка? {#limits}

Проверка читает собственные данные панели и несколько файлов, а файлы, которые есть в папке сайта, запрашивает только у веб-сервера этого же сервера (127.0.0.1). У каждой проверки есть ограничение, поэтому даже на сервере с множеством сайтов запуск остаётся коротким:

| Ограничение | Значение |
|---|---|
| Запуск, который вы начали сами | Не более 25 секунд. Проверки, не завершённые к этому времени, отмечаются как остановленные по ограничению, а результат помечается как неполный |
| Каждая программа, которую опрашивает проверка (fail2ban, Docker, apt…) | Не более 5 секунд; программа, которая не ответила вовремя, пропускается |
| Файлы и папки, которые обходятся в папке одного сайта | 20 000 (100 000 для всех сайтов вместе) |
| Записи, которые читаются в папке `public` одного сайта | 5000 |
| Запросы к веб-серверу этого сервера | 200 всего, по 4 одновременно, не более 3 секунд каждый |

## Принятие находки {#accept-a-finding}

Некоторые находки на вашем сервере допустимы: SSH на порту 22 под защитой fail2ban или порт базы данных, который вы намеренно открыли для одного адреса. Нажмите **Принять** у такой находки. Она перейдёт на вкладку **Принятые** и больше не учитывается.

Принятая находка возвращается, когда меняются её обстоятельства: например, ещё одна учётная запись получает идентификатор пользователя 0 или база данных начинает слушать другой адрес. Она возвращается и тогда, когда её исправили, а потом она появилась снова. Чтобы вернуть её самостоятельно, откройте вкладку **Принятые** и нажмите **Показать снова**. Принятие и возврат находок записываются в журнал действий.

## Ежедневная проверка и оповещения {#daily-check-and-alerts}

Если включено **Запускать каждый день** (по умолчанию), панель раз в день выполняет проверку в фоне во время своего ежечасного обслуживания, но никогда — в первые 10 минут после запуска панели. Так на панели мониторинга всегда виден свежий результат.

Включите **Оповещать, когда ежедневная проверка находит новую проблему** (по умолчанию выключено), чтобы получать сообщение в каналы оповещений (**Настройки** → **Оповещения**), когда ежедневная проверка находит критичную проблему или предупреждение, которых не было при предыдущей проверке. Примечания и принятые находки никогда не отправляются. См. [Оповещения](./mail-alerts#alerts).

## На панели мониторинга {#on-the-dashboard}

Если последняя проверка нашла критичные проблемы или предупреждения, блок **Требует внимания** на панели мониторинга и колокольчик уведомлений показывают «Проверка безопасности: нужно исправить 3 проблемы» с кнопкой **Посмотреть**. Если серьёзных открытых проблем нет, плитка **Риски безопасности** показывает, когда проверка выполнялась в последний раз, а нажатие на неё открывает проверку безопасности.

О том, как получать оповещения о входах по SSH и в панель, см. [Оповещения о входах](./mail-alerts#sign-in-alerts).
