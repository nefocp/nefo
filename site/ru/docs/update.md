# Обновление

Чтобы обновить Nefo, нажмите **Проверить обновления** в разделе **Настройки** → **Панель** или выполните `nefo update` от имени root. Панель скачивает последний выпуск, проверяет его подпись Ed25519 и контрольную сумму SHA-256, заменяет `/usr/local/bin/nefo` за один шаг и перезапускается. Сайты продолжают работать. Сама по себе Nefo никогда не обновляется.

На этой странице показано, как обновлять Nefo, как каждый выпуск проверяется перед установкой и что делать, если обновление не удалось. До версии 1.0 исправления безопасности получает только последний выпуск, поэтому своевременно обновляйте Nefo.

## Обновление из панели {#update-from-the-panel}

1. Откройте **Настройки** → **Панель**. Текущая версия показана рядом с названием Nefo.
2. Нажмите **Проверить обновления**. Если у вас уже последний выпуск, панель сообщает «Это последняя версия.»
3. Если есть более новый выпуск, панель сообщает «Доступна версия v0.2.0.» Нажмите **Установить обновление** и подтвердите.

Ход обновления виден на странице. Когда новая версия установлена, панель перезапускается, а страница сама перезагружается примерно через 20 секунд. Во время перезапуска ваши сайты продолжают работать.

Обновиться можно и с панели мониторинга: нажмите **Проверить обновления**, затем **Обновить до v0.2.0**.

## Обновление из командной строки {#update-from-the-command-line}

```sh
nefo update
```

```
Installed: v0.1.0
Latest:    v0.2.0
Release signature verified
Downloading nefo-linux-amd64 v0.2.0
Checked: Nefo v0.2.0 (commit 5e6f7a8)
Installed. The panel restarts now; reload the page in a few seconds.
```

Если у вас уже последний выпуск, команда выводит обе версии и ничего не меняет. Чтобы только проверить, выполните `nefo update --check`.

## Что происходит во время обновления {#what-happens-during-an-update}

1. Панель узнаёт номер последней версии из выпусков проекта на GitHub.
2. Она скачивает список контрольных сумм и его подпись и проверяет подпись ключом проекта, встроенным в панель.
3. Она скачивает новую программу для вашего процессора и сверяет её контрольную сумму SHA-256 со списком.
4. Она один раз запускает новую программу, чтобы убедиться, что та работает на этом сервере.
5. Она заменяет `/usr/local/bin/nefo` за один шаг, так что недописанной программы на диске не бывает никогда.
6. Она перезапускает службу `nefo`. Если выполняется задача, например установка программы, панель сначала даёт ей завершиться — до 75 секунд.

Когда новая версия запускается, она переводит базу данных панели в новый формат. Она также приводит управляемые ею файлы конфигурации (веб-сервера, пулов PHP-FPM) в соответствие со своими шаблонами. Если веб-сервер не принимает новые файлы, панель возвращает старые.

## Как проверяются выпуски {#how-releases-are-verified}

Каждый выпуск на GitHub содержит программы для amd64 и arm64, `install.sh`, файл `VERSION`, `checksums.txt` с контрольными суммами SHA-256 двух программ и установщика и `checksums.txt.sig` — подпись Ed25519 файла `checksums.txt`.

И установщик, и механизм обновления отклоняют `checksums.txt`, не подписанный ключом проекта, а также скачанный файл, контрольная сумма которого не совпадает. Во время обновления ошибки выглядят так:

- «checksums.txt has no valid signature from the project: the update was not installed» (у checksums.txt нет действительной подписи проекта: обновление не установлено);
- «the download does not match checksums.txt: not installed» (скачанный файл не соответствует checksums.txt: не установлено).

Поэтому тот, кто смог бы изменить файлы выпуска на GitHub или по пути к вашему серверу, не сможет добиться установки своей программы через обновление: обновление проверяется ключом, встроенным в уже работающую у вас Nefo. С первой установкой иначе: скачанный вами установщик несёт собственную копию ключа. Кроме того, ключ подписи хранится как секрет репозитория на GitHub, где GitHub Actions подписывает каждый выпуск, поэтому тот, кто захватил бы репозиторий, смог бы подписать выпуск. См. [Что подпись доказывает и чего не доказывает](../security-policy#what-the-signature-does-and-doesn-t-prove).

Сборка для разработки, сделанная без ключа проекта, не может проверять подписи. Она проверяет только контрольную сумму, а в её журнале написано «Development build: the release signature is not checked» (Сборка для разработки: подпись выпуска не проверяется).

## Что сохраняется {#what-is-kept}

Обновление заменяет только программу, `/usr/local/bin/nefo`. Всё остальное остаётся на месте:

- файл конфигурации `/etc/nefo/config.json`, включая порт и секретный путь;
- папка данных `/var/lib/nefo`: ваша учётная запись и двухфакторная аутентификация, настройки, сайты, расписания, сертификаты и журнал действий;
- ваши сайты, базы данных, файлы и резервные копии, а также службы, которые их обслуживают.

Перезапускается только панель. Сайты, базы данных и другие службы продолжают работать.

## Если обновление не удалось {#if-an-update-fails}

**Обновление останавливается до установки новой программы.** Так бывает, если скачивание не удалось, подпись или контрольная сумма не совпадает либо новая программа не запускается на этом сервере. Ничего не изменилось: продолжает работать старая версия. Ошибка видна в журнале задачи в панели или в терминале. Повторите попытку позже, а если ошибка не исчезает, сообщите о ней.

**Новая версия не запускается.** Проверьте службу и её журнал:

```sh
systemctl status nefo
journalctl -u nefo -n 50 --no-pager
```

Сообщите о проблеме в [репозитории на GitHub](https://github.com/nefocp/nefo/issues) и приложите этот вывод. Чтобы вернуться к предыдущему выпуску, установите его программу вручную. В этом примере используется `v0.1.0` на сервере amd64:

```sh
cd /tmp
curl -fsSLO https://github.com/nefocp/nefo/releases/download/v0.1.0/nefo-linux-amd64
curl -fsSLO https://github.com/nefocp/nefo/releases/download/v0.1.0/checksums.txt
grep " nefo-linux-amd64$" checksums.txt | sha256sum -c -
install -m 0755 nefo-linux-amd64 /usr/local/bin/nefo
systemctl restart nefo
```

Продолжайте, только если `sha256sum` выводит `OK`. На сервере ARM используйте `nefo-linux-arm64`.

::: warning Возврат к старой версии
Если более новая версия уже изменила базу данных панели, старая версия откажется запускаться с сообщением «database schema version … is newer than this panel supports» (версия схемы базы данных … новее, чем поддерживает эта панель). Тогда с этими данными работает только более новая версия. Перед важным обновлением можно сохранить копию папки данных: `systemctl stop nefo`, затем `cp -a /var/lib/nefo /root/nefo-data-copy`, затем `systemctl start nefo`.
:::

## Автоматические обновления {#automatic-updates}

Nefo не обновляется сама и не проверяет обновления по собственной инициативе. Проверка выполняется, только когда вы нажимаете **Проверить обновления** или запускаете `nefo update`. Чтобы узнавать о новых выпусках, следите за выпусками [репозитория на GitHub](https://github.com/nefocp/nefo/releases). В [журнале изменений](../changelog) перечислено, что изменилось в каждом из них.

Это касается только самой панели. Пакеты операционной системы — отдельная тема: панель проверяет их наличие раз в несколько часов, показывает их в разделе **Система** → **Обновления** и умеет автоматически устанавливать обновления безопасности. См. [Система](./os#updates).

## Откуда берутся обновления {#where-updates-come-from}

По умолчанию обновления берутся с `https://github.com/nefocp/nefo/releases/latest/download`. Поле `update_url` в `/etc/nefo/config.json` может указывать на другой адрес, где публикуются те же файлы. Адрес должен начинаться с `https://`, иначе проверка обновлений завершается ошибкой «update_url в config.json должен быть адресом https://.» Не задавайте это поле, если не уверены, что оно вам нужно.
