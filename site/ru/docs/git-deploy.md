# Развёртывание из Git

Nefo разворачивает сайт из Git-репозитория на GitHub, GitLab, Gitea, Forgejo или любом Git-сервере, по HTTPS или по SSH с отдельным ключом развёртывания для каждого сайта. Развёртывание запускается кнопкой или при каждом push через подписанный вебхук, после чего выполняется ваш скрипт развёртывания. Всё выполняется от имени собственного пользователя Linux сайта.

Развёртывание из Git находится на вкладке **Развёртывание из Git** каждого сайта, кроме сайтов Docker-приложений. На сайте, [файлы которого заблокированы](./website-protection#lock-a-website-s-files), панель разблокирует их на время развёртывания и затем снова блокирует.

## Перед началом {#before-you-start}

- **Адрес репозитория.** Nefo принимает три формы:
  - `https://github.com/owner/repo.git` для публичного репозитория;
  - `git@github.com:owner/repo.git` (форма, которую показывает GitHub) для закрытого;
  - `ssh://git@git.example.com:2222/owner/repo.git` для SSH-сервера на другом порту.

  Простой `http://` не принимается, как и пароль или токен в адресе, потому что он попал бы в журналы. Для закрытого репозитория используйте SSH-адрес и ключ развёртывания сайта.
- **Папка.** Выберите, куда попадут файлы:
  - **Веб-папка** (`/var/www/example.com/public`): для сайта, который и есть репозиторий, с `index.html` или `index.php` в корне.
  - **Папка сайта** (`/var/www/example.com`): для проектов со своей папкой `public`, например Laravel или Symfony. Тогда сайт показывает папку `public` репозитория.

  У сайта-приложения на Node.js, Python или Java выбора нет: используется **Папка приложения** (`/var/www/example.com/app`), откуда запускается его программа. Поместите `package.json` или `requirements.txt` в корень репозитория.
- **Пустая папка для первого развёртывания.** Страница приветствия панели не в счёт, как и папки `logs`, `tmp` и `.ssh` в папке сайта и папка `.venv` приложения Python в папке приложения. Остальные файлы сначала перенесите в другое место или разворачивайте в другую папку.
- **Git** устанавливать не нужно: если его нет, Nefo установит его при первом развёртывании.

## Настройка репозитория {#set-up-the-repository}

1. Откройте **Сайты**, затем вкладку сайта **Развёртывание из Git**.
2. Заполните поле **Адрес репозитория**.
3. Заполните поле **Ветка**, например `main`.
4. В разделе **Куда поместить файлы** выберите **Веб-папка** или **Папка сайта**. У сайта-приложения вместо этого показано **Папка приложения**, и выбирать нечего.
5. Необязательно: заполните поле **Скрипт развёртывания (необязательно)** (см. [Скрипт развёртывания](#the-deploy-script)).
6. Нажмите **Сохранить**.

В первый раз Nefo создаёт ключ развёртывания и секрет вебхука для сайта и сообщает: «Настройки сохранены. Добавьте в репозиторий ключ развёртывания и вебхук (они ниже), затем разверните сайт.»

## Добавление ключа развёртывания (закрытые репозитории) {#add-the-deploy-key-private-repositories}

Публичному HTTPS-репозиторию ключ не нужен. Для закрытого репозитория добавьте в него **Открытый ключ** сайта, показанный в разделе **Ключ развёртывания**, как ключ развёртывания только для чтения:

- **GitHub:** репозиторий → Settings → Deploy keys → Add deploy key (Настройки → Ключи развёртывания → Добавить ключ развёртывания). Оставьте «Allow write access» (Разрешить запись) выключенным.
- **GitLab:** проект → Settings → Repository → Deploy keys (Настройки → Репозиторий → Ключи развёртывания), без права записи.
- **Gitea и Forgejo:** репозиторий → Settings → Deploy keys.

У каждого сайта свой ключ ed25519, созданный от имени пользователя сайта в `/var/www/example.com/.ssh/panel_deploy`. **Новый ключ** заменяет его: старый ключ сразу перестаёт работать, поэтому добавьте новый ключ в репозиторий и удалите там старый.

При первом SSH-подключении ключ хоста Git-сервера принимается и запоминается в `/var/www/example.com/.ssh/known_hosts`. Если ключ сервера позже изменится, развёртывания будут завершаться ошибкой «The Git server's SSH host key is not the one seen before.» (SSH-ключ хоста Git-сервера не совпадает с замеченным ранее). Если сервер действительно сменил ключ, удалите этот файл и разверните сайт снова.

## Развёртывание {#deploy}

В разделе **Развернуть** нажмите **Развернуть сейчас**. Если вы меняли настройки, сначала сохраните их. Журнал показывает каждый шаг:

1. Nefo получает ветку из репозитория.
2. Отслеживаемые файлы приводятся к версии ветки из репозитория.
3. Выполняется скрипт развёртывания, если вы его написали.

Неотслеживаемые файлы остаются, поэтому загруженные файлы и файлы, которые репозиторий игнорирует (например, `.env`), сохраняются при каждом развёртывании. После первого развёртывания Nefo удаляет свою страницу приветствия, если репозиторий поместил сайт в `public`.

::: warning
Изменения, которые вы вносите на сервере в отслеживаемые репозиторием файлы, перезаписываются при следующем развёртывании. Вместо этого фиксируйте их в репозитории.
:::

После развёртывания вкладка показывает его статус (**Развёрнуто** или **Ошибка**), время, первые 12 символов коммита и его заголовок. Получение кода может длиться до 10 минут, скрипт — до 15 минут, а всё развёртывание — до 30 минут.

Если получить код не удалось, журнал объясняет обычные причины:

| Сообщение | Что сделать |
|---|---|
| `The repository refused the deploy key` | Добавьте в репозиторий ключ, показанный в панели. |
| `The repository is private or does not exist` | Проверьте адрес. Для закрытого репозитория используйте его SSH-адрес и добавьте ключ развёртывания. |
| `The repository has no branch …` | Проверьте поле **Ветка**. |
| `The Git server's SSH host key is not the one seen before` | См. раздел о ключе развёртывания выше. |
| `The repository's host name was not found` | Проверьте адрес. |
| `It took longer than 10 minutes` | Попробуйте снова; проверьте размер репозитория и сеть. |

## Скрипт развёртывания {#the-deploy-script}

Скрипт выполняется после каждого развёртывания в папке развёртывания от имени пользователя сайта, не дольше 15 минут. Он может содержать до 2000 символов. Например, для сайта на Laravel:

```sh
composer install --no-dev --optimize-autoloader
php artisan migrate --force
```

На сайте-приложении скрипт выполняется в папке `app`, например `npm ci`, а затем `npm run build`. Его `node` и `npm` — это версия Node.js, выбранная для сайта, а на сайте Python `python` и `pip` берутся из его виртуального окружения (`app/.venv`). На сайте Java `java`, `javac` и `JAVA_HOME` относятся к выбранной для него версии Java, поэтому `./mvnw package` или `./gradlew build` собирают проект этой версией.

- Скрипт запускается через `sh -e`: он останавливается на первой команде с ошибкой, и развёртывание получает статус **Ошибка**. Новые файлы к этому моменту уже на месте.
- `php` — это версия PHP сайта, в том числе для Composer.
- `DEPLOY_COMMIT` содержит развёрнутый коммит, а `DEPLOY_BRANCH` — ветку.
- `HOME` — это папка `tmp` сайта.
- Скрипт не может использовать `sudo` или перезапускать системные службы. Чтобы после развёртывания перезапустить программу сайта-приложения, нажмите **Перезапустить** на вкладке **Обзор** сайта.

## Развёртывание при каждом push {#deploy-on-every-push}

В разделе **Развёртывание при push** Nefo показывает **URL вебхука**, например `https://example.com/.panel/deploy/12`, и его **Секрет**. Вебхук находится на собственном домене сайта, поэтому хостингу репозитория никогда не нужно обращаться к порту панели. Веб-сервер передаёт его небольшому обработчику панели на `127.0.0.1:7809`.

::: warning
Без HTTPS URL вебхука использует `http://`, и GitLab отправлял бы секрет без шифрования. Сначала включите HTTPS: см. [SSL-сертификаты](./ssl).
:::

Каждый push в выбранную ветку разворачивает сайт. Push в другие ветки, push тегов, другие события и удаление веток игнорируются.

### GitHub {#github}

1. Откройте репозиторий → Settings → Webhooks → Add webhook (Настройки → Вебхуки → Добавить вебхук).
2. Вставьте **URL вебхука** в поле Payload URL, а **Секрет** — в поле Secret.
3. Установите content type `application/json`.
4. Выберите «Just the push event» (Только событие push) и добавьте вебхук.

GitHub сразу отправляет тестовый запрос (ping), и панель на него отвечает, поэтому первая доставка показывается как успешная.

### GitLab {#gitlab}

1. Откройте проект → Settings → Webhooks.
2. Вставьте **URL вебхука** в поле URL, а **Секрет** — в поле Secret token.
3. Отметьте Push events и добавьте вебхук.

### Gitea и Forgejo {#gitea-and-forgejo}

1. Откройте репозиторий → Settings → Webhooks → Add webhook и выберите Gitea (или Forgejo).
2. Вставьте **URL вебхука** в поле Target URL, а **Секрет** — в поле Secret.
3. Установите content type `application/json`, выберите срабатывание на события push и добавьте вебхук.

Gogs работает так же: на шаге 1 выберите Gogs.

### Как панель проверяет вебхук {#how-the-panel-checks-a-webhook}

- GitHub, Gitea, Forgejo и Gogs подписывают каждый вебхук секретом (HMAC-SHA256). GitLab отправляет сам секрет. Вебхук с неверной подписью или без неё получает HTTP 401 и записывается в журнал вместе с адресом отправителя.
- Защита сайта паролем и веб-брандмауэр не действуют на путь вебхука, поэтому делать для него исключение не нужно.
- Nefo выполняет одну задачу за раз. Если при поступлении push выполняется другая задача, развёртывание ждёт и повторяется каждые 15 секунд в течение часа. Если за это время пришло несколько push, нужно одно развёртывание: оно получает самый новый коммит.
- **Новый секрет** заменяет секрет. Push отклоняются, пока вы не вставите новый секрет в вебхук репозитория.

Хостинг репозитория показывает ответ панели в списке последних доставок: `deploying`, `queued: another task is running`, `ignored: not branch main` или ошибку, например `bad_signature`.

## Журнал развёртывания {#the-deploy-log}

- Вкладка **Развёртывание из Git** показывает журнал текущего или последнего развёртывания, в том числе запущенного через push.
- **Учётная запись** → **Последние действия** перечисляет каждое развёртывание как «Развёртывание из Git» или «Ошибка развёртывания из Git» с сайтом, коммитом и тем, что его запустило (`manual` или push с хостинга репозитория).

## Отключение развёртывания из Git {#stop-deploying-from-git}

В разделе **Прекратить развёртывание из Git** нажмите **Прекратить развёртывание из Git** и подтвердите. Nefo забывает настройки и удаляет ключ развёртывания. Развёрнутые файлы остаются в папке вместе с папкой `.git` репозитория.
