# Командная строка

Программа `nefo` в `/usr/local/bin/nefo` запускает панель и предоставляет команды для пользователя root на сервере: `nefo info` показывает адрес панели, `nefo reset-password` задаёт новый пароль (и может выключить 2FA), `nefo update` устанавливает последний выпуск, а `nefo setup` устанавливает программы. Выполняйте все команды от имени root.

На этой странице перечислены команды, затем показано, как управлять службой `nefo` и что содержится в файле конфигурации.

## Команды {#commands}

| Команда | Что делает |
|---|---|
| `nefo info` | Показывает URL панели |
| `nefo reset-password` | Задаёт новый случайный пароль и завершает все сеансы |
| `nefo update` | Устанавливает последний выпуск и перезапускает панель |
| `nefo setup` | Устанавливает веб-сервер, версии PHP, сервер баз данных и дополнительные компоненты |
| `nefo unlock-files` | Возвращает заблокированным сайтам их файлы (перед удалением панели) |
| `nefo decrypt-backup` | Расшифровывает копию, которую зашифровало удалённое хранилище |
| `nefo version` | Показывает версию |
| `nefo init` | Создаёт файл конфигурации и первую учётную запись администратора |
| `nefo serve` | Запускает панель (это делает за вас systemd) |
| `nefo help` | Показывает список команд |

Выполните `nefo <command> -h`, чтобы увидеть параметры команды. Параметры работают с одним дефисом или с двумя: `-port` и `--port` — одно и то же.

Все команды, кроме `version`, `help` и `decrypt-backup`, читают файл конфигурации `/etc/nefo/config.json`. Чтобы использовать другой файл, добавьте `--config /path/to/config.json` или задайте переменную окружения `NEFO_CONFIG`.

## nefo info {#nefo-info}

Показывает URL панели и расположение её файлов.

```sh
nefo info
```

```
URL:    https://panel.example.com:28443/k3x9p2qa7m1z/
URL:    https://203.0.113.10:28443/k3x9p2qa7m1z/
Config: /etc/nefo/config.json
Data:   /var/lib/nefo
```

Первая строка появляется, когда у панели есть собственный домен (**Настройки** → **Сертификат**). Во второй используется первый IP-адрес сервера. Если провайдер выдаёт серверу частный адрес и отдельный публичный, передайте публичный:

```sh
nefo info --host 203.0.113.10
```

| Параметр | Что делает |
|---|---|
| `--host` | Имя хоста или IP-адрес, который нужно показать в URL |
| `--port` | Выводит только номер порта, для скриптов |
| `--config` | Файл конфигурации, который нужно прочитать |

## nefo reset-password {#nefo-reset-password}

Задаёт учётной записи новый случайный пароль, завершает её сеансы на всех устройствах и выводит пароль. Используйте, если забыли пароль.

```sh
nefo reset-password
```

```
New password for admin: ••••••••••••••••••••
```

Если вы потеряли и телефон с приложением-аутентификатором, добавьте `--disable-2fa`. Этот параметр выключает двухфакторную аутентификацию для учётной записи:

```sh
nefo reset-password --disable-2fa
```

```
New password for admin: ••••••••••••••••••••
Two-factor authentication is off. Turn it on again after signing in.
```

| Параметр | Что делает |
|---|---|
| `--disable-2fa` | Также выключает двухфакторную аутентификацию |
| `--user` | Имя учётной записи (по умолчанию `admin`, единственная учётная запись панели) |
| `--config` | Файл конфигурации, который нужно прочитать |

Панель продолжает работать: перезапускать её не нужно. Сброс записывается в журнал действий.

## nefo update {#nefo-update}

Проверяет выпуски проекта на GitHub. Если есть более новая версия, скачивает её, проверяет подпись и контрольную сумму, заменяет программу и перезапускает панель.

```sh
nefo update
```

Чтобы только узнать, доступно ли обновление:

```sh
nefo update --check
```

```
Installed: v0.1.0
Latest:    v0.2.0
```

| Параметр | Что делает |
|---|---|
| `--check` | Только показывает установленную и последнюю версию |
| `--config` | Файл конфигурации, который нужно прочитать |

Что проверяет обновление и что делать, если оно не удалось, см. в разделе [Обновление](./update).

## nefo setup {#nefo-setup}

Настраивает сервер так же, как страница первоначальной настройки в панели (см. [Первые шаги](./first-steps#set-up-the-server)): устанавливает веб-сервер, версии PHP, сервер баз данных и дополнительные компоненты, одно за другим. Уже установленные части пропускаются, поэтому после сбоя команду можно запустить снова. Когда она завершится, панель больше не открывает страницу настройки после входа.

```sh
nefo setup --web nginx --php 8.3,8.4 --db mariadb --redis
```

```
This server: 1 CPU, 960 MB of RAM (250 MB in use), 19.5 GB of free disk.

What the setup installs, one after the other:
  1. Nginx and PHP 8.3  about 40 MB of RAM, 55 MB of disk
  2. PHP 8.4            about 25 MB of RAM, 50 MB of disk, from packages.sury.org
  3. MariaDB            about 228 MB of RAM, 300 MB of disk
  4. Redis              up to 64 MB of RAM, 10 MB of disk
In all: about 357 MB more RAM and 415 MB of disk.

Install? [y/N]
```

После ответа `y` команда показывает журнал каждой установки. Если одна из них не удалась, команда останавливается, сообщает, что уже установлено, и завершается с ошибкой. Без `--web`, `--php`, `--db` или дополнительного компонента она предлагает рекомендуемый вариант для объёма оперативной памяти сервера, как и страница настройки.

Пока панель работает, `nefo setup` поручает установки панели как одну из её задач: они ждут завершения других задач, видны в панели и продолжаются, даже если закрыть сеанс SSH. С панелью команда общается через сокет в папке данных, который может открыть только root. Если панель не запущена, `nefo setup` выполняет установки сама.

| Параметр | Что делает |
|---|---|
| `--web` | `nginx`, `apache`, `openlitespeed` или `none`. Веб-сервер устанавливается с версией PHP из вашего дистрибутива |
| `--php` | Версии PHP через запятую, например `8.3,8.4`, или `none` |
| `--db` | `mariadb`, `mysql` или `none`; `mariadb-11.4`, `mariadb-11.8` или `mariadb-12.3` для серии LTS из репозитория MariaDB, если сервер её предлагает (см. [Версии MariaDB](./databases#mariadb-versions)). `--mariadb` — то же, что `--db mariadb` |
| `--redis`, `--node`, `--python`, `--docker` | Также устанавливает Redis, Node.js (самый новый выпуск LTS), Python для сайтов-приложений или Docker |
| `--adminer`, `--waf` | Также устанавливает Adminer или веб-брандмауэр. Обоим нужен веб-сервер |
| `--clamav` | Также устанавливает ClamAV, на серверах с 2 GB оперативной памяти или больше |
| `--postgresql`, `--memcached` | Также устанавливает PostgreSQL или Memcached, если их предлагает страница «Программы» |
| `--yes`, `-y` | Устанавливает без вопросов. Нужен, когда терминал не подключён, например в скрипте |
| `--dry-run` | Только показывает, что было бы установлено |
| `--skip` | Ничего не устанавливает: панель больше не открывает страницу настройки после входа |
| `--wait` | Сколько ждать запуска панели, например `60s`. Его использует установщик |
| `--check` | Только проверяет параметры. Установщик использует его, прежде чем что-либо настраивать |
| `--config` | Файл конфигурации, который нужно прочитать |

Установщик принимает те же параметры, чтобы настроить сервер в том же запуске (см. [Установка](./install#set-the-server-up-in-the-same-run)).

## nefo unlock-files {#nefo-unlock-files}

Возвращает каждому сайту с заблокированными файлами (**Сайты** → (сайт) → **Блокировка файлов**, см. [Блокировка по странам и блокировка файлов](./website-protection#lock-a-website-s-files)) его файлы — ровно с теми владельцем, группой и правами, которые были у каждого из них до блокировки, — и удаляет группы блокировки сайтов. Запускайте её от имени root при остановленной панели, перед удалением Nefo (см. [Удаление](./uninstall#unlock-the-websites-files)).

```sh
systemctl stop nefo
nefo unlock-files
```

```
Unlocked the files of example.com
Unlocked the files of blog.example.com
```

Если ни один сайт не заблокирован, команда выводит `No website's files are locked.`

| Параметр | Что делает |
|---|---|
| `--config` | Файл конфигурации, который нужно прочитать |

## nefo decrypt-backup {#nefo-decrypt-backup}

Расшифровывает копию, которую зашифровало удалённое хранилище (файл `.tar.gz.enc`), например скачанную из Google Drive. Нужна только парольная фраза: команда работает на любом сервере, в том числе там, где панель не настроена, и не читает файл конфигурации. См. [Восстановление на новом сервере](./restore-new-server#decrypt-a-copy-by-hand).

```sh
nefo decrypt-backup example.com_20261126-030000.tar.gz.enc
```

```
Passphrase:
Decrypted to example.com_20261126-030000.tar.gz
SHA-256: 3f1c…
```

Парольная фраза никогда не передаётся в командной строке, где её могли бы увидеть другие пользователи. В терминале она запрашивается без отображения; иначе это первая строка стандартного ввода или файла из `-passphrase-file`.

| Параметр | Что делает |
|---|---|
| `-o` | Выходной файл. По умолчанию — имя входного файла без `.enc`. `-o -` пишет в стандартный вывод, например `nefo decrypt-backup -o - FILE.enc \| tar xz` |
| `-passphrase-file` | Читает парольную фразу из первой строки этого файла |
| `-force` | Заменяет выходной файл, если он существует |

Результат записывается во временный файл и переименовывается, только когда расшифрована вся копия, поэтому неверная парольная фраза или повреждённый файл ничего не оставляют после себя (кроме случая `-o -`, когда конец файла проверяется последним). Незашифрованный файл копируется как есть, с примечанием. Выводимая сумма SHA-256 — та, которую панель записала для этой резервной копии.

## nefo version {#nefo-version}

Показывает версию и коммит, из которого она собрана. `nefo --version` и `nefo -v` делают то же самое.

```sh
nefo version
```

```
Nefo v0.1.0 (commit 1a2b3c4)
```

## nefo init {#nefo-init}

Создаёт файл конфигурации и первую учётную запись администратора. Установщик запускает эту команду сам, поэтому обычно она вам не нужна. Она не перезаписывает существующий файл конфигурации.

Команда выбирает случайный порт от 20000 до 49999 и случайный секретный путь, включает HTTPS и создаёт учётную запись `admin` со случайным паролем. Если в папке данных уже есть учётные записи, она сохраняет их, записывает только новый файл конфигурации и не выводит пароль.

| Параметр | Что делает |
|---|---|
| `--config` | Куда записать файл конфигурации (по умолчанию `/etc/nefo/config.json`) |
| `--data` | Папка данных (по умолчанию `/var/lib/nefo`) |
| `--listen` | Адрес для прослушивания, например `:28443`, вместо случайного порта |
| `--host` | Имя хоста или IP-адрес, который нужно показать в выведенном URL |
| `--dev` | Режим разработки: обычный HTTP на `127.0.0.1:8080` с путём `dev`. Никогда не используйте его на сервере. |

## nefo serve {#nefo-serve}

Запускает панель. Служба `nefo` запускает её командой `nefo serve --config /etc/nefo/config.json`, поэтому сами вы её не запускаете. Вторая копия не запустится, потому что порт уже занят службой.

## Управление службой nefo {#manage-the-nefo-service}

| Команда | Что делает |
|---|---|
| `systemctl status nefo` | Показывает, работает ли панель, и последние строки её журнала |
| `systemctl restart nefo` | Перезапускает панель |
| `systemctl stop nefo` | Останавливает панель |
| `systemctl start nefo` | Запускает панель |
| `journalctl -u nefo` | Показывает журнал панели |
| `journalctl -u nefo -f` | Следит за журналом по мере появления новых строк |
| `journalctl -u nefo -n 100 --no-pager` | Показывает последние 100 строк |
| `journalctl -u nefo --since "1 hour ago"` | Показывает журнал за последний час |

Перезапуск панели не останавливает ваши сайты, базы данных и другие службы. Перезапустить её можно и в разделе **Настройки** → **Панель** → **Питание** → **Перезапустить панель**.

При остановке панель сначала даёт завершиться выполняющейся задаче, например установке программы, — до 75 секунд. Если панель остановилась из-за ошибки, systemd снова запускает её через 3 секунды.

Файл службы — `/etc/systemd/system/nefo.service`:

```ini
[Unit]
Description=Nefo server control panel
Documentation=https://nefo.io
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=/usr/local/bin/nefo serve --config /etc/nefo/config.json
Restart=on-failure
RestartSec=3
UMask=0077
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
```

Панель работает от имени root, потому что управляет всем сервером.

## Файл конфигурации {#the-configuration-file}

`/etc/nefo/config.json` доступен для чтения только root. Его записывает установщик, например:

```json
{
  "listen": ":28443",
  "entrance": "k3x9p2qa7m1z",
  "data_dir": "/var/lib/nefo",
  "tls": {
    "enabled": true
  }
}
```

| Поле | Что означает |
|---|---|
| `listen` | Адрес и порт, на которых слушает панель. `:28443` означает порт 28443 на всех адресах. |
| `entrance` | Секретный путь. От 8 до 32 строчных латинских букв или цифр. На любой другой путь панель отвечает `404`. |
| `data_dir` | Папка данных: база данных панели `nefo.db`, сертификаты и ключи. |
| `tls.enabled` | HTTPS для панели. Не выключайте. |
| `tls.cert`, `tls.key` | Необязательные пути к вашим собственным сертификату и ключу для панели. Они важнее сертификата Let's Encrypt панели и самоподписанного сертификата. |
| `acme_directory` | Необязательный центр сертификации для сертификатов. Пустое значение означает Let's Encrypt. Во время тестов задайте `https://acme-staging-v02.api.letsencrypt.org/directory`: тестовым (staging) сертификатам браузеры не доверяют, но неудачные попытки не засчитываются в лимиты Let's Encrypt. |
| `update_url` | Необязательный адрес, с которого скачиваются обновления. Пустое значение означает выпуски проекта на GitHub. Адрес должен начинаться с `https://`. |
| `dev` | Режим разработки. Никогда не задавайте его на сервере. |

После правки файла перезапустите панель командой `systemctl restart nefo`. Если в файле есть ошибка, панель не запускается: причину показывает `journalctl -u nefo`.

::: warning Смена порта
Если вы меняете порт в `listen`, сначала откройте новый порт — и в ufw (например, `ufw allow 31234/tcp`), и в облачном брандмауэре провайдера. Иначе после перезапуска вы не сможете открыть панель.
:::
