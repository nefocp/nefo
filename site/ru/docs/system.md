# Системные инструменты

**Панель мониторинга** показывает загрузку CPU, памяти, диска и нагрузку на сервер в реальном времени с историей за 7 дней и перечисляет то, что требует внимания. Серверные инструменты Nefo также управляют заданиями cron, службами systemd, фоновыми программами, которые должны работать постоянно, процессами и прослушиваемыми портами, показывают входы по SSH, открывают терминал root в браузере, перезапускают панель и перезагружают сервер.

На этой странице описан каждый из этих инструментов и сказано, где искать журналы. Большинство из них находятся в группе **Сервер** левого меню. Обновления операционной системы, swap, часовой пояс и имя хоста, TCP BBR и очистка диска — на странице [Система](./os).

## Панель мониторинга {#dashboard}

**Панель мониторинга** открывается после входа.

- Вверху страницы показаны имя сервера, операционная система, время работы, число процессоров и память. На VPS, который сам является контейнером (LXC), память — это ограничение контейнера с пометкой «лимит контейнера» (см. [VPS в контейнере](./first-steps#a-vps-that-is-a-container)). Кнопки там позволяют **Проверить обновления**, открыть **Терминал** и воспользоваться меню **Питание**.
- Четыре индикатора показывают текущие значения: **Нагрузка на систему**, CPU, **Память** и **Диск /**. Они обновляются каждые 5 секунд. Нагрузка на систему — это средняя нагрузка за 1 минуту, делённая на число процессоров.
- Плитки показывают количество сайтов, баз данных, учётных записей SFTP, заданий cron, резервных копий и рисков безопасности. Выберите плитку, чтобы открыть её страницу. Когда серьёзных проблем нет, плитка **Риски безопасности** показывает, когда в последний раз выполнялась [проверка безопасности](./security-check).
- Блок **История ресурсов** строит график CPU, памяти, диска, нагрузки или сети за 1 час, 24 часа или 7 дней. Под графиком — значения **Сейчас**, **Среднее** и **Максимум**. Для сети показаны скорости **Входящий** и **Исходящий** и итоги за выбранный период.
- Блок **Требует внимания** перечисляет проблемы, которые требуют вашего участия, начиная с самых серьёзных.
- Блок **Установленные программы** показывает основные компоненты и их состояние.

Панель записывает нагрузку каждую минуту и хранит историю за 7 дней. После новой установки графики появляются через несколько минут. Внизу левого меню также показано текущее использование CPU и памяти.

### Что проверяет блок «Требует внимания» {#what-needs-attention-checks}

- Двухфакторный вход выключен.
- Root может входить по SSH с паролем.
- Брандмауэр выключен.
- Сертификат сайта не удалось продлить, он истёк или истекает в течение 14 дней.
- Срок действия сайта истекает в течение 7 дней.
- Резервное копирование по расписанию завершилось ошибкой.
- Диск заполнен на 90% или больше.
- Ожидают установки обновления безопасности операционной системы (см. [Обновления](./os#updates)).
- Серверу нужна перезагрузка, чтобы завершить установку обновлений.
- Последняя [проверка безопасности](./security-check) нашла критичные проблемы или предупреждения.
- Сайт, доступность которого отслеживается, не отвечает (см. [Мониторинг](./websites#monitoring)).

Колокольчик справа вверху (**Уведомления**) показывает тот же список. И то и другое видно, только пока вы вошли в панель. Чтобы вместо этого получать сообщения в Telegram, по электронной почте, в Discord, Slack или через вебхук, настройте [оповещения](./mail-alerts).

## Задания cron {#cron-jobs}

Задания cron выполняют команды по расписанию. Откройте **Задания cron** в левом меню.

### Добавление задания cron {#add-a-cron-job}

1. Нажмите **Добавить задание cron**.
2. В поле **Название** введите имя длиной до 100 символов.
3. В поле **Запускать от имени** выберите root или пользователя сайта (показан с доменом). Задачи сайта запускайте от имени его собственного пользователя, а root используйте только для серверных задач.
4. Задайте **Расписание**. Выберите типовое расписание (**Каждые 5 минут**, **Каждый час**, **Каждый день в 03:00**, **Каждое воскресенье в 04:00**, **При запуске сервера**) или введите своё. Под полем панель описывает расписание словами.
5. В поле **Команда** введите команду оболочки в одну строку длиной до 2000 символов; она выполняется через `/bin/sh`.
6. Оставьте включённым переключатель **Включено** и нажмите **Сохранить**.

Для пользователя сайта с PHP ссылка **Использовать команду cron WordPress** подставляет cron WordPress, например `php8.3 /var/www/example.com/public/wp-cron.php`, каждые 5 минут.

### Синтаксис расписания {#schedule-syntax}

Расписание состоит из пяти полей, время — серверное:

| Поле | Значения |
|---|---|
| минута | 0–59 |
| час | 0–23 |
| день месяца | 1–31 |
| месяц | 1–12 |
| день недели | 0–7 (0 и 7 — воскресенье) |

В каждом поле используйте `*` для любого значения, список вроде `1,15`, диапазон вроде `1-5` или шаг вроде `*/10`. Вместо пяти полей можно также указать одно из этих значений: `@hourly`, `@daily` (или `@midnight`), `@weekly`, `@monthly`, `@yearly` (или `@annually`) и `@reboot`. Панель не принимает числа вне диапазона, например минуту 60.

| Расписание | Когда выполняется |
|---|---|
| `*/5 * * * *` | каждые 5 минут |
| `0 3 * * *` | каждый день в 03:00 |
| `30 2 * * 1` | каждый понедельник в 02:30 |
| `0 0 1 * *` | в полночь 1-го числа каждого месяца |

### Как выполняются задания cron {#how-cron-jobs-run}

- Панель записывает задания в `/etc/cron.d/panel`, поэтому системный cron выполняет их, даже когда панель остановлена. Не редактируйте этот файл: панель его перезаписывает.
- Вывод и ошибки команды добавляются в журнал задания `/var/log/panel-cron/<id>.log`, который принадлежит пользователю задания.
- Символ `%` в команде работает так, как введён: панель экранирует его для cron.
- Задание перестаёт выполняться, когда его пользователя больше нет, например после удаления сайта.

### Запуск, проверка и изменение задания {#run-check-and-change-a-job}

- Переключатель в столбце **Вкл.** включает или выключает задание. Выключенное задание остаётся в списке.
- Кнопка **Выполнить сейчас** сразу запускает задание от имени его пользователя и показывает вывод в реальном времени. Через час выполнение прерывается.
- Пункт **Журналы** в меню ⋯ строки показывает конец журнала задания. Журналы больше 5 MB обрезаются до последнего 1 MB.
- **Изменить** и **Удалить** находятся в том же меню. При удалении задания удаляется и его журнал.

Над списком можно показать **Все** задания или только **Включённые** или **Выключенные**, а также искать по названию, команде или пользователю.

## Службы {#services}

Страница **Службы** перечисляет системные службы, которыми управляет Nefo, если они установлены:

| Служба | Юнит systemd |
|---|---|
| Nefo | `nefo` |
| Nginx, Apache или OpenLiteSpeed | `nginx`, `apache2`, `lshttpd` |
| PHP-FPM, по одной на каждую установленную версию | например `php8.3-fpm` |
| MariaDB или MySQL | `mariadb` или `mysql` |
| PostgreSQL | например `postgresql@16-main` |
| Redis | `redis-server` |
| Memcached | `memcached` |
| fail2ban | `fail2ban` |
| SSH | `ssh` |
| Cron | `cron` |
| Брандмауэр (ufw) | `ufw` |

Другие службы, например Docker или Postfix, в списке не показаны. В каждой строке видно состояние (**Работает**, **Остановлено**, **Ошибка**…), сколько времени служба работает, пометка «не запускается при загрузке», если это так, и использование памяти.

Действия зависят от службы:

| Служба | Действия |
|---|---|
| Веб-сервер, PHP-FPM | **Запустить**, **Остановить**, **Перезапустить**, **Перечитать конфигурацию** |
| Nefo | **Перезапустить** |
| SSH | **Перезапустить**, **Перечитать конфигурацию** |
| Остальные | **Запустить**, **Остановить**, **Перезапустить** |

- Действие **Остановить** просит подтверждения, потому что сайты, которым нужна эта служба, перестанут работать.
- Прежде чем перезапустить веб-сервер или перечитать его конфигурацию, панель проверяет конфигурацию. Если проверка не проходит, ничего не перезапускается и показывается ошибка.
- SSH нельзя остановить из панели, чтобы вы не закрыли себе доступ к серверу.
- После перезапуска Nefo страница перезагружается через несколько секунд.
- Пункт **Журналы** показывает последние 150 строк журнала службы.

Панель не меняет, запускается ли служба при загрузке.

## Фоновые программы {#background-programs}

Фоновые программы — это команды, которые должны работать постоянно, например обработчик очереди. Панель запускает каждую из них как службу systemd от имени пользователя Linux сайта и снова запускает её, когда она останавливается. Сначала нужен хотя бы один сайт.

### Добавление программы {#add-a-program}

1. Откройте **Фоновые программы** и нажмите **Добавить программу**.
2. В поле **Название** введите имя длиной до 60 символов.
3. Выберите **Сайт**. Программа работает от имени пользователя Linux этого сайта, никогда не от root.
4. Необязательно: в поле **Рабочая папка** укажите папку внутри папки сайта, например `app`. Оставьте поле пустым, чтобы использовать саму папку сайта.
5. В поле **Команда** введите одну программу с аргументами, в одну строку, длиной до 1000 символов.
6. Необязательно: добавьте **Переменные окружения** — по одной `NAME=value` на строку, не больше 20. На сервере их может прочитать только root.
7. Оставьте включённым переключатель **Запустить сейчас и при запуске сервера** и нажмите **Создать**.

Для PHP-сайта ссылка **Использовать обработчик очереди Laravel** подставляет `php8.3 artisan queue:work --sleep=3 --tries=3 --max-time=3600` с версией PHP сайта.

### Как работают фоновые программы {#how-background-programs-run}

- Каждая программа — это служба systemd с именем `panel-daemon-<id>.service`.
- Когда программа завершается по любой причине, systemd запускает её снова через 3 секунды.
- При загрузке она запускается после MariaDB и Redis.
- Она работает с защитами systemd: `/usr`, `/boot` и `/etc` доступны только для чтения, `/home` и `/root` скрыты, а `/tmp` у неё свой.
- Рабочая папка должна существовать и оставаться внутри папки сайта, в том числе через символические ссылки.
- Её вывод попадает в системный журнал.

### Управление программой {#control-a-program}

В каждой строке видно состояние (работает, перезапускается, ошибка, останавливается или остановлено), сколько раз программа перезапускалась и сколько памяти она использует.

- В строке кнопкой показано **Запустить** (когда программа остановлена) или **Перезапустить** (когда она работает). Остальные действия, включая **Остановить**, находятся в меню ⋯ строки. Действие **Остановить** оставляет программу остановленной, в том числе после перезагрузки, пока вы снова её не запустите.
- Пункт **Журналы** показывает последние 200 строк, которые вывела программа.
- Пункт **Изменить** открывает настройки программы. Кнопка **Сохранить** перезапускает её с новыми настройками.
- Пункт **Удалить** останавливает и удаляет её.

При удалении сайта его фоновые программы тоже останавливаются и удаляются.

## Процессы и порты {#processes-and-ports}

Страница **Процессы** показывает, что работает на сервере, на трёх вкладках: **Процессы**, **Порты** и **Входы по SSH**.

### Процессы {#processes}

В списке показаны самые загруженные процессы, не больше 300. Сортируйте по PID, CPU % или памяти с помощью заголовков столбцов и фильтруйте по имени, пользователю или PID. Переключатель **Обновлять каждые 5 секунд** поддерживает список в актуальном состоянии.

CPU % измеряется за последние несколько секунд: 100% — это одно ядро процессора, занятое всё время.

Чтобы остановить процесс, нажмите кнопку остановки в конце его строки, затем:

- Действие **Остановить** просит программу завершить работу и выйти (сигнал TERM). Хорошо написанные программы сначала сохраняют свои данные.
- Действие **Принудительно остановить** завершает её сразу (сигнал KILL). Используйте этот вариант, только когда **Остановить** не помогает: несохранённые данные будут потеряны.

Службу, запущенную через systemd, systemd может запустить снова. Панель не может остановить системный процесс init (PID 1), саму панель, процесс, запустивший панель, и потоки ядра. Каждая остановка записывается в журнал действий.

### Порты {#ports}

Вкладка **Порты** перечисляет порты TCP и UDP, которые слушают программы, со столбцами **Адрес**, **Программа** и **Доступен из**: **только с этого сервера** или **из сети**.

Порт, открытый в сеть, всё равно может быть закрыт снаружи брандмауэром. См. [Брандмауэр](./security#firewall-ufw).

## Входы по SSH {#ssh-sign-ins}

Вкладка **Процессы** → **Входы по SSH** перечисляет входы по SSH и неудачные попытки за последние 30 дней, начиная с самых новых, не больше 200. В каждой строке видны время, результат (**вход выполнен**, **неверный пароль** или **неизвестный пользователь**), пользователь, IP-адрес и метод, например `publickey` или `password`.

Показывайте **Все**, **Только успешные** или **Только неудачные**. Список читается из журнала службы SSH.

Много неудачных попыток обычно означает, что кто-то подбирает пароли. Выключите вход по паролю или установите fail2ban, чтобы блокировать такие адреса. См. [Безопасность](./security#brute-force-protection-fail2ban).

## Терминал {#terminal}

Страница **Терминал** открывает в браузере оболочку root (bash) на сервере.

::: warning
Терминал — то же самое, что сеанс SSH от имени root: каждая команда выполняется с полными правами, и ошибочная команда может удалить данные или остановить сервер. Панель не может отменить то, что вы там выполнили.
:::

- Сеанс завершается, когда вы уходите со страницы, или после 30 минут без ввода. Нажмите **Подключиться снова**, чтобы открыть новый.
- Одновременно можно открыть до 4 терминалов, включая терминалы контейнеров.
- Журнал действий записывает, когда терминал был открыт и закрыт и сколько времени он работал. Команды он не записывает.

## Журналы {#logs}

Отдельной страницы журналов в Nefo нет. Каждый журнал показан рядом с тем, к чему он относится:

| Журнал | Где |
|---|---|
| Журнал доступа сайта, журнал ошибок, ошибки PHP и журналы приложения | **Сайты** → (сайт) → **Журналы** |
| События брандмауэра сайта | **Сайты** → (сайт) → **Веб-брандмауэр (WAF)** |
| Вывод задания cron | **Задания cron** → **Журналы** |
| Журнал службы | **Службы** → **Журналы** |
| Вывод фоновой программы | **Фоновые программы** → **Журналы** |
| Контейнеры и проекты Compose | **Docker** |
| Что делалось в панели | **Учётная запись** → **Последние действия** |
| Собственный журнал службы панели | `journalctl -u nefo` на сервере |

Журналы доступа, ошибок и PHP сайта показывают последние 300 строк. Чтобы загрузить новые строки, нажмите **Обновить** в окне журнала.

## Перезапуск панели и перезагрузка сервера {#restart-the-panel-or-reboot-the-server}

Откройте **Настройки** → **Панель** → **Питание**. На странице **Панель мониторинга** те же действия есть в меню **Питание**.

- Действие **Перезапустить панель** перезапускает только панель. Сайты, базы данных и другие службы продолжают работать, а панель возвращается через несколько секунд.
- Действие **Перезагрузить сервер** перезагружает весь сервер. Сайты и базы данных недоступны, пока он не вернётся, обычно одну-две минуты. Для подтверждения введите имя сервера.

В обоих случаях страница перезагружается сама, когда панель снова отвечает. Оба действия запрещены, пока выполняется фоновая задача, например установка или резервное копирование: дождитесь её завершения. Оба записываются в журнал действий.

На сервере панель можно также перезапустить командой:

```sh
systemctl restart nefo
```
