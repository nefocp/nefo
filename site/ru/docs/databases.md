# Базы данных

На сервере Nefo работает один MySQL-совместимый сервер баз данных: MariaDB (из вашего дистрибутива или 11.4, 11.8 либо 12.3 LTS от MariaDB) или MySQL 8.4 LTS. Он настроен для небольшого VPS и доступен только с самого сервера. Страница **Базы данных** создаёт базы данных и пользователей, импортирует и экспортирует SQL, открывает отдельную базу данных для выбранных адресов и показывает медленные запросы. Рядом может работать PostgreSQL.

На этой странице описано:

- выбор между MariaDB и MySQL и выбор версии MariaDB, установка, настройка Nefo для небольшого сервера, обновление MariaDB и переход с одного сервера на другой;
- создание баз данных, просмотр данных для входа и смена паролей;
- импорт и экспорт SQL;
- удалённый доступ, для каждой базы данных отдельно;
- журнал медленных запросов;
- Adminer и phpMyAdmin — интерфейсы для работы с базами данных в браузере;
- просмотр ключей Redis на вкладке **Redis** той же страницы и состояние Memcached.

У PostgreSQL на этой странице своя вкладка **PostgreSQL** и своя страница документации: см. [PostgreSQL](./postgresql). MongoDB, а также PostgreSQL в контейнере доступны в [магазине приложений](./apps) как Docker-приложения, которые слушают только 127.0.0.1. Эти Docker-приложения не отображаются на странице **Базы данных**.

## Выбор между MariaDB и MySQL {#choose-mariadb-or-mysql}

На сервере работает один MySQL-совместимый сервер баз данных: MariaDB или MySQL 8.4 LTS. Вы выбираете его при установке: на странице **Базы данных**, на карточке **Сервер баз данных** страницы **Программы** или при первоначальной настройке (**Настройка сервера**). Пока установлен один из них, панель не позволяет установить другой; позже можно [перейти](#switch-between-mariadb-and-mysql) с одного на другой вместе с базами данных.

| | MariaDB (рекомендуется) | MySQL 8.4 LTS |
|---|---|---|
| Откуда | Пакеты вашего дистрибутива или LTS-серия из собственного репозитория MariaDB (см. [Версии MariaDB](#mariadb-versions)) | Репозиторий Oracle, `repo.mysql.com` (ветка `mysql-8.4-lts`) |
| Память, примерно | Буферный пул плюс около 100 MB | Буферный пул плюс около 150 MB или плюс около 300 MB с включённой performance schema, которую панель включает начиная примерно с 3,5 GB оперативной памяти (то есть на серверах с 4 GB) |
| Поддержка | Пока её поддерживает ваш дистрибутив; серия из репозитория MariaDB — до даты окончания поддержки, которую для неё назначила MariaDB | Oracle поддерживает 8.4 LTS до 2032 года |
| Системы | Все системы, которые поддерживает Nefo | Ubuntu 22.04, 24.04 и 26.04 и Debian 12 и 13, только на amd64 (x86-64) |
| Подходит для | WordPress и большинства PHP-приложений | Приложений, которым нужна именно MySQL, или команды, привыкшей к ней |

Оба сервера работают со всем, что описано на этой странице, с резервными копиями, копиями сайтов, тестовыми копиями WordPress и PHP-приложениями из магазина приложений. Adminer и phpMyAdmin открывают оба. На сервере arm64 или в системе, для которой у Oracle нет пакетов, страница **Программы** предлагает только MariaDB и объясняет почему.

## Установка MariaDB {#install-mariadb}

1. Откройте страницу **Базы данных**.
2. Нажмите **Установить MariaDB (рекомендуется)**. MariaDB можно установить и на странице **Программы**: оставьте выбранной **MariaDB** на карточке **Сервер баз данных** и нажмите **Установить MariaDB**.
3. Подождите одну-две минуты. Журнал выполнения показывает каждый шаг.

Nefo устанавливает пакеты `mariadb-server` и `mariadb-client` из вашего дистрибутива. Затем записывает свои настройки, запускает MariaDB и удаляет анонимных пользователей и базу данных `test`, которые есть в некоторых версиях.

Чтобы вместо этого установить более новую серию из собственного репозитория MariaDB, см. [Версии MariaDB](#mariadb-versions).

### Как настраивается MariaDB {#how-mariadb-is-tuned}

Nefo записывает свои настройки в `/etc/mysql/mariadb.conf.d/90-panel.cnf`. Самая крупная настройка памяти, буферный пул InnoDB, зависит от объёма оперативной памяти сервера:

| Память сервера | `innodb_buffer_pool_size` |
|---|---|
| Меньше 1,5 GB | 128M |
| 1,5 GB и больше | 256M |
| 3 GB и больше | 512M |
| 7 GB и больше | 1G |

Остальные настройки одинаковы на всех серверах:

| Настройка | Значение | Зачем |
|---|---|---|
| `bind-address` | `127.0.0.1` | MariaDB принимает подключения только с этого сервера |
| `skip-name-resolve` | включено | Без DNS-запроса при каждом подключении |
| `performance_schema` | `OFF` | Экономит память |
| `max_connections` | `100` | |
| `character-set-server` | `utf8mb4` | Полный Юникод, включая эмодзи |
| `collation-server` | `utf8mb4_unicode_ci` | |

В итоге MariaDB занимает примерно размер буферного пула плюс 100 MB. Эту оценку показывает страница **Программы**.

::: warning
Не редактируйте `90-panel.cnf`. Панель перезаписывает этот файл.
:::

## Какие версии MariaDB можно установить? {#mariadb-versions}

По умолчанию MariaDB берётся из вашего дистрибутива. Тогда исправления безопасности приходят вместе с обновлениями системы, и никакой другой репозиторий не добавляется. Если вам нужна MariaDB новее, чем в дистрибутиве, можно вместо этого установить серию с долгосрочной поддержкой (LTS) из собственного репозитория MariaDB, `dlm.mariadb.com`:

| Серия | MariaDB поддерживает её до | Предлагается в |
|---|---|---|
| 11.4 LTS | 29 мая 2029 г. | Ubuntu 22.04 и 24.04, Debian 12 |
| 11.8 LTS | 4 июня 2028 г. | Ubuntu 22.04 и 24.04, Debian 12 |
| 12.3 LTS | 12 июня 2029 г. | Ubuntu 22.04, 24.04 и 26.04, Debian 12 и 13 |

Серия предлагается, только если она новее собственной MariaDB дистрибутива:

| Система | MariaDB дистрибутива | Предлагаемые серии |
|---|---|---|
| Ubuntu 22.04 | 10.6 | 11.4, 11.8, 12.3 |
| Ubuntu 24.04 | 10.11 | 11.4, 11.8, 12.3 |
| Debian 12 | 10.11 | 11.4, 11.8, 12.3 |
| Ubuntu 26.04 | 11.8 | 12.3 |
| Debian 13 | 11.8 | 12.3 |

MariaDB 12.3 не устанавливает Galera (кластерное ПО MariaDB, которое одному серверу не нужно); 11.4 и 11.8 устанавливают его, потому что этого требуют их пакеты.

Чтобы установить серию:

1. Откройте страницу **Программы**. На карточке **Сервер баз данных** оставьте выбранной **MariaDB**.
2. Ниже выберите версию, например **11.4 LTS от MariaDB**. По умолчанию остаётся версия вашего дистрибутива, например «10.11, версия дистрибутива».
3. Нажмите **Установить MariaDB 11.4**.

Те же версии предлагает первоначальная настройка (**Настройка сервера**) в разделе **MariaDB**, а также команда `nefo setup --db mariadb-11.4` (см. [Командная строка](./cli#nefo-setup)).

Что делает панель для серии из репозитория MariaDB:

- Скачивает ключ подписи MariaDB с `https://supplychain.mariadb.com/MariaDB-Server-GPG-KEY` (или с `keyserver.ubuntu.com`) и принимает его, только если его отпечаток в точности `177F 4010 FE56 CA33 3630 0305 F165 6F24 C74C D1D8` — это «MariaDB Signing Key», указанный в документации MariaDB. Сохраняет его как `/etc/apt/keyrings/panel-mariadb.gpg` с доверием только для этого репозитория.
- Записывает `/etc/apt/sources.list.d/panel-mariadb.list` с одной строкой только для этой серии, например `https://dlm.mariadb.com/repo/mariadb-server/11.4/repo/ubuntu noble main`. Сервер получает корректирующие выпуски 11.4 вместе с обновлениями системы, но никогда сам не переходит на более новую серию.
- Проверяет, что apt действительно установит пакеты MariaDB этой серии, затем устанавливает `mariadb-server` и `mariadb-client` с теми же настройками, что и MariaDB из дистрибутива.

При удалении MariaDB удаляются также файл репозитория и ключ.

Панель не позволяет:

- устанавливать серию, пока установлена другая MariaDB: вместо этого используйте **Обновить версию** (см. ниже);
- устанавливать MariaDB старше той, чьи данные остались в `/var/lib/mysql` от прежней установки, потому что она не сможет их прочитать. Установите эту версию или более новую либо сначала переместите каталог данных.

## Обновление MariaDB {#upgrade-mariadb}

Установленную MariaDB можно обновить до более новой LTS-серии из репозитория MariaDB, например 10.11 из дистрибутива до 11.4 или 11.8 из Debian 13 до 12.3; базы данных при этом остаются на месте.

1. Откройте страницу **Программы**. На карточке **Сервер баз данных** нажмите **Обновить версию**.
2. Выберите серию. Диалог показывает, что произойдёт и сколько свободного места на диске нужно.
3. Нажмите **Обновить до MariaDB 11.4** и следите за журналом.

Обновление идёт в таком порядке:

1. Каждая база данных экспортируется в отдельный SQL-файл, сжатый gzip, в новую папку внутри `/var/backups/panel/db-server/`. Панель хранит эти дампы, пока вы их не удалите.
2. Скачиваются пакеты новой серии, а пакеты установленной сохраняются, так что откат работает без сети.
3. MariaDB переходит в режим только для чтения, панель подсчитывает строки каждой таблицы, и MariaDB останавливается. Её каталог данных копируется в `/var/lib/mysql.before-11.4-<date>-<time>`, а `/etc/mysql` — в папку с дампами. С этого момента сайты не могут работать со своими базами данных, пока обновление не закончится; обычно это несколько минут.
4. Новые пакеты заменяют старые и запускают MariaDB на тех же данных, по-прежнему в режиме только для чтения. Затем `mariadb-upgrade` обновляет её системные таблицы.
5. Панель проверяет, что MariaDB сообщает новую версию, что в каждой базе данных те же таблицы с тем же числом строк, те же представления, хранимые процедуры, триггеры и события и что каждый пользователь базы данных панели может войти со своим паролем.
6. MariaDB снова принимает запись, а копия каталога данных удаляется.

Если сбой происходит на шаге 4 или позже, панель возвращает старую MariaDB: удаляет новые пакеты, восстанавливает `/etc/mysql` и скопированный каталог данных, снова устанавливает старые пакеты и запускает MariaDB. В конце журнала указана причина. Ваши базы данных остаются такими же, как до обновления.

::: warning Вернуться на старую серию нельзя
После обновления MariaDB обновляет свои файлы данных и системные таблицы, которые старая MariaDB прочитать не может. Панель не позволяет понизить версию, например с 11.8 до 11.4, и объясняет почему. Чтобы вернуться, экспортируйте базы данных, удалите MariaDB вместе с данными, установите старую версию и импортируйте их.
:::

Панели нужно свободное место на диске для дампов, копии каталога данных и пакетов: примерно полтора размера каталога данных плюс 400 MB. Без него обновление не начнётся. Панель также не запускает обновление, пока MariaDB остановлена или если конфигурация сервера переносит каталог данных из `/var/lib/mysql` в другое место.

## Установка MySQL {#install-mysql}

1. Откройте страницу **Базы данных** и нажмите **Установить вместо неё MySQL 8.4**. На странице **Программы** выберите **MySQL 8.4 LTS** на карточке **Сервер баз данных** и нажмите **Установить MySQL 8.4 LTS**.
2. Подождите две-четыре минуты. Журнал выполнения показывает каждый шаг.

Nefo добавляет репозиторий Oracle сам, а не через пакет Oracle `mysql-apt-config`:

- Скачивает ключ подписи с `https://repo.mysql.com/RPM-GPG-KEY-mysql-2025` и принимает его, только если его отпечаток в точности `BCA4 3417 C3B4 85DD 128E C6D4 B7B3 B788 A8D3 785C` — это ключ MySQL Release Engineering, указанный в документации MySQL. Сохраняет ключ как `/etc/apt/keyrings/panel-mysql.gpg`.
- `/etc/apt/sources.list.d/panel-mysql.list` доверяет этому ключу только для этого репозитория и подключает только ветку `mysql-8.4-lts`.
- Oracle время от времени продлевает ключ; срок действия текущей копии истекает 23 октября 2027 г. Раз в неделю панель ищет продлённую копию того же ключа и заменяет ею старую, чтобы `apt-get update` продолжал работать.

Затем панель устанавливает `mysql-community-server` и `mysql-community-client` без вопросов. У учётной записи `root` в MySQL нет пароля: она входит только через локальный сокет (`auth_socket`), от имени root на сервере, и панель не хранит пароль root. В конце панель удаляет анонимных пользователей и базу данных `test`.

### Как настраивается MySQL {#how-mysql-is-tuned}

Nefo записывает `/etc/mysql/mysql.conf.d/90-panel.cnf` до того, как пакет впервые запустит MySQL, поэтому MySQL на вашем сервере никогда не работает с настройками Oracle по умолчанию. Настройки памяти зависят от объёма оперативной памяти сервера:

| Память сервера | `innodb_buffer_pool_size` | `max_connections` | `table_open_cache` | `temptable_max_ram` |
|---|---|---|---|---|
| Меньше 1,5 GB | 128M | 75 | 400 | 32M |
| 1,5 GB и больше | 256M | 100 | 600 | 64M |
| 3 GB и больше | 512M | 150 | 1000 | 128M |
| 7 GB и больше | 1024M | 200 | 2000 | 256M |

Остальные настройки:

| Настройка | Значение | Зачем |
|---|---|---|
| `bind-address` | `127.0.0.1` | MySQL принимает подключения только с этого сервера, пока какая-нибудь база данных не разрешит удалённый доступ |
| `mysqlx` | `OFF` | Порт 33060 для X Protocol не прослушивается: PHP и панель используют классический протокол |
| `disable_log_bin` | включено | Двоичные журналы не заполняют диск: у сервера нет реплик |
| `performance_schema` | `OFF` при объёме оперативной памяти меньше примерно 3,5 GB, `ON` начиная с него (то есть на серверах с 4 GB) | Сама по себе занимает от 100 до 200 MB |
| `skip-name-resolve`, `host_cache_size` | включено, `0` | Без DNS-запроса при каждом подключении |
| `innodb_log_buffer_size` | `16M` | В MySQL 8.4 по умолчанию 64M |
| `character-set-server`, `collation-server` | `utf8mb4`, `utf8mb4_unicode_ci` | Так же, как в MariaDB, поэтому дампы переносятся между ними |

В итоге MySQL занимает примерно размер буферного пула плюс 150 MB или плюс 300 MB с включённой performance schema. Эту оценку показывает страница **Программы**, а реальное потребление — страница **Службы**.

Пользователи входят через `caching_sha2_password` — способ по умолчанию в MySQL 8.4, который поддерживают `mysqli` и PDO в PHP. `mysql_native_password` остаётся выключенным, как в поставке MySQL 8.4: он хеширует несолёным SHA-1, а в MySQL 9 его убрали. Поэтому старый хеш пароля с другого сервера (так их хранит, например, cPanel) в MySQL использовать нельзя: перенесённой базе данных нужен её пароль или новый.

В MySQL панель выполняет SQL командой `mysql` вместо `mariadb`, экспортирует через `mysqldump`, а служба называется `mysql`.

::: warning
Не редактируйте `90-panel.cnf`. Панель перезаписывает этот файл.
:::

## Можно ли перейти с MariaDB на MySQL и обратно? {#switch-between-mariadb-and-mysql}

Да, начиная с v0.24.0. На сервере работает один сервер баз данных, но MariaDB можно заменить на MySQL 8.4 LTS, а MySQL — на MariaDB вместе с базами данных, их пользователями и привилегиями.

1. Откройте страницу **Программы**. На карточке **Сервер баз данных** в блоке **Вместо этого: MySQL 8.4 LTS** (или **Вместо этого: MariaDB**) нажмите **Перейти на MySQL 8.4 LTS** (или **Перейти на MariaDB**).
2. Прочитайте диалог. В нём перечислены базы данных и учётные записи, которые будут перенесены, и то, как каждая учётная запись будет входить после перехода.
3. Для подтверждения введите `mysql` (или `mariadb`) и нажмите кнопку перехода.

При обратном переходе на MariaDB устанавливается MariaDB вашего дистрибутива. Если баз данных нет, та же задача просто заменяет один сервер другим.

### Что происходит при переходе {#what-the-switch-does}

1. Панель скачивает пакеты нового сервера и сохраняет пакеты старого на случай отката. Для ваших сайтов пока ничего не меняется.
2. Старый сервер переходит в режим только для чтения: сайты могут читать свои базы данных, но не записывать в них. Панель считывает его учётные записи и привилегии, подсчитывает строки каждой таблицы и экспортирует каждую базу данных в новую папку внутри `/var/backups/panel/db-server/`.
3. Старый сервер останавливается. Его каталог данных перемещается в `/var/lib/mysql.mariadb-<date>-<time>` (или `.mysql-…`), а `/etc/mysql` копируется в папку с дампами. Его пакеты удаляются. С этого момента сайты не могут работать со своими базами данных, пока переход не закончится.
4. Новый сервер устанавливается так же, как его устанавливает страница **Программы**, и остаётся в режиме только для чтения. Удалённый доступ и журнал медленных запросов настраиваются заново так, как были.
5. Создаются учётные записи, импортируется каждая база данных и снова выдаются привилегии. Дампы из MySQL 8 адаптируются для MariaDB так же, как при импорте сайтов: сопоставления `utf8mb4_0900_*` заменяются сопоставлениями MariaDB (`utf8mb4_unicode_520_ci`, собственным сопоставлением языка или `utf8mb4_bin`), а настройки, которые есть только в MySQL, отбрасываются. В дампах из MariaDB 11, которые идут в MySQL, сопоставления `uca1400` из MariaDB заменяются сопоставлениями MySQL (`utf8mb4_uca1400_ai_ci` становится `utf8mb4_0900_ai_ci`).
6. Панель проверяет, что в каждой базе данных те же таблицы с тем же числом строк, те же представления, хранимые процедуры, триггеры и события и что каждый пользователь базы данных панели входит со своим паролем. Затем сервер снова принимает запись, а старый каталог данных удаляется.

Если сбой происходит на шаге 3 или позже, панель удаляет новый сервер, восстанавливает конфигурацию и каталог данных старого, снова устанавливает его пакеты и запускает его: всё возвращается к исходному состоянию. Дампы сохраняются в любом случае.

Сколько займёт переход, зависит от размера баз данных: экспорт, импорт и подсчёт строк каждый раз читают все данные.

### Учётные записи и пароли {#accounts-and-passwords}

MariaDB и MySQL хранят пароли по-разному, поэтому перенести можно не каждый пароль:

| Учётная запись | После перехода |
|---|---|
| Пользователь базы данных со страницы **Базы данных** | Его пароль, который знает панель, на `localhost` и на каждом адресе, которому разрешён удалённый доступ |
| Учётная запись, которую вы создали сами, с паролем `mysql_native_password`, при переходе на MariaDB | Её пароль, по хешу |
| Учётная запись, которая входит через сокет (`unix_socket` в MariaDB, `auth_socket` в MySQL) | Снова входит через сокет |
| Любая другая учётная запись, которую вы создали сами, например учётная запись MariaDB при переходе на MySQL (MySQL 8.4 держит `mysql_native_password` выключенным) или учётная запись MySQL при переходе на MariaDB (MariaDB не умеет читать `caching_sha2_password`) | Создаётся с новым случайным паролем и блокируется. Журнал перечисляет каждую такую запись. Задайте пароль от имени root на сервере: `ALTER USER 'name'@'localhost' IDENTIFIED BY '…' ACCOUNT UNLOCK;` |

Привилегии выдаются заново по `SHOW GRANTS` старого сервера. Привилегия, которой нет у другого сервера, пропускается и указывается в журнале, как и выдача ролей и прокси-привилегий, которые панель не переносит.

### Что продолжает работать {#what-keeps-working}

- Сайты сохраняют свои настройки: они подключаются к `localhost` через тот же сокет на обоих серверах.
- phpMyAdmin и Adminer открывают новый сервер.
- Резервные копии: новые копии используют программу экспорта нового сервера, а копию, созданную до перехода, можно восстановить после него.
- Удалённый доступ остаётся открытым для тех же адресов.

### Когда панель не позволяет перейти {#when-the-panel-refuses}

Диалог перечисляет, что нужно исправить сначала, в разделе **Сначала исправьте:**, и кнопка перехода остаётся неактивной:

| Причина | Что делать |
|---|---|
| Панель не знает пароль пользователя базы данных (база данных перенесена только с хешем пароля) | Задайте новый пароль для этой базы данных на странице **Базы данных** и укажите его в настройках сайта |
| При переходе на MySQL: таблицы, которые используют собственные движки хранения MariaDB (Aria и другие), последовательности или системно-версионированные таблицы | Преобразуйте их, например с помощью `ALTER TABLE … ENGINE=InnoDB`, или удалите |
| При переходе на MySQL: столбцы `INET4`, `INET6` или `UUID` | Измените их тип, например на `VARCHAR` |
| При переходе на MySQL: представления, триггеры или хранимые процедуры, у которых имя пользователя definer длиннее 32 символов | Создайте их заново с другим definer |
| Имя базы данных начинается с дефиса | Переименуйте базу данных |
| Не хватает свободного места на диске: дампам и импортированным данным рядом со старым каталогом данных нужно примерно вдвое больше размера ваших баз данных плюс 700 MB | Освободите место; удалите старые дампы |

Переход также невозможен, пока сервер остановлен, если конфигурация сервера переносит каталог данных из `/var/lib/mysql` в другое место, и, для MySQL, там, где MySQL не предлагается (arm64 или система, для которой у Oracle нет пакетов).

Некоторые различия проявляются только при импорте данных, например индекс, который MariaDB помечает как `IGNORED`, а MySQL такого не знает. Тогда импорт завершается ошибкой, и панель возвращает старый сервер, а ошибка остаётся в журнале.

## Дампы при обновлениях и переходах {#dumps-from-upgrades-and-switches}

Карточка **Сервер баз данных** на странице **Программы** перечисляет папки в разделе **Сохранённые дампы**: когда и что (например, «MariaDB 10.11.14 → MariaDB 11.4»), чем закончилось — **Готово**, **Откат выполнен** или **Ошибка**, — сколько баз данных, их размер и папка. Каждая база данных — один файл, `001.sql.gz`, `002.sql.gz` и так далее, а `manifest.json` указывает, какой базе данных соответствует каждый файл, потому что в именах баз данных могут быть символы, недопустимые в именах файлов. Папка доступна для чтения только root.

Чтобы вернуть одну базу данных, распакуйте её файл и импортируйте его на странице **Базы данных**. Чтобы удалить папку, нажмите **Удалить эти дампы** (значок корзины рядом с ней). Пока идёт обновление или переход, панель этого не позволяет.

## Создание базы данных {#create-a-database}

1. Откройте страницу **Базы данных** и нажмите **Добавить базу данных**.
2. Введите имя в поле **База данных**. Создаётся пользователь с тем же именем, которому доступна только эта база данных.
3. Оставьте поле **Пароль** пустым, чтобы получить надёжный случайный пароль, или введите свой.
4. Необязательно: выберите сайт в поле **Сайт**. Тогда резервная копия этого сайта будет включать эту базу данных.
5. Нажмите **Создать базу данных**.

Затем появляется карточка с заголовком **Данные для подключения к** и именем базы данных, в которой указаны **База данных**, **Пользователь**, **Пароль** и **Хост**. Хост всегда `localhost`.

Правила для имён и паролей:

- Имена начинаются с буквы и содержат только `a-z`, `0-9` и `_`, не длиннее 32 символов. Зарезервированы имена `mysql`, `information_schema`, `performance_schema`, `sys`, `test`, `root`, `mariadb`, `phpmyadmin`, `debian_sys_maint`. Панель также не позволяет использовать имя, которое уже занято базой данных или пользователем базы данных в MariaDB.
- Пароли длиной от 12 до 64 символов, из букв, цифр и `! # % * + , . : = ? @ ^ _ ~ -`. Сгенерированный пароль состоит из 24 символов.

Новые базы данных используют `utf8mb4` и `utf8mb4_unicode_ci`.

### Пользователи и привилегии {#users-and-privileges}

У каждой базы данных один пользователь, `name@localhost`, со всеми привилегиями на эту базу данных и без привилегий на другие. Когда удалённый доступ включён, у этого пользователя также появляется копия для каждого разрешённого адреса (см. [Разрешение удалённого доступа](#allow-remote-access)). Кроме временного пользователя, который выполняет импорт (см. [Импорт](#import)), панель не создаёт дополнительных пользователей и не меняет привилегии. Если это нужно, используйте на сервере от имени root команду `mariadb` (`mysql` в MySQL).

В списке показаны базы данных, созданные панелью. База данных, удалённая не через панель, помечается **Не найдена в MariaDB** (или **Не найдена в MySQL**).

## Просмотр данных для входа {#show-a-database-s-login}

Нажмите **Показать данные для входа** в строке базы данных. Карточка с данными для подключения показывает имя, пользователя, пароль и хост, у каждого есть кнопка копирования. Если установлен Adminer или phpMyAdmin, на карточке также есть **Открыть в Adminer** или **Открыть в phpMyAdmin**.

## Смена пароля базы данных {#change-a-database-password}

1. Откройте меню базы данных и выберите **Новый пароль**.
2. Оставьте **Сгенерировать надёжный случайный пароль** или выберите **Использовать свой пароль** и введите его. Свой пароль подчиняется тем же правилам, что и при [создании базы данных](#create-a-database).
3. Нажмите **Новый пароль**.

Панель задаёт новый пароль и показывает его на карточке с данными для подключения. Если база данных связана с сайтом WordPress, созданным панелью, панель также записывает новый пароль в `wp-config.php` этого сайта. Другие приложения перестанут подключаться, пока вы не обновите их настройки.

Если база данных разрешает удалённый доступ, удалённые пользователи тоже получают новый пароль.

## Экспорт и импорт {#export-and-import}

### Экспорт {#export}

Откройте меню базы данных и выберите **Экспорт в .sql**. Браузер скачает обычный SQL-файл с именем вида `shop_20261126-143000.sql`.

Дамп создаётся командой `mariadb-dump --single-transaction` (`mysqldump` в MySQL, также с `--set-gtid-purged=OFF`), поэтому сайт продолжает работать во время экспорта. В дамп входят хранимые процедуры и триггеры.

### Импорт {#import}

1. Откройте меню базы данных и выберите **Импорт**.
2. Выберите файл в поле **SQL-файл (.sql или .sql.gz)**. Файл `.sql.gz` распаковывается на лету.
3. Необязательно: отметьте **Сначала очистить базу данных (удалить все её таблицы)**. Тогда перед импортом база данных удаляется и создаётся заново, а её пользователь сохраняет доступ.
4. Нажмите **Импорт**.

Один импорт может быть размером до 4 GB.

Дамп, созданный другим сервером, например резервная копия, сделанная до [перехода](#switch-between-mariadb-and-mysql), тоже импортируется: пока файл поступает, панель заменяет имена сопоставлений, которых этот сервер не знает (`utf8mb4_0900_*` из MySQL 8 в MariaDB, `uca1400` из MariaDB 11 в MySQL). В MySQL она также убирает `NO_AUTO_CREATE_USER`, который MariaDB записывает в режим SQL каждого триггера и хранимой процедуры и который MySQL 8 не принимает. Больше ничего в файле не меняется; дамп, который использует другую базу данных, по-прежнему не принимается. Восстановление резервной копии базы данных работает так же.

Импорт выполняется от имени временного пользователя MariaDB, `nefo-import-` с именем базы данных, со всеми привилегиями на эту базу данных и без привилегий на другие. Этот пользователь может также задавать definer для триггеров, представлений и хранимых процедур, поэтому дампы, в которых они есть, например собственные экспорты и резервные копии панели, импортируются как раньше. Панель удаляет этого пользователя по окончании импорта, в том числе при ошибке. Только если файл создал триггеры, представления, хранимые процедуры или события без предложения `DEFINER`, которые тогда выполняются от имени этого пользователя, панель его сохраняет: заблокированным, чтобы под ним никто не мог войти, и с привилегиями только на эту базу данных. При удалении базы данных он тоже удаляется.

В MySQL имена пользователей ограничены 32 символами, поэтому при длинном имени базы данных имя пользователя сокращается и к нему добавляется короткий хеш. Definer там разрешается привилегиями `SET_ANY_DEFINER` и `ALLOW_NONEXISTENT_DEFINER` вместо `SET USER` из MariaDB; без `SYSTEM_USER` пользователь всё равно не может заставить объект выполняться от имени root. Первая строка дампов из новых версий MariaDB, `/*M!999999\- enable the sandbox mode */`, которую клиент MySQL не принимает, в MySQL пропускается.

::: warning
Если файл использует другую базу данных, например с помощью `USE other_db`, `CREATE DATABASE other_db` или `INSERT INTO other_db.posts`, MariaDB отклоняет эту инструкцию, и импорт останавливается с сообщением, которое начинается с «SQL-файл использует другую базу данных: other_db.». То, что файл сделал до этой строки, остаётся в базе данных. Удалите из файла строки `CREATE DATABASE` и `USE` или экспортируйте базу данных заново без `--databases`, затем импортируйте её снова с отмеченным **Сначала очистить базу данных (удалить все её таблицы)**. Строки `CREATE DATABASE` и `USE` с именем этой же базы данных допустимы.
:::

## Разрешение удалённого доступа {#allow-remote-access}

По умолчанию MariaDB принимает подключения только с самого сервера. Можно разрешить выбранным адресам подключаться к одной базе данных, например инструменту отчётности на компьютере в вашем офисе.

Прежде чем начать, установите и включите брандмауэр ufw на странице **Брандмауэр и SSH**. Пока ufw не установлен, панель не позволяет включить удалённый доступ.

1. Откройте меню базы данных и выберите **Удалённый доступ**.
2. В разделе **Разрешённые адреса** введите адрес. Чтобы добавить ещё, нажмите **Добавить адрес**.
3. Нажмите **Сохранить**.

Подключайтесь с пользователем и паролем базы данных к публичному IP-адресу сервера, порт 3306.

### Разрешённые адреса {#allowed-addresses}

- Отдельные адреса IPv4 или IPv6, например `203.0.113.10` или `2001:db8::1`.
- Диапазоны IPv4 в форме CIDR, например `198.51.100.0/24`, не шире `/16`.
- Диапазоны IPv6 невозможны, потому что MariaDB не умеет их сопоставлять. Вводите отдельные адреса IPv6.
- Не больше 10 адресов на базу данных.
- Адреса loopback, `0.0.0.0` и адреса multicast не принимаются.

### Что меняет панель {#what-the-panel-changes}

| Где | Изменение |
|---|---|
| Пользователи MariaDB | Для каждого адреса — пользователь `name@address` с тем же паролем и теми же привилегиями, что у локального пользователя |
| Брандмауэр (ufw) | Для каждого адреса — правило, которое разрешает порт 3306/tcp только с этого адреса, с комментарием `MariaDB name` |
| Настройки MariaDB | `/etc/mysql/mariadb.conf.d/99-panel-remote.cnf` заставляет MariaDB слушать все интерфейсы (`0.0.0.0` или `::`, если разрешён адрес IPv6). Файл существует, только пока хотя бы одна база данных разрешает удалённый доступ |

MySQL работает так же: файл называется `/etc/mysql/mysql.conf.d/99-panel-remote.cnf`, комментарий правил — `MySQL name`, а удалённый пользователь при изменении удаляется и создаётся заново, потому что в MySQL нет `CREATE OR REPLACE USER`. В сообщениях ниже тогда стоит MySQL.

MariaDB перезапускается при первом включении удалённого доступа и ещё раз, когда он выключается для последней базы данных. Сайты теряют подключение к базе данных на несколько секунд. Если в этот момент выполняется другая задача, диалог сообщает: «Чтобы принимать удалённые подключения, MariaDB нужно перезапустить.» Когда задача закончится, нажмите **Перезапустить MariaDB**.

Если MariaDB не запускается с файлом удалённого доступа, панель удаляет этот файл и запускает MariaDB без него, чтобы ваши сайты продолжали работать.

::: warning
- Если брандмауэр выключен, порт 3306 открыт для всех. MariaDB всё равно принимает только указанные адреса.
- Подключения не шифруются, если клиент не запрашивает TLS. Для конфиденциальных данных используйте SSH-туннель или VPN.
- Указывайте только адреса, которые вы контролируете и которые не меняются.
:::

Чтобы выключить удалённый доступ, снова откройте **Удалённый доступ** и нажмите **Выключить**. При удалении базы данных удаляются также её удалённые пользователи и правила брандмауэра.

## Поиск медленных запросов {#find-slow-queries}

MariaDB может записывать в журнал каждый запрос, который выполняется дольше порогового значения. Это помогает найти, что замедляет сайт.

1. Откройте **Базы данных** → **Медленные запросы**. Вкладка появляется после установки MariaDB.
2. Задайте в поле **Медленнее чем** число секунд, от 0,1 до 60.
3. Включите переключатель **Записывать медленные запросы** и нажмите **Применить**.

Чтобы изменить эти настройки, MariaDB должна работать. Изменение применяется сразу, к подключениям, открытым после него, и сохраняется после перезапуска: панель хранит его в `/etc/mysql/mariadb.conf.d/99-panel-slowlog.cnf`, а журнал записывается в `/var/log/mysql/mariadb-slow.log`. В MySQL настройки находятся в `/etc/mysql/mysql.conf.d/99-panel-slowlog.cnf`, а журнал — `/var/log/mysql/mysql-slow.log`.

Панель ротирует журнал, чтобы он не заполнил диск, и в MariaDB, и в MySQL. Раз в час она проверяет его, и если журнал больше 50 MB или его самой старой записи 7 дней, панель переименовывает его, заставляет сервер открыть новый (`FLUSH SLOW LOGS`, без перезапуска) и сжимает старый рядом с ним, как `mariadb-slow.log-YYYYMMDD-HHMMSS.gz` (`mysql-slow.log-…` в MySQL). Она хранит 4 самых новых таких файла и удаляет более старые. Вкладка показывает, сколько их хранится сейчас. Таблица читает только текущий журнал.

Таблица показывает 200 самых новых записей, сначала новые, из последних 4 MB журнала:

| Столбец | Значение |
|---|---|
| **Время** | Когда выполнялся запрос |
| **Пользователь и хост** | Кто его выполнил, например `shop@localhost` |
| **База данных** | Какую базу данных он использовал |
| **Длительность** | Сколько он длился, в секундах |
| **Просмотрено строк** | Сколько строк прочитала MariaDB |
| **Запрос** | Сам запрос. Нажмите на него, чтобы увидеть целиком, до 2000 символов. Более длинные запросы помечены **Сокращён** |

Нажмите **Обновить**, чтобы перечитать журнал, или **Очистить журнал**, чтобы его очистить. **Очистить журнал** очищает только текущий журнал; сжатые старые журналы остаются, пока их не удалит ротация.

::: tip
Запись в журнал немного нагружает сервер. Когда закончите, выключите переключатель и нажмите **Применить**.

## Adminer {#adminer}

Adminer позволяет просматривать и редактировать базы данных в браузере, как phpMyAdmin.

### Установка Adminer {#install-adminer}

1. Сначала установите веб-сервер на странице **Программы**. Adminer работает на нём с PHP.
2. Откройте **Программы** → **Adminer (интерфейс баз данных)** и нажмите **Установить**.

Панель скачивает Adminer 6.3.1 (сборку со всеми драйверами Adminer) и перед установкой сверяет его с закреплённой контрольной суммой SHA-256. Он открывает базы данных MariaDB или MySQL, а после установки PostgreSQL — и базы данных PostgreSQL (см. [PostgreSQL в Adminer](./postgresql#postgresql-in-adminer)). Его драйвер SQLite отклоняет любой вход, потому что у SQLite нет пароля.

### Как открыть Adminer {#open-adminer}

1. Нажмите **Открыть в Adminer** вверху страницы **Базы данных** или на карточке с данными для подключения к базе данных. То же самое делает **Программы** → **Открыть Adminer**.
2. Adminer открывается в новой вкладке по адресу панели с `adminer/` на конце, например `https://203.0.113.10:28443/k3x9p2qa7m1z/adminer/`.
3. Войдите в Adminer с пользователем и паролем базы данных из **Показать данные для входа**.

### Как защищён Adminer {#how-adminer-is-protected}

Adminer доступен только через вход в панель:

- Он работает на внутреннем сайте вашего веб-сервера, который слушает только 127.0.0.1, на случайном порту от 40000 до 59999.
- Этот внутренний сайт отвечает только на запросы с секретным токеном. Остальные запросы получают `404`.
- Панель добавляет токен только к запросам из сеанса, в котором выполнен вход в панель. Без сеанса панели `adminer/` отвечает `401`, и запрос не доходит до Adminer.
- Cookie сеанса самой панели никогда не передаётся в Adminer.

Поэтому Adminer недоступен из интернета, а другие программы на сервере не могут использовать его без токена.

Adminer может импортировать файлы размером до 256 MB, а запрос может выполняться до 600 секунд. Для дампов побольше используйте **Импорт** на странице **Базы данных**.

При удалении Adminer удаляются его файлы и его внутренний сайт. Ваши базы данных не затрагиваются. При удалении веб-сервера Adminer тоже удаляется.

## phpMyAdmin {#phpmyadmin}

phpMyAdmin — второй интерфейс для баз данных, для MariaDB и MySQL. Установите тот, который вам больше нравится, или оба: общих файлов у них нет.

### Установка phpMyAdmin {#install-phpmyadmin}

1. Сначала установите веб-сервер на странице **Программы**. phpMyAdmin работает на нём с PHP.
2. Откройте **Программы** → **phpMyAdmin (интерфейс баз данных)** и нажмите **Установить**.

Панель скачивает phpMyAdmin 5.2.3 (со всеми языками) с `files.phpmyadmin.net` и сверяет его с закреплённой контрольной суммой SHA-256, прежде чем распаковать в `/usr/share/nefo-phpmyadmin`. Скрипт настройки, примеры и локальная документация не устанавливаются (ссылки справки вместо этого открывают docs.phpmyadmin.net). Временные файлы phpMyAdmin хранит в `/var/lib/nefo-phpmyadmin/tmp`.

Панель записывает `config.inc.php` для phpMyAdmin со случайным ключом шифрования cookie:

- Вы входите с пользователем и паролем базы данных и только в базу данных этого сервера. Выбрать другой сервер, войти без пароля или войти как `root` нельзя.
- phpMyAdmin не проверяет новые версии и не отправляет отчёты об ошибках.
- Его форма смены пароля скрыта. Меняйте пароль базы данных на странице **Базы данных**: она также обновляет `wp-config.php` сайта WordPress.

### Как открыть phpMyAdmin {#open-phpmyadmin}

1. Нажмите **Открыть в phpMyAdmin** вверху страницы **Базы данных**, в меню базы данных или на карточке с данными для подключения. То же самое делает **Программы** → **Открыть phpMyAdmin**.
2. phpMyAdmin открывается в новой вкладке по адресу панели с `phpmyadmin/` на конце, например `https://203.0.113.10:28443/k3x9p2qa7m1z/phpmyadmin/`.
3. Войдите с пользователем и паролем базы данных из **Показать данные для входа**.

phpMyAdmin защищён так же, как Adminer (см. [Как защищён Adminer](#how-adminer-is-protected)), на собственном внутреннем сайте с собственным секретным токеном. Без сеанса панели `phpmyadmin/` отвечает `401`, и API-ключ тоже не даёт к нему доступа. Как PHP выполняются только три точки входа phpMyAdmin, а как файлы отдаются только его скрипты, стили и изображения; на всё остальное, включая скрипт настройки, ответ — `404`. phpMyAdmin отправляет собственный заголовок Content-Security-Policy и сам проверяет токены своих форм.

Как и Adminer, phpMyAdmin может импортировать файлы размером до 256 MB, а запрос может выполняться до 600 секунд. При удалении phpMyAdmin удаляются его файлы, его внутренний сайт и его настройки. Ваши базы данных не затрагиваются. При удалении веб-сервера phpMyAdmin тоже удаляется.

## Просмотр ключей Redis {#redis-key-browser}

Когда установлен Redis, на странице **Базы данных** есть вкладка **Redis**. Чтобы установить Redis, откройте **Программы** → **Redis** → **Установить**. Как он настраивается, см. в разделе [Программное обеспечение](./software#redis).

Вкладка показывает версию Redis, сколько времени он работает, **Использовано памяти** (вместе с лимитом памяти) и число ключей (**Ключи**). Если там написано **Redis установлен, но не запущен.**, запустите Redis на странице **Службы**.

### Поиск ключей {#find-keys}

1. Выберите базу данных от 0 до 15. В списке указано, сколько ключей в каждой.
2. Введите шаблон. `*` означает что угодно, а `?` — один символ, например `user:*`.
3. Нажмите **Найти**.

Поиск идёт по ключам порциями примерно по 100. Если ключей больше, нажмите **Продолжить поиск**.

### Просмотр ключа {#view-a-key}

Нажмите на ключ, чтобы увидеть его **Тип**, **Истекает через** и **Размер**, а также значение:

| Тип | Что показывает панель |
|---|---|
| string | Первые 64 KB значения |
| list, hash, set, sorted set | Первые 200 элементов. Каждый элемент обрезается до 4 KB |
| stream и другие типы | Только тип и срок действия |

Символы двоичных значений, которые нельзя показать, заменяются.

### Удаление ключей {#delete-keys}

- Чтобы удалить один ключ, выберите его и нажмите **Удалить ключ**.
- Чтобы удалить все ключи выбранной базы данных, нажмите **Очистить базу 0** (на кнопке указан номер базы данных), введите номер для подтверждения и нажмите **Удалить все ключи**.

Сайты, которые используют Redis как кэш, заново его наполнят. Данные, которые хранились только в Redis, теряются.

Просмотрщик не меняет значения и сроки действия. Для этого используйте `redis-cli` на сервере.

Если у Redis есть пароль (`requirepass` в `/etc/redis/redis.conf`), панель читает его из этого файла и входит с ним.

## Удаление базы данных {#delete-a-database}

1. Откройте меню базы данных и выберите **Удалить**.
2. Для подтверждения введите имя базы данных и нажмите **Удалить**.

::: danger
Будут удалены база данных, все её таблицы и её пользователь. Это нельзя отменить. Вместе с ней удаляются её удалённые пользователи, правила брандмауэра и расписания автоматического резервного копирования. Уже созданные резервные копии остаются на странице **Резервные копии**.
:::

Когда вы удаляете сайт, его базы данных сохраняются, если вы не отметите **Также удалить его базы данных**: они остаются здесь, не связанные ни с каким сайтом. Восстановление резервной копии сайта снова связывает их с ним.

## Удаление MariaDB {#uninstall-mariadb}

MariaDB удаляется на странице **Программы**. Панель не позволяет это сделать, пока в MariaDB есть хоть одна база данных, кроме её собственных системных баз, включая базы данных, созданные не через панель. Что сохраняется при удалении, см. в разделе [Программное обеспечение](./software).

MariaDB из репозитория MariaDB удаляется вместе с файлом репозитория и ключом.

MySQL удаляется так же, на своей карточке, с той же проверкой. Панель также удаляет репозиторий Oracle и его ключ. Каталог данных `/var/lib/mysql` сохраняется, если вы не отметите флажок и не введёте `mysql`.

Чтобы заменить один сервер другим с сохранением баз данных, лучше выполните [переход](#switch-between-mariadb-and-mysql).

## PostgreSQL {#postgresql}

PostgreSQL работает рядом с MariaDB или MySQL, на своей вкладке **PostgreSQL** этой страницы: версия вашего дистрибутива или версии с 15 по 19 от проекта PostgreSQL, с базами данных и владельцами, импортом и экспортом, удалённым доступом через TLS, резервным копированием и обновлением основной версии. См. [PostgreSQL](./postgresql).

## Memcached {#memcached}

Когда установлен Memcached (**Программы** → **Memcached**), на странице **Базы данных** есть вкладка **Memcached**. Она показывает версию, сколько времени он работает, **Использовано памяти** вместе с лимитом, число элементов (**Элементы**), долю попаданий в кэш и открытые подключения. Также она показывает то, что сообщает сам Memcached: что он слушает только 127.0.0.1 и что UDP выключен.

**Перезапустить** очищает кэш. Как он настраивается, см. в разделе [Программное обеспечение](./software#memcached).
