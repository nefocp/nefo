# Блокировка по странам и блокировка файлов

С версии v0.24.0 у каждого сайта в Nefo есть две защиты. **Блокировка по странам** не пускает посетителей из перечисленных вами стран или, наоборот, пускает только из них; она использует бесплатные данные о странах от DB-IP и работает на Nginx, Apache и OpenLiteSpeed. Блокировка файлов делает код сайта доступным только для чтения для его собственного PHP и учётной записи SFTP, кроме папок, в которые сайт должен писать, например папки загрузок.

Обе защиты находятся в настройках сайта, в группе **Безопасность**: **Сайты** → (сайт) → **Блокировка по странам** и **Блокировка файлов**. Пока защита выключена, она ничего не стоит: ничего не скачивается, не запускается лишний процесс, в веб-сервер ничего не загружается. О брандмауэре веб-приложений, ограничениях частоты запросов и антивирусном сканере см. [Безопасность](./security#website-security).

## Как заблокировать страны на сайте? {#block-or-allow-countries}

1. Откройте **Сайты**, нажмите на сайт и откройте вкладку **Блокировка по странам**.
2. Выберите **Блокировать страны из списка ниже** или **Пускать только страны из списка ниже**.
3. Введите в поле поиска название страны (на языке панели) или её двухбуквенный код и нажмите на неё, чтобы добавить. Чтобы убрать страну, нажмите × на её метке.
4. Нажмите **Сохранить**.

Когда какой-либо сайт на сервере впервые использует блокировку по странам, Nefo перед сохранением скачивает базу данных стран с db-ip.com (около 5 MB); это занимает несколько секунд. Чтобы снова выключить блокировку, выберите **Выключено: доступ открыт из всех стран** и нажмите **Сохранить**.

Блокировка по странам работает на сайтах любого типа, включая сайты с обратным прокси. У каждого сайта своя настройка.

Заблокированные посетители получают **403 Forbidden**. Чтобы показывать вместо этого свою страницу, положите файл `403.html` в папку `public` сайта и укажите его как страницу ошибки 403 веб-сервера в **Сайты** → (сайт) → **Конфигурация Nginx** (Nginx: `error_page 403 /403.html;`; Apache: `ErrorDocument 403 /403.html`, это работает и в `.htaccess`; OpenLiteSpeed: блок `errorpage 403`). Саму страницу `/403.html` заблокированные посетители открыть могут.

### Что никогда не блокируется {#what-is-never-blocked}

- Проверки Let's Encrypt (`/.well-known/acme-challenge/`), чтобы сертификаты продолжали продлеваться.
- Вебхук развёртывания из Git (`/.panel/deploy/…`). Панель проверяет его подпись.
- `/403.html`.
- Частные и другие зарезервированные адреса (`10.0.0.0/8`, `192.168.0.0/16`, loopback и так далее).
- Запросы самого сервера, например когда WordPress обращается к себе, чтобы выполнить задачи по расписанию.

Сама панель не является сайтом: у неё свой порт, и блокировка по странам на неё никогда не действует. Чтобы ограничить, кто может открыть панель, используйте брандмауэр (см. [Безопасность](./security#firewall-ufw)).

### За Cloudflare {#behind-cloudflare}

Когда DNS-запись сайта проксируется через Cloudflare, все запросы приходят с адресов Cloudflare.

- **Nginx и Apache**: для запросов с адресов Cloudflare Nefo определяет страну по адресу посетителя, который Cloudflare передаёт в заголовке `CF-Connecting-IP`. Запросы со всех остальных адресов проверяются по их собственному адресу, поэтому клиент не может подделать заголовок. На Apache журнал доступа сайта и PHP тогда тоже видят адрес посетителя для запросов через Cloudflare.
- **OpenLiteSpeed**: для запросов с адресов Cloudflare Nefo использует страну, которую Cloudflare передаёт в заголовке `CF-IPCountry`. Включите в Cloudflare **IP Geolocation** (Геолокация IP) в настройках зоны **Network** (Сеть). Без этого посетители, которые приходят через Cloudflare, не блокируются, а с **Пускать только страны из списка ниже** — пропускаются.

Nefo хранит встроенный список адресов Cloudflare и каждый месяц обновляет его с сайта Cloudflare вместе с базой данных стран.

### Ограничения разных веб-серверов {#limits-per-web-server}

| Веб-сервер | Как это работает | Ограничение |
|---|---|---|
| Nginx | Встроенный модуль Nginx `geo`, который загружается, только пока какой-либо сайт использует блокировку по странам, и только со странами из списков сайтов | Нет. Память: около 2–5 MB на одну страну, около 40 MB для больших списков (США, Германия и Япония вместе) |
| Apache | Apache при каждом запросе по одному проверяет диапазоны адресов перечисленных стран | Не более 50 000 диапазонов адресов на сайт, поэтому крупные страны не принимаются (у одних только США около 270 000). Китай (15 000 диапазонов) занимает около 2,5 MB |
| OpenLiteSpeed | Собственный поиск GeoIP в OpenLiteSpeed по файлу базы данных DB-IP | Нет. Меньше 1 MB |

В списке может быть до 100 стран. На Apache вкладка показывает, сколько диапазонов адресов сайт использует из допустимого числа. Если список слишком большой, Apache его не принимает, а сообщение называет страны, которые не помещаются, начиная с самых крупных, и число их диапазонов. Уберите их или используйте Nginx или OpenLiteSpeed, которые справляются с любой страной.

### Данные о странах {#the-country-data}

Данные — это бесплатная база DB-IP **IP to Country Lite**, IP Geolocation by [DB-IP](https://db-ip.com), под лицензией Creative Commons Attribution 4.0. Она охватывает IPv4 и IPv6.

- Nefo скачивает её по HTTPS, когда какой-либо сайт впервые использует блокировку по странам.
- Прежде чем заменить старую копию, Nefo проверяет, что файл — полная база данных: его формат, размер и то, что в нём больше 200 стран.
- Nefo обновляет её раз в месяц (DB-IP публикует новый выпуск в начале каждого месяца). Вкладка показывает используемый выпуск.
- Пока ни один сайт не использует блокировку по странам, ничего не скачивается и веб-сервер ничего не загружает.

База данных хранится в `/var/lib/panel-geoip/`. Её могут читать все пользователи, потому что её читает веб-сервер: это общедоступные данные.

## Как сделать файлы сайта доступными только для чтения? {#lock-a-website-s-files}

Вкладка **Блокировка файлов** делает код сайта доступным только для чтения для его PHP, его приложения и его учётной записи SFTP. Тогда плагин с уязвимостью больше не может изменять файлы сайта или добавлять новые, кроме как в разрешённых вами папках, например в папках загрузок и кэша. В других панелях это называется защитой от изменений.

1. Откройте **Сайты**, нажмите на сайт и откройте вкладку **Блокировка файлов**.
2. Проверьте список **Папки с правом записи**. Для сайтов на WordPress, Joomla, Laravel, Drupal, Nextcloud, OpenCart, Moodle, Symfony и CodeIgniter панель сама заполняет папки приложения; **Использовать папки для WordPress** (или для приложения сайта) возвращает их. Пишите по одной папке на строку, относительно папки сайта, например `public/wp-content/uploads`. `*` означает имя одной папки: `public/sites/*/files`. `tmp` и `logs` всегда остаются доступными для записи.
3. Чтобы узнавать, если PHP-файлы всё-таки изменятся, отметьте **Оповещать при изменении PHP-файлов** (см. [ниже](#alerts-when-php-files-change)).
4. Нажмите **Заблокировать файлы**.

После этого вкладка показывает **Заблокированы с** и дату. Чтобы позже изменить папки с правом записи или оповещение, отредактируйте их и нажмите **Сохранить**: файлы снова блокируются с новым списком. **Разблокировать файлы** возвращает всё пользователю сайта — ровно с тем владельцем, группой и правами, которые были у каждого файла раньше.

Вкладки **Блокировка файлов** нет у Docker-приложений, файлы которых принадлежат их контейнерам, и у сайтов с обратным прокси, которые не отдают файлов.

Готовые наборы папок:

| Приложение | Папки с правом записи |
|---|---|
| WordPress | `public/wp-content/uploads`, `public/wp-content/cache`, `public/wp-content/upgrade` |
| Joomla | `public/images`, `public/media`, `public/cache`, `public/administrator/cache`, `public/administrator/logs`, `public/tmp` |
| Laravel | `storage`, `bootstrap/cache` |
| Drupal | `public/sites/*/files` |
| Nextcloud | `data`, `public/config` |
| OpenCart | `storage`, `public/image/cache`, `public/image/catalog` |
| Moodle | `moodledata` |
| Symfony | `var` |
| CodeIgniter | `writable` |

Папка с правом записи, которой ещё нет, создаётся для пользователя сайта при блокировке файлов, если существует папка уровнем выше. Вкладка перечисляет папки, которые не удалось найти.

### Что меняется, пока файлы заблокированы {#what-changes-while-the-files-are-locked}

- PHP сайта, его приложение и его учётная запись SFTP не могут ничего менять, добавлять, переименовывать или удалять за пределами папок с правом записи и не могут менять там права. Загрузки и кэши продолжают работать.
- WordPress не может обновляться сам, устанавливать и обновлять плагины и темы из своей консоли, переписывать `wp-config.php` или `.htaccess`. Обновляйте его вместо этого на вкладке **WordPress** (см. ниже).
- Сайт продолжает работать: веб-сервер и PHP по-прежнему читают все файлы, которые могли читать раньше. Файлы, которые мог читать только пользователь сайта, например `wp-config.php` (режим `0600`), остаются недоступными для чтения веб-серверу.

Как это устроено: файлы и папки, которыми владел пользователь сайта, теперь принадлежат root, без права записи для кого-либо ещё. Файлы, которые могла читать группа сайта, сохраняют эту группу. Файлы, которые мог читать только их владелец, получают собственную группу блокировки сайта (`panel-lock-<uid>`, единственный участник которой — пользователь сайта). Никакого модуля ядра, никакого `chattr`. Всё, что изменила блокировка, записывается в `/var/lib/nefo/filelock/`, поэтому разблокировка восстанавливает это в точности, даже после сбоя.

### Операции панели на заблокированном сайте {#panel-operations-on-a-locked-website}

| Операция | Пока файлы заблокированы |
|---|---|
| Вкладка **WordPress**: **Обновить всё**, режим обслуживания, режим отладки, автоматические обновления | Панель разблокирует файлы, вносит изменение и снова блокирует их |
| Перенос тестовой копии на этот сайт | Файлы разблокируются на время переноса, затем снова блокируются |
| **Развёртывание из Git** (вручную или из вебхука) | Файлы разблокируются на время развёртывания, затем снова блокируются |
| Восстановление резервной копии этого сайта (или папки в нём) | Файлы разблокируются на время восстановления, затем снова блокируются |
| Проверка на вирусы: перемещение файла в карантин или его восстановление | Файлы разблокируются на это время, затем снова блокируются |
| Установка зависимостей приложения (Node.js, Python) | Файлы разблокируются на это время, затем снова блокируются |
| **Файлы** (файловый менеджер): редактирование, загрузка, создание, переименование, удаление, распаковка, смена прав | Разрешено в папках с правом записи и в `tmp`, `logs`; в остальных местах запрещено с сообщением, что файлы сайта заблокированы |
| Установка приложения (WordPress или другого) на сайт | Запрещено: сначала разблокируйте файлы |
| Импорт сайта в этот (пустой) сайт | Запрещено: сначала разблокируйте файлы |
| Клонирование сайта, его тестовая копия, резервные копии | Работают: они только читают файлы, в том числе те, которые мог читать только сайт (например, `wp-config.php`). Копия принадлежит своему сайту и не блокируется |

После переноса, развёртывания или восстановления новые файлы оказываются под блокировкой, как и остальные; файлы, которые попадают в папку с правом записи, остаются у сайта. Каждая операция, которая разблокирует файлы, записывает в журнал своей задачи «Unlocking the files of example.com for this change» (Разблокировка файлов example.com) и «Locking the files of example.com again» (Повторная блокировка файлов example.com). Если повторная блокировка не удалась, задача сообщает об этом, и панель пробует снова каждый час. Пока операция выполняется, вкладка показывает, что файлы разблокированы для неё.

::: warning
Блокировка останавливает собственного пользователя сайта, но не root. Всё, что работает от имени root, например сеанс SSH под root или терминал панели, по-прежнему может изменять файлы. Перед удалением панели выполните `nefo unlock-files` (см. [Удаление](./uninstall#unlock-the-websites-files)), иначе файлы заблокированных сайтов останутся во владении root.
:::

### Оповещения при изменении PHP-файлов {#alerts-when-php-files-change}

С **Оповещать при изменении PHP-файлов** панель при блокировке файлов делает снимок (контрольную сумму SHA-256 каждого PHP-файла сайта, включая папки с правом записи) и раз в день сравнивает с ним PHP-файлы. Если файлы изменились, добавились (PHP-файл в `uploads` — классический признак взлома) или удалились, панель отправляет оповещение по каналам из **Настройки** → **Оповещения**, а вкладка перечисляет эти файлы. Повторно она оповещает, только когда меняется список различий.

Если изменения внесли вы сами, нажмите **Сделать новый снимок**. Операции, которые разблокируют и снова блокируют файлы, например обновление WordPress, делают новый снимок сами.

Ежедневная проверка читает не более 200 000 PHP-файлов или 2 GB на сайт. Вкладка сообщает, если проверка остановилась на этом ограничении.
