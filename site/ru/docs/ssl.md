# SSL-сертификаты

Nefo в один клик получает для каждого сайта бесплатный сертификат Let's Encrypt и сама его продлевает. Она также умеет получать wildcard-сертификаты через Cloudflare DNS, устанавливать уже имеющийся у вас сертификат, перенаправлять HTTP на HTTPS и отправлять HSTS. Перед каждым запросом Nefo проверяет, что все имена ведут на сервер, поэтому неудачные попытки не расходуют лимиты Let's Encrypt.

На этой странице описаны требования, перенаправление на HTTPS и HSTS, wildcard-сертификаты через Cloudflare DNS, установка уже имеющегося сертификата, выключение HTTPS и что делать, если сертификат не удаётся получить.

## Перед началом {#before-you-start}

Для обычного сертификата Let's Encrypt проверяет по простому HTTP, что каждое имя сайта ведёт на ваш сервер. Проверку должно пройти каждое имя: домен и каждое из его [дополнительных доменных имён](./websites#domains-and-aliases).

- **DNS:** у каждого имени есть A-запись, указывающая на IP-адрес этого сервера, например `203.0.113.10`. Если у имени есть ещё и запись AAAA (IPv6), она тоже должна указывать на этот сервер или быть удалена.
- **Порт 80:** сервер отвечает из интернета на порту 80. Nefo открывает порты 80 и 443 в ufw при установке веб-сервера. Если у вашего хостинг-провайдера есть собственный брандмауэр, откройте порт 80 и там.
- **Прокси:** если ваш DNS находится в Cloudflare и прокси включён (оранжевое облако), сначала прочитайте раздел [Прокси Cloudflare](#cloudflare-proxy-orange-cloud).

Включая HTTPS, вы принимаете [Subscriber Agreement](https://letsencrypt.org/repository/) (соглашение подписчика) Let's Encrypt.

## Получение бесплатного сертификата {#get-a-free-certificate}

1. Откройте **Сайты**, затем вкладку сайта **SSL / HTTPS**. В списке сайтов ту же вкладку открывает кнопка **Включить HTTPS** в столбце **SSL**.
2. В разделе **Бесплатный сертификат от Let's Encrypt** оставьте пункт **Проверка через DNS (Cloudflare)** неотмеченным.
3. Нажмите **Получить сертификат**.

Журнал показывает шаги: Nefo проверяет, что каждое имя ведёт на этот сервер, запрашивает сертификат у Let's Encrypt, проходит проверку каждого имени и включает HTTPS в веб-сервере. В конце выводится «Done. The certificate is valid until» (Готово. Сертификат действителен до) и дата.

Когда сайт получает первый сертификат, Nefo также переводит установленный ею сайт на WordPress на адрес `https://` и перезапускает Docker-приложение с адресом `https://`. Файлы хранятся в `/var/lib/nefo/certs/example.com/` как `fullchain.pem` и `privkey.pem`.

### Проверка перед запросом {#the-check-before-the-request}

Прежде чем обратиться к Let's Encrypt, Nefo кладёт на сервер тестовый файл и скачивает его через каждое имя по HTTP. Если какое-то имя не проходит, Nefo вообще не отправляет запрос, поэтому неудачные попытки не расходуют лимиты Let's Encrypt. Тогда журнал сообщает «these names do not reach this server yet, so no certificate was requested:» (эти имена пока не ведут на этот сервер, поэтому сертификат не запрошен:) и выводит по строке на каждое имя:

| Сообщение | Что исправить |
|---|---|
| `blog.example.com: no DNS record. Add an A record that points to this server's IP address.` | Добавьте A-запись и дождитесь, пока она станет видна. |
| `example.com (203.0.113.10): no answer over HTTP on port 80 (…). Check the DNS record and the firewall.` | Откройте порт 80 в брандмауэре провайдера и проверьте, что веб-сервер работает. |
| `example.com (198.51.100.7) answered HTTP 404, but not from this server. Check that the DNS record points here.` | Имя указывает на другой сервер: старый IP-адрес, запись AAAA, ведущая в другое место, или прокси, например Cloudflare. |

Адреса в круглых скобках — это то, во что разрешается имя. Сравните их с IP-адресом вашего сервера.

## Перенаправление с HTTP на HTTPS {#redirect-http-to-https}

Когда у сайта появился сертификат, включите **Перенаправлять HTTP на HTTPS** на вкладке **SSL / HTTPS** или на вкладке **Обзор**. Тогда каждый адрес `http://` отвечает постоянным перенаправлением (301) на `https://`. Проверка Let's Encrypt и вебхуки Git по-прежнему работают по HTTP.

Чтобы браузеры использовали HTTPS ещё до перенаправления, включите также [HSTS](#hsts).

## HSTS {#hsts}

HSTS (заголовок `Strict-Transport-Security`) велит браузерам открывать сайт только по `https://`, даже если кто-то вводит `http://` или переходит по старой ссылке. Включите **HSTS (заголовок Strict-Transport-Security)** на вкладке **SSL / HTTPS**. Для этого нужны сертификат и **Перенаправлять HTTP на HTTPS**; выключение перенаправления выключает и HSTS.

После этого Nefo отправляет `Strict-Transport-Security: max-age=15552000` (180 дней, около 6 месяцев) с HTTPS-ответами сайта в Nginx, Apache и OpenLiteSpeed. Отметьте **Включая поддомены**, чтобы добавить `includeSubDomains`: тогда браузеры используют HTTPS и для каждого поддомена домена, поэтому отмечайте этот пункт, только если HTTPS есть у всех поддоменов. Nefo никогда не добавляет `preload`: выйти из списка предзагрузки браузеров трудно, поэтому, если это вообще нужно, подавайте домен туда сами.

::: warning
Браузер, получивший заголовок, отказывается открывать сайт по простому HTTP в течение 6 месяцев после последнего посещения, даже если вы потом выключите HSTS или HTTPS. Включайте HSTS только для сайта, который останется на HTTPS.
:::

В Nginx заголовок задаётся для всего блока `server` сайта. Если ваши собственные директивы (см. [Сайты](./websites#rewrite-rules-and-your-own-directives)) добавляют `location` со своим `add_header`, Nginx в этом location отбрасывает заголовки сайта: повторите там `add_header Strict-Transport-Security "max-age=15552000" always;`.

Для проверки выполните `curl -sI https://example.com/ | grep -i strict-transport`.

## Автоматическое продление {#automatic-renewal}

Nefo проверяет сертификаты при запуске и затем каждый час. Сертификат Let's Encrypt продлевается, когда остаётся треть его срока действия: за 30 дней до окончания для 90-дневного сертификата. Вам ничего не нужно делать, а сертификат приостановленного сайта тоже продолжает продлеваться.

Если продление не удаётся, Nefo повторяет попытку каждые 12 часов. Тем временем:

- список сайтов показывает «Ошибка продления» в столбце **SSL**;
- вкладка **SSL / HTTPS** показывает «Последняя попытка получить сертификат не удалась.» вместе с ошибкой;
- отправляется оповещение, если вы настроили оповещения о неудачных продлениях: см. [Почта и оповещения](./mail-alerts).

Собственный сертификат панели из **Настройки** → **Сертификат** (см. [Безопасность](./security#https-from-the-first-start)) продлевается так же: за треть срока до окончания и повторно каждые 12 часов после неудачи. Неудачное продление записывается в журнал действий и отправляет то же оповещение.

Nefo регистрирует свою учётную запись Let's Encrypt без адреса электронной почты, поэтому Let's Encrypt не пишет вам об истекающих сертификатах. Полагайтесь на оповещения панели.

Чтобы продлить сертификат вручную, например после устранения проблемы, нажмите **Продлить сертификат** на вкладке **SSL / HTTPS**.

## Wildcard-сертификаты через Cloudflare DNS {#wildcard-certificates-through-cloudflare-dns}

Wildcard-имя, например `*.example.com`, можно проверить только через DNS. Nefo делает это через API Cloudflare, поэтому DNS домена должен находиться в Cloudflare. Проверка через DNS работает и для сайта, который пока недоступен по HTTP, например за прокси Cloudflare. Для сертификата Nefo только добавляет и удаляет TXT-записи `_acme-challenge`.

### Создание API-токена Cloudflare {#create-a-cloudflare-api-token}

Тот же токен используется и на [странице DNS](./dns). Его права перечислены в одном месте, в разделе [API-токен](./dns#the-api-token): сертификатам нужно только Zone → DNS → Edit; странице DNS могут пригодиться также Zone → Zone → Read и Zone → Cache Purge → Purge.

1. В панели управления Cloudflare откройте **My Profile → API Tokens → Create Token** (Мой профиль → API-токены → Создать токен).
2. Используйте шаблон **Edit zone DNS** (Изменение DNS зоны). Он даёт право Zone → DNS → Edit.
3. В ресурсах зоны укажите зоны (домены), которые вы используете на этом сервере.
4. Создайте токен и скопируйте его.

См. руководство Cloudflare по [созданию API-токена](https://developers.cloudflare.com/fundamentals/api/get-started/create-token/).

### Сохранение токена в Nefo {#save-the-token-in-nefo}

1. Откройте **Настройки**, затем вкладку **Cloudflare**.
2. Вставьте токен в поле **API-токен** и нажмите **Проверить и сохранить**.

Nefo проверяет, что Cloudflare принимает токен и что он активен, затем показывает «Токен сохранён» с последними символами токена и **Зоны**, которые он может использовать. Чтобы сменить токен, нажмите **Заменить API-токен**, чтобы удалить — **Удалить**.

### Получение сертификата {#get-the-certificate}

1. Для wildcard-сертификата откройте вкладку сайта **Домены**, добавьте `*.example.com` в **Дополнительные доменные имена** и нажмите **Сохранить**.
2. На вкладке **SSL / HTTPS** отметьте **Проверка через DNS (Cloudflare)**. Для сайта с wildcard-именем этот пункт отмечен и не меняется: «Обязательно: у этого сайта wildcard-имя (*.domain).»
3. Нажмите **Получить сертификат**.

Nefo добавляет TXT-запись `_acme-challenge.example.com`, до 3 минут ждёт, пока DNS-серверы Cloudflare начнут её отдавать, проходит проверку и удаляет запись. Сайт запоминает этот выбор, поэтому его продления тоже используют проверку через DNS.

Сертификат охватывает имена; посетителям по-прежнему нужны DNS-записи, которые направляют поддомены на этот сервер.

## Собственный сертификат {#use-your-own-certificate}

Устанавливайте собственный сертификат, если вы купили его у другого поставщика, или для сертификата Cloudflare Origin.

1. Откройте вкладку сайта **SSL / HTTPS** и перейдите к разделу **Свой сертификат**.
2. Вставьте **Сертификат (PEM, с промежуточными)**: сертификат, за которым следует его цепочка. Можно также выбрать файл `.pem`, `.crt`, `.cer` или `.txt`.
3. Вставьте **Закрытый ключ (PEM, без шифрования)** или выберите файл `.pem`, `.key` или `.txt`.
4. Нажмите **Установить**.

Nefo проверяет файлы, прежде чем что-либо менять, и не принимает:

- файл, который не является сертификатом PEM или больше 64 KB;
- закрытый ключ, защищённый парольной фразой. Сначала снимите её, например командой `openssl pkey -in key.pem -out plain.pem`;
- ключ, который не соответствует сертификату;
- сертификат, который ещё не действителен или уже истёк;
- сертификат, который не охватывает все имена сайта. Wildcard-имя сайта должно быть указано в сертификате в точности.

Сертификат устанавливается с предупреждением («Установлен, но с предупреждениями:»), если браузеры сами по себе не будут ему доверять (это ожидаемо для сертификата Cloudflare Origin за прокси Cloudflare) или если он истекает в течение двух недель.

Nefo не продлевает ваш собственный сертификат. В последние две недели его срока вкладка **SSL / HTTPS** сообщает «Nefo не продлевает сертификат, установленный вами. Установите новый до» и дату, а **Требует внимания** на панели мониторинга перечисляет этот сайт. Кроме того, Nefo напоминает об этом раз в день: журнал действий записывает это как неудачное продление, и отправляется оповещение о неудачных продлениях. Вовремя установите новый сертификат или вернитесь к Let's Encrypt кнопкой **Получить сертификат**. В списке сайтов такие сайты помечены «свой».

## Выключение HTTPS {#turn-off-https}

Чтобы вернуть сайт на простой HTTP, нажмите **Выключить HTTPS** внизу его вкладки **SSL / HTTPS** и подтвердите. После этого Nefo:

- отдаёт сайт только по `http://`: HTTPS-часть конфигурации веб-сервера удаляется;
- выключает **Перенаправлять HTTP на HTTPS** и [HSTS](#hsts);
- удаляет файлы сертификата в `/var/lib/nefo/certs/example.com/`, от Let's Encrypt или ваши собственные, поэтому ничего не продлевается и напоминаний не будет. Учётная запись Let's Encrypt остаётся для других сайтов;
- переводит установленный ею сайт на WordPress обратно на адрес `http://` и перезапускает Docker-приложение с адресом `http://`.

Посетители, которые открывают адрес сайта с `https://` (из закладки, результатов поиска или по ссылке), получат ошибку браузера, потому что у сервера больше нет сертификата для этого имени. Если у сайта был HSTS, браузеры, получившие заголовок, продолжают отказываться от простого HTTP до 6 месяцев, поэтому у таких посетителей сайт вообще не откроется, пока у него снова не будет HTTPS. Новый сертификат можно получить в любое время кнопкой **Получить сертификат**.

Чтобы заменить сертификат, выключать HTTPS не нужно: получите новый сертификат Let's Encrypt или установите свой поверх старого. При удалении сайта удаляется и его сертификат: см. [Сайты](./websites). При удалении веб-сервера сертификаты сохраняются.

## Если сертификат не выдаётся {#when-a-certificate-fails}

Ошибка показывается на вкладке сайта **SSL / HTTPS** под сообщением «Последняя попытка получить сертификат не удалась.» и в журнале попытки.

### DNS или порт 80 {#dns-or-port-80}

См. [проверку перед запросом](#the-check-before-the-request). Чаще всего причина в DNS-записи, которая ещё не указывает на этот сервер, или в порте 80, закрытом в брандмауэре провайдера.

### Прокси Cloudflare (оранжевое облако) {#cloudflare-proxy-orange-cloud}

Когда прокси Cloudflare включён, домен разрешается в адреса Cloudflare, и запросы попадают в Cloudflare раньше, чем на ваш сервер. Тогда настройки Cloudflare, например **Always Use HTTPS** (Всегда использовать HTTPS; это перенаправление на HTTPS в разделе **SSL/TLS → Edge Certificates**, «SSL/TLS → Пограничные сертификаты»), могут не дать проверке дойти до сервера без изменений, и Nefo сообщает, что имя «answered HTTP …, but not from this server» (ответило HTTP …, но не с этого сервера). См. также [Let's Encrypt за оранжевым облаком](./dns#let-s-encrypt-behind-the-orange-cloud). Есть три выхода:

- отметьте **Проверка через DNS (Cloudflare)** и получите сертификат через DNS. Прокси может оставаться включённым, а продления работают так же;
- установите сертификат Cloudflare Origin как [собственный сертификат](#use-your-own-certificate);
- выключите прокси для этого имени (DNS only, серое облако). Продления тоже проверяются по HTTP, поэтому оставьте его выключенным.

### Записи CAA {#caa-records}

Если у вашего домена в DNS есть записи CAA, одна из них должна разрешать `letsencrypt.org`. Иначе Let's Encrypt откажет в сертификате, а журнал покажет его ошибку с упоминанием CAA. См. [Let's Encrypt и CAA](https://letsencrypt.org/docs/caa/).

### Лимиты запросов {#rate-limits}

Let's Encrypt ограничивает, сколько сертификатов и неудачных проверок может быть у домена и учётной записи. Когда вы упираетесь в лимит, журнал показывает сообщение Let's Encrypt со временем ожидания. См. [лимиты запросов Let's Encrypt](https://letsencrypt.org/docs/rate-limits/).

::: tip
Чтобы тестировать, не расходуя лимиты, добавьте `"acme_directory": "https://acme-staging-v02.api.letsencrypt.org/directory"` в `/etc/nefo/config.json` и перезапустите панель командой `systemctl restart nefo`. Тестовым (staging) сертификатам браузеры не доверяют. Чтобы получать настоящие сертификаты, удалите эту строку и снова перезапустите панель.
:::

### Проверка через DNS в Cloudflare {#dns-validation-through-cloudflare}

| Сообщение | Что исправить |
|---|---|
| `DNS validation needs a Cloudflare API token: add one in Settings → Cloudflare` | Сохраните токен на странице **Настройки**, вкладка **Cloudflare**. |
| `Cloudflare did not accept this token.` | Токен неверный, истёк или неактивен. Создайте новый. |
| `none of the Cloudflare zones this API token can use holds example.com` | Добавьте зону домена в ресурсы зоны токена в Cloudflare. |
| `the DNS record _acme-challenge.example.com did not appear on … in time` | DNS-серверы Cloudflare ответили слишком медленно. Повторите попытку через несколько минут. |
