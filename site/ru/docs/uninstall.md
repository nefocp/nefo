# Удаление

У Nefo нет команды удаления: её удаляют вручную, от имени root, за несколько шагов. Разблокируйте заблокированные сайты командой `nefo unlock-files`, остановите и удалите службу `nefo` и `/usr/local/bin/nefo`, закройте порт панели и удалите `/etc/nefo` и `/var/lib/nefo`. Ваши сайты, базы данных и программы продолжают работать, если вы не удалите их заранее.

На этой странице показан каждый шаг. Здесь также объясняется, что остаётся на сервере, потому что удаление панели не удаляет сайты и программы, которые вы с её помощью настроили.

## Что остаётся после удаления Nefo {#what-stays-when-you-remove-nefo}

Шаги на этой странице удаляют саму панель: её программу, службу, конфигурацию и данные. Всё, что вы настроили через панель, остаётся и продолжает работать:

- веб-сервер, PHP, MariaDB, Redis, Docker и другие компоненты со страницы **Программы**;
- ваши сайты в `/var/www`, их пользователи Linux и их базы данных;
- задания cron, фоновые программы, сайты-приложения и контейнеры Docker;
- резервные копии, которые хранятся на сервере в `/var/backups/panel`.

Без панели никто не продлевает сертификаты ваших сайтов и не запускает резервное копирование по расписанию. Сертификаты сайтов хранятся в папке данных Nefo, `/var/lib/nefo/certs`. Если удалить эту папку, пока сайты ещё используют HTTPS, веб-сервер не сможет загрузить их сертификаты.

Поэтому сначала решите:

- **Чтобы удалить всё**, сначала удалите сайты и программы в панели (шаг 2), затем удалите Nefo.
- **Чтобы сайты продолжали работать** без панели, пропустите шаг 2 и сохраните `/var/lib/nefo/certs` при удалении данных (шаг 7). Сертификаты Let's Encrypt действуют не больше 90 дней, поэтому заранее настройте другой способ их продления, пока срок их действия не истёк.

## 1. Сохраните копии того, что вам нужно {#_1-keep-copies-of-what-you-need}

1. На странице **Резервные копии** кнопкой **Создать копию сейчас** создайте свежую резервную копию каждого сайта и каждой базы данных, которые хотите сохранить.
2. Скопируйте резервные копии за пределы сервера. Они находятся в `/var/backups/panel`, а также в удалённом хранилище, если вы его настроили.

## 2. Удалите сайты и программы в панели {#_2-remove-websites-and-software-in-the-panel}

Сделайте это, пока панель ещё работает. Панель не позволяет удалить компонент, пока его что-то использует, поэтому действуйте в таком порядке:

1. **Сайты:** откройте каждый сайт и на его вкладке **Обзор** нажмите **Удалить**. Отметьте **Также удалить его базы данных**, если они вам не нужны. Снимите отметку **Сначала создать резервную копию сайта**, если вы уже сохранили копию (шаг 1). Это удаляет файлы сайта, его пользователя Linux и его сертификат.
2. **Базы данных:** удалите оставшиеся базы данных.
3. **Docker:** удалите созданные вами контейнеры и проекты Compose.
4. **Задания cron** и **Фоновые программы:** удалите те, что вы создали.
5. **Программы:** нажмите **Удалить** у каждого компонента, который больше не нужен, например у Docker, MariaDB, Redis и веб-сервера. У MariaDB и Docker папка данных (`/var/lib/mysql` у MariaDB, `/var/lib/docker` у Docker) сохраняется, если вы не отметите поле, чтобы удалить и её.

Последняя версия PHP остаётся, потому что она нужна настройке веб-сервера. Если она вам не нужна, удалите её через apt после удаления Nefo.

## 3. Запишите порт панели {#_3-note-the-panel-s-port}

Порт понадобится, чтобы потом закрыть его в брандмауэре:

```sh
nefo info --port
```

## 4. Разблокируйте файлы сайтов {#unlock-the-websites-files}

Если вы заблокировали файлы некоторых сайтов (**Сайты** → (сайт) → **Блокировка файлов**, см. [Блокировка по странам и блокировка файлов](./website-protection#lock-a-website-s-files)), то, пока они заблокированы, их файлы принадлежат root. Верните их сайтам до удаления панели, иначе они так и останутся у root:

```sh
systemctl stop nefo
nefo unlock-files
```

Команда перечисляет каждый разблокированный сайт:

```
Unlocked the files of example.com
Unlocked the files of blog.example.com
```

Каждый файл и каждая папка получают ровно тех владельца, группу и права, которые были у них в момент блокировки. Файлы, которые root тем временем положил в сайт, остаются у root. Команда также удаляет группы блокировки сайтов (`panel-lock-<uid>`). Она читает записи в `/var/lib/nefo/filelock`, поэтому запустите её до удаления данных панели (шаг 7). Повторный запуск ничего не делает: команда выводит `No website's files are locked.`

## 5. Остановите и удалите службу и программу {#_5-stop-and-remove-the-service-and-the-program}

```sh
systemctl disable --now nefo
rm /etc/systemd/system/nefo.service
systemctl daemon-reload
rm /usr/local/bin/nefo
```

## 6. Закройте порт панели {#_6-close-the-panel-s-port}

Если ufw включён, удалите правила для порта панели. Установщик добавил их с комментарием `Nefo`.

1. Выведите список правил с номерами:

   ```sh
   ufw status numbered
   ```

2. Удалите правило для порта панели по его номеру, например:

   ```sh
   ufw delete 3
   ```

3. Обычно у ufw есть второе правило для IPv6, помеченное `(v6)`. После каждого удаления номера меняются, поэтому снова выведите список правил и удалите и его.

Если вместо ufw вы используете firewalld (порт 28443 для примера):

```sh
firewall-cmd --permanent --remove-port=28443/tcp
firewall-cmd --reload
```

Также удалите порт из облачного брандмауэра провайдера.

## 7. Удалите конфигурацию и данные {#_7-delete-the-configuration-and-the-data}

::: danger Это нельзя отменить
Это удаляет учётную запись панели, её настройки, список сайтов, расписания резервного копирования, журнал действий, собственный сертификат панели и сертификаты ваших сайтов. Убедитесь, что вы сохранили всё нужное (шаг 1).
:::

Чтобы удалить всё:

```sh
rm -rf /etc/nefo /var/lib/nefo
```

Если ваши сайты остаются (см. выше), сохраните их сертификаты и удалите остальное:

```sh
rm -rf /etc/nefo
find /var/lib/nefo -mindepth 1 -maxdepth 1 ! -name certs -exec rm -rf {} +
```

## 8. Необязательно: удалите то, что Nefo оставила в других местах {#_8-optional-remove-what-nefo-left-elsewhere}

Пока вы ею пользовались, Nefo создавала файлы и за пределами своих папок. Удаляйте только то, что вам больше не нужно:

| Путь | Что это |
|---|---|
| `/var/backups/panel` | Резервные копии, которые хранятся на этом сервере |
| `/etc/cron.d/panel` и `/var/log/panel-cron` | Задания cron, созданные в панели, и их журналы. Задания продолжают выполняться, пока вы не удалите файл. |
| `/var/lib/panel-trash` | Файлы, удалённые в файловом менеджере; хранятся 30 дней |
| `/var/lib/panel-quarantine` | Файлы, которые антивирусный сканер убрал в карантин |
| `/var/lib/panel-geoip` | База данных стран для блокировки по странам |
| `/var/backups/nefo-postgresql` | Дампы, сделанные перед обновлением PostgreSQL |
| `/var/lib/panel-acme` | Папка, которая отвечает на проверки Let's Encrypt. Удаляйте её, только когда ни один веб-сервер её больше не использует. |
| `/etc/ssh/sshd_config.d/99-panel-sftp.conf` | Правила SSH для учётных записей сайтов и SFTP |
| `/etc/fail2ban/jail.d/panel.conf` и `/etc/fail2ban/filter.d/panel.conf` | Правила fail2ban для SSH и панели, если вы установили fail2ban из панели |
| `/etc/ssh/sshd_config.d/00-panel.conf` | Настройки SSH, которые вы сохранили в панели |

::: warning Настройки SSH
Если вы меняли порт SSH или выключали вход по паролю в панели, эти настройки находятся в `/etc/ssh/sshd_config.d/00-panel.conf`. Удаление файла изменит способ входа по SSH после перезапуска SSH. Оставьте файл, если не уверены, что хотите вернуть настройки по умолчанию, и проверьте новый сеанс SSH, прежде чем закрывать текущий.
:::
