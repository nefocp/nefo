# WordPress 工具箱

Nefo 的 WordPress 工具箱会显示每个 WordPress 网站的版本和待安装的更新，并在备份数据库之后一键更新 WordPress、插件和主题。它还可以切换维护模式、调试模式和自动更新，重置管理员密码，以及制作可以推送回正式网站的预发布副本。

它适用于 Nefo 安装的 WordPress 网站：从 [应用商店](./apps) 安装的、用空 PHP 网站的 **安装 WordPress** 按钮安装的，或作为预发布副本创建的。你自己上传的 WordPress 不会出现。服务器上有 WordPress 网站后，左侧菜单中会出现 **WordPress** 项。

工具箱使用 wp-cli。Nefo 在第一次使用时从 wp-cli 的最新发布版本下载它，并对照该发布版本公布的 SHA-512 校验和进行检查。**软件** → **工具** 会显示它的版本并可以更新它（见 [软件](./software#tools)）。wp-cli 以每个网站自己的 Linux 用户、用网站的 PHP 版本运行，并且不加载插件或主题，所以损坏的插件不会碍事。

## 安装 WordPress {#install-wordpress}

两种方式：

- **应用商店**：把 WordPress 或 WooCommerce 安装到一个空的 PHP 网站中。见 [应用商店](./apps)。
- **从空的 PHP 网站安装**：打开网站的 **概览** 标签页，点击 **安装 WordPress**。填写 **网站标题**、**管理员用户名**（避免用 `admin`：这是攻击者最先尝试的名字）、**管理员邮箱** 和 **管理员密码**，密码也可以留空，以获得一个高强度密码。你输入的密码需要 12 到 128 个字符，与应用商店相同。点击 **安装 WordPress**。

WordPress 需要 MariaDB 或 MySQL：请先在 **数据库** 页面安装（见 [数据库](./databases)）。请在安装之前开启 HTTPS，这样 WordPress 一开始就使用 `https://` 地址；如果之后再开启，Nefo 会替你把 WordPress 切换过去。登录信息出现时请保存好：密码不会再次显示。

## 网站列表 {#the-site-list}

在左侧菜单中打开 **WordPress**。表格为每个网站显示：

| 列 | 显示内容 |
|---|---|
| **网站** | 域名和 PHP 版本。点击它会打开网站的 **WordPress** 标签页。 |
| **版本** | WordPress 版本；有更新版本时显示“WordPress … 可用”，否则显示“已是最新”。 |
| **插件和主题** | 共有多少个，其中多少个有更新。**显示 … 个可用更新** 会列出它们。 |
| **模式** | 开启时显示 **维护**、**调试** 和 **自动更新**。 |

打开页面时，Nefo 会检查每个网站。顶部的 **重新检查** 会再次检查所有网站；网站菜单中的同名项只检查该网站。如果某个网站无法检查（例如它的数据库宕机了），该行会显示“无法检查网站：”及原因。

每行末尾的菜单包含下面的操作。同样的操作和开关也在每个网站的 **WordPress** 标签页上，那里还有 **WP Admin**。

## 更新 WordPress、插件和主题 {#update-wordpress-plugins-and-themes}

1. 在网站所在的行，或在网站的 **WordPress** 标签页上，点击 **全部更新**。
2. 确认：“备份 example.com 的数据库，然后更新 WordPress、所有插件和所有主题？”

更新在后台运行，并带有日志：

1. Nefo 把数据库导出到 `/var/www/example.com/tmp/panel-wp-backup-YYYYMMDD-HHMMSS.sql`。只有网站用户能读取这个文件，也无法从网上访问它。Nefo 保留最新的三个这样的文件。如果备份失败，什么都不会更新。
2. 它更新 WordPress 及其数据库，然后更新每个插件和每个主题。
3. 原来处于维护模式的网站会保持维护模式。

如果有些插件或主题无法更新，日志会说明原因，并给出数据库备份的名称。对于 [文件被锁定](./website-protection#lock-a-website-s-files) 的网站，工具箱会在更新、维护模式、调试模式和自动更新时解锁文件，完成后重新锁定。文件锁定期间，WordPress 自己无法更新任何东西：请在这里更新。要回退，从 **文件** 下载备份，并在 **数据库** 页面导入它：见 [数据库](./databases)。如果还需要文件的完整副本，请使用 [备份](./backups)。

## 维护模式 {#maintenance-mode}

选择 **开启维护模式**，或在网站的 **WordPress** 标签页上打开 **维护模式** 开关。访客会看到 WordPress 的维护页面（HTTP 503）。它会一直保持，直到你在面板中用 **关闭维护模式** 关闭它。

维护模式是 WordPress 自己的页面。如果想在 Web 服务器层面关闭整个网站，请暂停它：见 [网站](./websites)。

## 调试模式 {#debug-mode}

选择 **开启调试模式**，或打开 **调试模式** 开关。Nefo 会在 `wp-config.php` 中设置 `WP_DEBUG` 和 `WP_DEBUG_LOG`，并保持 `WP_DEBUG_DISPLAY` 关闭，所以错误会写入日志，永远不会显示给访客：

- Web 请求的错误写入 `/var/www/example.com/logs/php-error.log`：打开网站的 **日志** 标签页，选择 **PHP 错误**；
- wp-cli 运行时的错误写入 `/var/www/example.com/logs/wp-debug.log`：在 **文件** 中打开它。

完成后用 **关闭调试模式** 关闭它。

## 自动更新 {#automatic-updates}

**开启自动更新** 让 WordPress 自己更新一切：WordPress（包括主版本）、每个插件和每个主题。

**关闭自动更新** 让 WordPress 恢复默认设置：它仍会安装 WordPress 自身的安全版本和次版本，插件和主题则不会自动更新。

这个设置作用于开启时已安装的插件和主题。对于之后添加的插件和主题，请关闭后再重新开启。

## 重置管理员密码 {#reset-an-administrator-password}

1. 选择 **重置管理员密码**。
2. 在 **管理员** 下选择账户。列表显示具有管理员角色的用户。
3. 选择 **生成强密码**，或 **输入密码**（12 到 128 个字符）。
4. 点击 **设置密码**。

Nefo 只显示一次新密码，旁边有 **登录** 按钮。该账户会在所有设备上退出登录。

## 制作预发布副本 {#make-a-staging-copy}

预发布副本是第二个网站，里面有网站的一份副本，你可以在上面尝试修改，而不影响正式网站。复制期间正式网站会继续运行。

1. 选择 **克隆到预发布环境**。
2. 检查 **预发布网站的域名**。除非你修改，否则它是 `staging.example.com`。
3. 点击 **创建预发布副本**。
4. 把预发布域名的 DNS 指向这台服务器，然后在它的 **SSL / HTTPS** 标签页上开启 HTTPS。

副本会得到：

- 一个使用相同 PHP 版本的新 PHP 网站，有它自己的 Linux 用户；
- 一个新数据库，包含内容的副本；
- `public` 中文件的副本，其中 `wp-config.php` 指向新数据库。缓存插件文件（`object-cache.php`、`advanced-cache.php`）和符号链接会被略过；
- 数据库中所有地方的网站地址都替换为新地址；
- 请求搜索引擎不要收录它；
- 与正式网站相同的重写规则。

预发布网站一开始使用 `http://`，没有证书。如果任何一步失败，Nefo 会移除它为副本创建的一切。

以下情况 Nefo 会拒绝制作副本：

- MariaDB 没有运行；
- 预发布域名已被某个网站使用，或者它的文件夹已存在于 `/var/www` 中；
- `wp-config.php` 不在网站的 `public` 文件夹中；
- `wp-config.php` 中的 `DB_NAME` 不是加引号的普通值，或者数据库名称使用了小写字母、数字和 `_` 以外的字符；
- 网站的数据库在另一台服务器上；
- 网站是多站点网络。

::: tip
预发布网站的 DNS 指向服务器后，任何人都可以打开它。要保持私密，请在它的 **阻止访问** 标签页上用密码保护它：见 [网站](./websites)。
:::

## 把预发布副本推送到正式网站 {#push-the-staging-copy-to-the-live-site}

你在预发布副本上尝试的修改准备好后，可以把它们复制回正式网站。Nefo 会记住每个预发布副本是从哪个网站制作的。Nefo 有这个按钮之前制作的副本，以及网站的 [克隆](./websites#clone-a-website)，都没有关联到正式网站，无法推送。

1. 在预发布网站所在的行选择 **推送到正式网站**，或在它的 **WordPress** 标签页上点击 **推送到正式网站**。网站列表会在预发布网站下方显示“example.com 的预发布副本”。
2. 选择要推送的内容：
   - **文件和数据库**；
   - **仅文件（主题、插件、上传）**：正式网站保留它的文章、页面、订单和设置；
   - **仅数据库（文章、页面、设置）**：正式网站保留它的文件。
3. 输入正式网站的域名进行确认，然后点击 **推送到正式网站**。

推送作为一个任务运行，有它自己的日志：

1. Nefo 备份正式网站的文件和数据库。备份在 [备份](./backups) 页面上。如果备份失败，什么都不会推送。
2. 正式网站显示它的维护页面。如果它之前就处于维护模式，推送之后仍保持维护模式。
3. **文件**：预发布网站 `public` 文件夹中的文件替换正式网站的文件，并属于正式网站的 Linux 用户。预发布副本中没有的文件会从正式网站上删除；大小和日期相同的文件保持不动。正式网站保留它自己的 `wp-config.php`、缓存插件文件（`object-cache.php`、`advanced-cache.php`）和符号链接。在 `.user.ini` 和 `wordfence-waf.php` 中，预发布文件夹会被替换为正式网站的文件夹。
4. **数据库**：正式网站的数据库被清空，换成预发布数据库的副本。然后 Nefo 会撤销预发布副本所做的改动：所有地方的预发布地址（`http://` 和 `https://`，包括 JSON 形式）和预发布文件夹都替换为正式网站的，正式网站也恢复它自己的地址和搜索引擎设置。对象缓存会被清空，WordPress 会在下一次访问时重新生成重写规则。
5. 维护模式关闭，即使某一步失败也会关闭。

::: warning
推送会替换正式网站。制作预发布副本之后正式网站上新增的内容会丢失：推送数据库时会丢失订单、评论和新用户，推送文件时会丢失上传的文件。如果推送后正式网站无法正常工作，请在 **备份** 页面恢复第 1 步的备份。
:::

以下情况 Nefo 会拒绝推送：

- 该网站不是预发布副本，或者它的正式网站已被删除；
- 你推送数据库，而 MariaDB 没有运行、正式网站的数据库不在 **数据库** 页面上、两个网站使用同一个数据库、它们的表前缀（`$table_prefix`）不同，或者上面列表中的某个原因适用于任一 `wp-config.php`。

`wp-config.php` 中的设置永远不会被推送：请自己在正式网站上修改。

## 删除预发布副本 {#delete-a-staging-copy}

要删除预发布副本，删除它的网站并勾选 **同时删除它的数据库**：见 [删除网站](./websites#delete-a-website)。删除预发布副本不会改动它的正式网站。

删除正式网站会保留它的预发布副本，但该副本无法再推送：删除对话框会显示“这是预发布副本 … 的正式网站。”
