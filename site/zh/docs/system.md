# 系统工具

**仪表盘** 显示服务器实时的 CPU、内存、磁盘和负载，以及 7 天的历史，并列出需要注意的事项。Nefo 的服务器工具还可以管理定时任务、systemd 服务、必须持续运行的后台程序、进程和监听端口、SSH 登录，提供浏览器中的 root 终端，并可以重启面板或服务器。

本页介绍这些工具，以及在哪里找到日志。它们大多位于左侧菜单的 **服务器** 分组中。操作系统更新、交换空间、时区和主机名、TCP BBR 以及磁盘清理在 [系统](./os) 页面上。

## 仪表盘 {#dashboard}

登录后会打开 **仪表盘**。

- 页面顶部显示服务器的名称、操作系统、运行时间、CPU 数量和内存。在容器形式的 VPS（LXC）上，内存是容器的上限，并标有“容器限制”（见 [容器形式的 VPS](./first-steps#a-vps-that-is-a-container)）。那里的按钮可以 **检查更新**、打开 **终端**，以及使用 **电源** 菜单。
- 四个仪表显示实时的 **系统负载**、CPU、**内存** 和 **磁盘 /**。它们每 5 秒刷新一次。系统负载是 1 分钟平均负载除以 CPU 数量。
- 卡片统计网站、数据库、SFTP 账户、定时任务、备份和安全风险的数量。点击卡片会打开相应页面。没有未解决的严重问题时，**安全风险** 卡片显示 [安全检查](./security-check) 上次运行的时间。
- **资源历史** 绘制 CPU、内存、磁盘、负载或网络的图表，时间范围为 1 小时、24 小时或 7 天。图表下方是 **当前**、**平均** 和 **最高** 值。对于网络，它显示 **入站** 和 **出站** 速率，以及该时间范围内的总量。
- **需要注意** 列出需要你处理的问题，最严重的排在前面。
- **已安装的软件** 显示主要组件及其状态。

面板每分钟记录一次负载，并保留 7 天的历史。全新安装后，几分钟后才会出现图表。左侧菜单底部也会显示当前的 CPU 和内存占用。

### “需要注意”会检查什么 {#what-needs-attention-checks}

- 双因素登录已关闭。
- root 可以用密码通过 SSH 登录。
- 防火墙已关闭。
- 某个网站的证书无法续期、已过期，或在 14 天内过期。
- 某个网站在 7 天内到期。
- 某个计划备份失败。
- 磁盘已用到 90% 或以上。
- 有操作系统的安全更新等待安装（见 [更新](./os#updates)）。
- 服务器需要重启才能完成更新的安装。
- 上一次 [安全检查](./security-check) 发现了严重问题或警告。
- 某个受监控的网站宕机了（见 [监控](./websites#monitoring)）。

右上角的铃铛（**通知**）显示同样的列表。两者都只在你登录时可见。如果想改为通过 Telegram、邮件、Discord、Slack 或 Webhook 接收消息，请设置 [告警](./mail-alerts)。

## 定时任务 {#cron-jobs}

定时任务按计划运行命令。在左侧菜单中前往 **定时任务**。

### 添加定时任务 {#add-a-cron-job}

1. 点击 **添加定时任务**。
2. 输入 **名称**，最多 100 个字符。
3. 选择 **运行身份**：root，或某个网站的用户（显示其域名）。网站的任务请用网站自己的用户运行，root 只用于服务器任务。
4. 设置 **计划**。选择一个常用计划（**每 5 分钟**、**每小时**、**每天 03:00**、**每周日 04:00**、**服务器启动时**），或者自己输入。字段下方，面板会用文字描述这个计划。
5. 输入 **命令**：一行 shell 命令，最多 2000 个字符，用 `/bin/sh` 运行。
6. 保持 **启用** 开启，然后点击 **保存**。

对于有 PHP 的网站用户，**使用 WordPress 定时命令** 链接会填入 WordPress 的 cron，例如 `php8.3 /var/www/example.com/public/wp-cron.php`，每 5 分钟运行一次。

### 计划的语法 {#schedule-syntax}

计划有五个字段，使用服务器时间：

| 字段 | 取值 |
|---|---|
| 分钟 | 0–59 |
| 小时 | 0–23 |
| 日 | 1–31 |
| 月 | 1–12 |
| 星期 | 0–7（0 和 7 都是星期日） |

在每个字段中，用 `*` 表示每个值，用 `1,15` 这样的列表、`1-5` 这样的范围，或 `*/10` 这样的步长。也可以用以下写法之一代替五个字段：`@hourly`、`@daily`（或 `@midnight`）、`@weekly`、`@monthly`、`@yearly`（或 `@annually`）和 `@reboot`。面板会拒绝超出范围的数字，例如第 60 分钟。

| 计划 | 运行时间 |
|---|---|
| `*/5 * * * *` | 每 5 分钟 |
| `0 3 * * *` | 每天 03:00 |
| `30 2 * * 1` | 每周一 02:30 |
| `0 0 1 * *` | 每月 1 日午夜 |

### 定时任务如何运行 {#how-cron-jobs-run}

- 面板把任务写入 `/etc/cron.d/panel`，所以即使面板停止，系统的 cron 也会运行它们。不要编辑这个文件：面板会重写它。
- 命令的输出和错误会追加到任务的日志 `/var/log/panel-cron/<id>.log` 中，该日志属于任务的用户。
- 命令中的 `%` 按输入的原样工作：面板会为 cron 转义它。
- 任务的用户不再存在时（例如删除网站之后），任务就不再运行。

### 运行、检查和修改任务 {#run-check-and-change-a-job}

- **开启** 列中的开关可以开启或关闭任务。关闭的任务会留在列表中。
- **立即运行** 以任务的用户身份立即运行它，并实时显示输出。一小时后会停止。
- 行的 ⋯ 菜单中的 **日志** 显示任务日志的末尾。超过 5 MB 的日志会截取为最后的 1 MB。
- **编辑** 和 **删除** 也在同一个菜单中。删除任务也会删除它的日志。

在列表上方，可以显示 **全部** 任务，或只显示 **已开启** 或 **已关闭** 的任务，还可以按名称、命令或用户搜索。

## 服务 {#services}

**服务** 列出 Nefo 管理的系统服务（如果已安装）：

| 服务 | systemd 单元 |
|---|---|
| Nefo | `nefo` |
| Nginx、Apache 或 OpenLiteSpeed | `nginx`、`apache2`、`lshttpd` |
| PHP-FPM，每个已安装的版本一个 | 例如 `php8.3-fpm` |
| MariaDB 或 MySQL | `mariadb` 或 `mysql` |
| PostgreSQL | 例如 `postgresql@16-main` |
| Redis | `redis-server` |
| Memcached | `memcached` |
| fail2ban | `fail2ban` |
| SSH | `ssh` |
| Cron | `cron` |
| 防火墙（ufw） | `ufw` |

其他服务（例如 Docker 或 Postfix）不会列出。每行显示状态（**运行中**、**已停止**、**失败**……）、服务已运行多长时间、适用时显示“开机不自动启动”，以及内存占用。

可用的操作取决于服务：

| 服务 | 操作 |
|---|---|
| Web 服务器、PHP-FPM | **启动**、**停止**、**重启**、**重新加载** |
| Nefo | **重启** |
| SSH | **重启**、**重新加载** |
| 其他 | **启动**、**停止**、**重启** |

- **停止** 会请你确认，因为需要该服务的网站会停止工作。
- 在重启或重新加载 Web 服务器之前，面板会测试它的配置。如果测试失败，什么都不会重启，并显示错误。
- 不能从面板停止 SSH，这样你不会把自己锁在外面。
- 重启 Nefo 会在几秒钟后重新加载页面。
- **日志** 显示该服务日志（journal）的最后 150 行。

面板不会更改服务是否开机启动。

## 后台程序 {#background-programs}

后台程序是必须持续运行的命令，例如队列工作进程。面板以 systemd 服务的形式、以某个网站的 Linux 用户身份运行每个后台程序，并在它停止时重新启动它。你需要先有至少一个网站。

### 添加程序 {#add-a-program}

1. 前往 **后台程序**，点击 **添加程序**。
2. 输入 **名称**，最多 60 个字符。
3. 选择 **网站**。程序以这个网站的 Linux 用户身份运行，从不以 root 运行。
4. 可选：设置 **工作文件夹**：网站文件夹中的某个文件夹，例如 `app`。留空则使用网站文件夹本身。
5. 输入 **命令**：一个程序及其参数，写在一行上，最多 1000 个字符。
6. 可选：添加 **环境变量**：每行一个 `NAME=value`，最多 20 个。在服务器上，只有 root 能读取它们。
7. 保持 **立即启动，并在服务器启动时启动** 开启，然后点击 **创建**。

对于 PHP 网站，**使用 Laravel 队列工作进程** 链接会用网站的 PHP 版本填入 `php8.3 artisan queue:work --sleep=3 --tries=3 --max-time=3600`。

### 后台程序如何运行 {#how-background-programs-run}

- 每个程序都是一个名为 `panel-daemon-<id>.service` 的 systemd 服务。
- 它退出时，无论什么原因，systemd 都会在 3 秒后重新启动它。
- 开机时，它在 MariaDB 和 Redis 之后启动。
- 它在 systemd 的保护下运行：`/usr`、`/boot` 和 `/etc` 是只读的，`/home` 和 `/root` 被隐藏，它有自己的 `/tmp`。
- 工作文件夹必须存在，并且必须位于网站文件夹内，经过符号链接也一样。
- 它的输出写入系统日志（journal）。

### 控制程序 {#control-a-program}

每行显示状态（运行中、正在重启、失败、正在停止或已停止）、重启了多少次，以及内存占用。

- 行上会显示一个按钮：**启动**（程序已停止时）或 **重启**（程序正在运行时）。其他操作（包括 **停止**）在行的 ⋯ 菜单中。**停止** 会让程序保持停止状态，重启服务器后也一样，直到你再次启动它。
- **日志** 显示程序最后写出的 200 行。
- **编辑** 可以修改程序。**保存** 会用新设置重启它。
- **删除** 会停止并移除它。

删除网站时，它的后台程序也会被停止并移除。

## 进程和端口 {#processes-and-ports}

**进程** 显示服务器上正在运行的东西，分为三个标签页：**进程**、**端口** 和 **SSH 登录**。

### 进程 {#processes}

列表显示最繁忙的进程，最多 300 个。点击列标题可以按 PID、CPU % 或内存排序，还可以按名称、用户或 PID 筛选。**每 5 秒刷新** 让列表保持最新。

CPU % 是在最近几秒内测得的：100% 表示一个 CPU 核心一直满负荷工作。

要停止进程，点击它所在行末尾的停止按钮，然后：

- **停止** 请程序结束并退出（TERM 信号）。设计良好的程序会先保存数据。
- **强制停止** 立即结束它（KILL 信号）。只在 **停止** 不起作用时使用：未保存的数据会丢失。

由 systemd 运行的服务可能会被 systemd 再次启动。面板不能停止系统的 init 进程（PID 1）、面板自身、启动面板的进程，或内核线程。每次停止都会记录在活动日志中。

### 端口 {#ports}

**端口** 列出程序监听的 TCP 和 UDP 端口，显示 **地址**、**程序** 以及 **可访问范围**：**仅本服务器** 或 **网络**。

对网络开放的端口，仍然可以由防火墙对外关闭。见 [防火墙](./security#firewall-ufw)。

## SSH 登录 {#ssh-sign-ins}

**进程** → **SSH 登录** 按从新到旧列出过去 30 天内的 SSH 登录和失败的尝试，最多 200 条。每行显示时间、结果（**已登录**、**密码错误** 或 **未知用户**）、用户、IP 地址和方式，例如 `publickey` 或 `password`。

可以显示 **全部**、**仅成功** 或 **仅失败**。列表读取自 SSH 服务的日志（journal）。

大量失败的尝试通常意味着有人在猜密码。请关闭密码登录，或安装 fail2ban 封禁这些地址。见 [安全](./security#brute-force-protection-fail2ban)。

## 终端 {#terminal}

**终端** 在你的浏览器中打开服务器上的 root shell（bash）。

::: warning
终端就像一个 root 的 SSH 会话：每条命令都以完全权限运行，一条错误的命令可能删除数据或让服务器停止。面板无法撤销你在那里运行的东西。
:::

- 离开页面，或 30 分钟没有输入后，会话结束。点击 **重新连接** 打开一个新会话。
- 最多可以同时打开 4 个终端，容器终端也计算在内。
- 活动日志会记录终端何时打开、何时关闭，以及持续了多长时间。它不记录命令。

## 日志 {#logs}

Nefo 没有统一的日志页面。每个日志都显示在它所属的东西旁边：

| 日志 | 位置 |
|---|---|
| 网站的访问日志、错误日志、PHP 错误和应用日志 | **网站** → 你的网站 → **日志** |
| 网站的防火墙事件 | **网站** → 你的网站 → **Web 防火墙（WAF）** |
| 定时任务的输出 | **定时任务** → **日志** |
| 服务的日志（journal） | **服务** → **日志** |
| 后台程序的输出 | **后台程序** → **日志** |
| 容器和 Compose 项目 | **Docker** |
| 在面板中做了什么 | **账户** → **最近活动** |
| 面板自己的服务日志 | 在服务器上运行 `journalctl -u nefo` |

网站的访问日志、错误日志和 PHP 日志显示最后 300 行。在日志窗口中点击 **刷新** 可以加载新的行。

## 重启面板或服务器 {#restart-the-panel-or-reboot-the-server}

前往 **设置** → **面板** → **电源**。**仪表盘** 的 **电源** 菜单中也有同样的操作。

- **重启面板** 只重启面板。网站、数据库和其他服务会继续运行，面板几秒钟后就会恢复。
- **重启服务器** 会重启整台服务器。在它恢复之前，网站和数据库都无法访问，通常需要一到两分钟。输入服务器的名称进行确认。

两种情况下，面板重新响应时页面都会自动重新加载。有后台任务（例如安装或备份）正在运行时，两者都会被拒绝：请等它完成。两者都会记录在活动日志中。

在服务器上，也可以这样重启面板：

```sh
systemctl restart nefo
```
