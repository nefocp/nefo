# Docker

Nefo 从你的发行版安装 Docker，在 **Docker** 页面管理容器、Compose 项目和镜像，每个容器都可以打开终端。它只在 127.0.0.1 上发布容器端口，所以你要通过网站访问它们；它还会拒绝会削弱服务器安全的 Compose 项目，例如特权容器或对互联网开放的端口。

本页介绍每个标签页、面板对 Compose 项目做的安全检查、应用商店中的 Docker 应用如何融入其中，以及如何通过网站公开一个容器。

## 安装 Docker {#install-docker}

前往 **软件** → **Docker**，点击 **安装**。面板会从你的发行版安装 `docker.io`，有 Compose 插件时一并安装。安装 Docker 后，菜单中会出现 **Docker** 项。

如果之后缺少 Compose 插件，面板会在你第一次启动 Compose 项目时安装它。

卸载 Docker 见 [软件](./software#when-an-uninstall-is-refused)。还有容器、Compose 项目或 Docker 应用时，卸载会被拒绝。

## 为什么端口只开在 127.0.0.1 上 {#why-ports-stay-on-127-0-0-1}

Docker 发布的端口会绕过 ufw 防火墙：在所有地址上发布的容器会对互联网开放，不管 ufw 怎么设置。所以面板会：

- 只在 `127.0.0.1` 上发布它启动的容器；
- 拒绝在其他任何地址上发布端口的 Compose 项目。

要公开一个容器，请在它前面放一个网站。见 [把容器放到网站上](#put-a-container-on-a-website)。

## 容器 {#containers}

**容器** 标签页列出服务器上的每个容器，无论是否在运行，并显示它的镜像、状态和端口。Compose 项目和应用商店应用的容器也会出现在这里。

每个容器所在的行都有 **启动** 或 **停止** 按钮，其他操作在它的菜单中：

| 操作 | 作用 |
|---|---|
| **启动** / **停止** | 启动或停止容器 |
| **终端** | 在容器内打开 shell。只适用于正在运行的容器 |
| **重启** | 重启容器 |
| **日志** | 显示它最后 200 行输出，带时间戳 |
| **删除** | 移除容器，即使它正在运行 |

::: warning
**删除** 会丢失容器的数据，除非数据保存在卷中。
:::

### 运行容器 {#run-a-container}

1. 在 **容器** 标签页上，点击 **运行容器**。
2. 填写：
   - **镜像**，例如 `nginx:alpine`；
   - **容器名称**，例如 `my-app`；
   - **本服务器上的端口**（1024 到 65535）和 **容器内的端口**，如果容器要对外提供服务；
   - **环境变量（每行一个 NAME=value）**，例如 `TZ=UTC`。
3. 点击 **启动**。

面板会按需下载镜像，并以重启策略 `unless-stopped` 启动容器，所以重启服务器后它会自动恢复。端口只在 `127.0.0.1` 上发布。

### 容器中的终端 {#terminal-in-a-container}

点击 **终端**，可以在正在运行的容器内打开 shell。镜像中有 `bash` 时面板使用它，否则使用 `sh`。关闭窗口或 30 分钟没有输入后，会话结束。

## Compose 项目 {#compose-projects}

Compose 项目是一个同时运行多个容器的 `compose.yaml`。面板把每个项目保存在 `/var/lib/panel-compose/<name>/compose.yaml` 中，只有 root 能读取，并以 Compose 项目 `panel-<name>` 的名义运行它。

### 创建项目 {#create-a-project}

1. 前往 **Docker** → **Compose**，点击 **新建项目**。
2. 输入 **项目名称**：小写字母、数字和短横线，最多 40 个字符。容器的名称为 `panel-<name>-<service>-1`。
3. 在 `compose.yaml` 字段中编写文件。**插入示例** 会填入一个可以运行的小例子。
4. 点击 **创建并启动**。

面板会检查文件、保存它并启动容器，同时拉取需要的镜像。文件中的相对路径（例如 `./data:/data`）指的是项目的文件夹。

一个最小的项目：

```yaml
services:
  web:
    image: traefik/whoami
    restart: unless-stopped
    ports:
      - "127.0.0.1:8081:80"
```

`compose.yaml` 最大 64 KB。

### 编辑项目 {#edit-a-project}

打开项目的菜单，点击 **编辑**。修改文件后点击 **保存并应用**。面板会检查新文件、保存它，并重新创建配置有变化的容器。你从文件中删除的服务，其容器也会被移除。

### 项目操作 {#project-actions}

| 操作 | 作用 |
|---|---|
| **启动** | 检查文件并启动容器 |
| **停止** | 停止容器 |
| **重启** | 重启容器 |
| **更新镜像** | 检查文件，拉取更新的镜像并重新创建容器 |
| **移除容器** | 停止并移除容器。卷和 `compose.yaml` 会保留 |
| **日志** | 每个容器的最后 200 行 |
| **删除** | 移除容器、网络，以及包含 `compose.yaml` 的项目文件夹。勾选 **同时删除它的卷（其中的数据会丢失）** 可以同时删除卷。镜像会保留 |

### 安全检查 {#safety-checks}

在保存项目之前，以及每次启动和更新之前，面板都会向 Compose 获取最终配置（include、extends 和变量都已解析）。它会拒绝会削弱服务器安全的项目：

| 拒绝的内容 | 原因 |
|---|---|
| `privileged: true` | 特权容器可以完全控制服务器 |
| `network_mode`、`pid`、`ipc`、`userns_mode` 或 `cgroup` 设为 `host` | 容器会共享服务器自己的命名空间 |
| 任何 `cap_add` | 额外的容器权限 |
| 任何 `devices` 或 `device_cgroup_rules` | 把宿主机设备交给容器 |
| `no-new-privileges` 以外的 `security_opt` | `seccomp=unconfined` 或 `apparmor=unconfined` 这类选项会削弱对容器的限制 |
| 任何 `sysctls` | 内核设置 |
| 主机地址不是 `127.0.0.1` 或 `::1` 的端口（例如 `"8080:80"`），或没有发布端口号的端口 | Docker 会在所有地址上监听，绕过防火墙 |
| 绑定挂载 `/etc`、`/root`、`/boot`、`/proc`、`/sys`、`/dev`，或其中的任何内容 | 系统文件夹会让容器控制服务器 |
| 绑定挂载 Docker 套接字 `/var/run/docker.sock` 或 `/run/docker.sock`，或包含它的文件夹，例如 `/`、`/var`、`/var/run` 或 `/run` | 这个套接字会让容器控制 Docker，进而控制服务器 |
| `device` 选项是上述路径的命名卷，以及从上述路径读取的 secrets 或 configs | 同样的文件夹，只是换了一种挂载方式 |

路径会按写法检查，也会在跟随符号链接后检查。`/etc/localtime` 和 `/etc/timezone` 可以只读挂载（`:ro`），这样容器可以使用服务器的时区。

检查失败时，编辑器会显示哪个服务的哪项设置被拒绝。不会保存或启动任何东西。

## 镜像 {#images}

**镜像** 标签页列出本地镜像，以及它们的大小、创建日期和使用它们的容器（**使用者**）。

- **移除** 删除一个镜像。如果有容器在使用它，面板会列出这些容器，并再次询问后才强行移除。
- **移除未使用的镜像** 删除所有没有容器使用的镜像。需要时会重新下载。

没有单独的拉取按钮。镜像会在你运行容器、启动 Compose 项目或点击 **更新镜像** 时下载。

## 应用商店中的 Docker 应用 {#docker-apps-from-the-app-store}

[应用商店](./apps) 可以安装 Ghost、Uptime Kuma、n8n 和 Gitea 等 Docker 应用。它们以 Compose 项目运行，由面板根据每个应用的配方写出：

- 它们的文件和数据在 `/var/lib/panel-apps/<name>` 中，Compose 项目名为 `panelapp-<name>`。它们不会出现在 **Compose** 标签页上，但它们的容器会出现在 **容器** 标签页上。
- 它们和你自己的项目一样要经过安全检查。
- 每个 Docker 应用都有自己的网站。PostgreSQL、MongoDB 和 Ollama 等服务类应用没有网站，只监听 `127.0.0.1`。

在 **应用商店** → **已安装** 中管理这些应用，在那里启动、停止、更新和备份它们。移除它们见 [应用商店](./apps)，它们的备份见 [备份](./backups#app-backups)。

## 把容器放到网站上 {#put-a-container-on-a-website}

网站可以把访客转发到容器在 `127.0.0.1` 上的端口。这时 Web 服务器充当反向代理，你还可以给网站加上 SSL 证书。

1. 在 `127.0.0.1` 上发布容器的端口，例如在 `compose.yaml` 中写 `127.0.0.1:8081:80`，或在 **运行容器** 中把 **本服务器上的端口** 设为 `8081`。
2. 前往 **网站**，点击 **添加网站**。
3. 输入 **域名**，例如 `app.example.com`。
4. 在 **类型** 中选择 **代理后的应用（Node.js、Python、Java…）**。
5. 在 **应用监听的端口（127.0.0.1）** 中输入同一个端口 `8081`。
6. **启动命令（可选）** 留空：由 Docker 运行应用。
7. 点击 **创建网站**。

端口必须在 1024 到 65535 之间，并且不能是面板的端口、3306（MariaDB）、6379（Redis）或 7809（Git Webhook 监听程序）。两个应用网站不能使用同一个端口。

然后为网站获取证书，见 [SSL 证书](./ssl)。网站的其他设置见 [网站](./websites)。

**反向代理到另一个地址** 类型也适用于容器：它可以转发到任何地址，例如 `http://127.0.0.1:8081`，并提供 Host 请求头、WebSocket 和超时时间等选项。见 [反向代理网站](./websites#reverse-proxy-websites)。
