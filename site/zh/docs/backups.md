# 备份

Nefo 把网站、数据库、文件夹和应用商店中的应用备份为 `.tar.gz` 压缩包，可以手动备份，也可以按每天或每周的计划备份，并带有保留策略。它把每份备份保存在服务器上，还可以把一份副本上传到 S3 兼容存储、SFTP 服务器或 Google Drive，并可以用密码短语加密。恢复只需要备份本身，并输入它的名称进行确认，在新服务器上也一样。

本页介绍备份包含什么、手动备份和按计划备份、远程存储及其加密、恢复，以及备份失败时的告警。要在另一台服务器上恢复，见 [在新服务器上恢复](./restore-new-server)。

## 备份包含什么 {#what-a-backup-contains}

| 类型 | 包含 |
|---|---|
| **网站** | 网站文件夹 `/var/www/example.com` 中的文件（顶层的 `tmp` 和 `logs` 文件夹除外），以及关联到该网站的每个数据库的 SQL 转储 |
| **数据库** | 一个数据库的 SQL 转储 |
| **文件夹** | 服务器上的任意文件夹，例如 `/etc/nginx` 或 `/opt/app`，包括属主、权限和符号链接 |
| **应用** | 应用商店中的 Docker 应用：它在 `/var/lib/panel-apps` 中的文件夹、保存的密码、容器的数据，以及它的数据库的转储（见 [应用备份](#app-backups)） |

创建数据库时就把它关联到它的网站（见 [数据库](./databases#create-a-database)），这样网站的备份会包含它。网站备份会略过符号链接和特殊文件。

每份备份都是一个 `.tar.gz` 压缩包，其中有一个 `manifest.json`，文件在 `files/` 下，数据库转储在 `databases/` 下。数据库转储用 `mariadb-dump --single-transaction` 生成，所以网站会继续运行。

网站备份的 `manifest.json` 还会记录在另一台服务器上重新创建该网站所需的信息：它的别名、PHP 版本、重写规则、它自己的 Web 服务器指令，以及其数据库用户的密码。

这台服务器上的备份不加密。只有 root 能读取它们。每个远程存储都可以在副本离开服务器之前用密码短语加密（见 [加密副本](#encrypt-the-copies)）。

## 备份保存在哪里 {#where-backups-are-kept}

每份备份都会先保存在这台服务器的 `/var/backups/panel` 中：

```
/var/backups/panel/site/example.com/example.com_20261126-030000.tar.gz
/var/backups/panel/database/shop/shop_20261126-030000.tar.gz
/var/backups/panel/folder/etc_nginx-1a2b3c4d/etc_nginx_20261126-030000.tar.gz
```

文件夹的模式为 `0700`，文件为 `0600`。面板还会记录每个压缩包的 SHA-256 校验和。本地备份会占用磁盘空间，所以请留意磁盘，以及你的计划保留了多少份备份。

要把备份复制到你的电脑上，打开它的菜单并点击 **下载**。

## 立即备份 {#back-up-now}

1. 前往 **备份**，点击 **立即备份**。
2. 选择 **网站**、**数据库**、**文件夹** 或 **应用**。安装了应用商店中的应用后，才会出现 **应用**。
3. 在 **备份对象** 中选择网站、数据库或应用，或者输入 **文件夹路径**，例如 `/etc/nginx`。之前备份过的文件夹会作为建议显示。
4. 如果设置了远程存储，可以勾选 **同时上传到远程存储**。
5. 点击 **立即备份**。

进度日志会显示每一步。面板一次只运行一个长时间任务，所以请等正在运行的任务先完成。

对于网站，也可以前往 **网站** → 你的网站 → **备份**，点击 **立即备份**。

### 不能备份的文件夹 {#folders-that-can-t-be-backed-up}

面板会拒绝以下文件夹、其中的任何文件夹，以及包含它们的任何文件夹。检查之前会先跟随符号链接。

- `/`，即整个系统；
- `/proc`、`/sys`、`/dev` 和 `/run`；
- 面板的数据 `/var/lib/nefo` 和它的备份 `/var/backups/panel`；
- `/var/lib/panel-sftp`、`/var/lib/panel-acme` 和 `/var/lib/panel-quarantine`。

所以 `/var` 和 `/var/lib` 不能整个备份，但 `/var/www` 或 `/etc` 可以。

## 自动备份 {#automatic-backups}

1. 前往 **备份**，点击 **添加计划**。
2. 选择 **网站**、**数据库**、**文件夹** 或 **应用**，以及备份对象。
3. 在 **时间** 中选择 **每天** 或 **每周**。每周备份还要选择 **星期几**。
4. 选择 **小时**。这是服务器的时间，表单会显示它的 UTC 偏移。
5. 输入 **保留的备份数量**，1 到 365。
6. 可选：勾选 **同时上传到远程存储**。
7. 点击 **保存计划**。

网站有一个快捷方式：**网站** → 你的网站 → **备份** → **每天 03:00**。它保留 7 份备份。

**自动备份** 标签页列出各个计划及其上次运行结果，**完成** 或 **失败**。打开 **上次运行失败** 可以查看错误。

计划如何运行：

- 面板每分钟检查一次。如果有其他任务正在运行，备份会等到下一分钟。
- 如果计划的时间点服务器处于关机状态，面板重新运行后就会执行这次备份。
- 新计划会等到它第一个计划的时间点。要立即得到一份备份，请同时使用 **立即备份**。

### 保留策略 {#retention}

每次计划备份之后，面板会删除该计划生成的、超出保留数量的最旧备份，在这台服务器和远程存储上都会删除。你手动做的备份永远不会被自动删除。

Nefo 在删除网站之前做的备份（**先备份网站**）算作手动备份：它永远不会被自动删除。它的名称以 `_before-delete_<date>-<time>.tar.gz` 结尾。

删除计划会让它停止。它已有的备份会保留。删除网站、数据库或应用也会删除它的计划，它的备份会留在 **备份** 页面上。

## 远程存储 {#remote-storage}

在另一家服务商那里保存一份副本，可以在这台服务器丢失时保护你。前往 **备份** → **远程存储**，点击 **设置**（已设置过一个时点击 **添加存储**）。你可以同时设置 S3 兼容存储、SFTP 服务器和 Google Drive：这时备份会上传到其中每一个。

### S3 兼容存储 {#s3-compatible-storage}

选择 **S3 兼容存储** 并填写：

| 字段 | 输入什么 |
|---|---|
| **端点（https://…）** | 服务商的 S3 地址，只有 `https://` 和主机，没有路径。例如 `https://s3.eu-central-1.amazonaws.com` |
| **存储桶** | 存储桶的名称 |
| **区域** | 存储桶所在的区域。留空表示 `us-east-1`。Cloudflare R2 使用 `auto` |
| **存储桶中的文件夹（可选）** | 一个前缀，例如 `panel/` |
| **访问密钥 ID** | |
| **秘密访问密钥** | 以后修改设置时，留空表示保留当前的密钥 |

适用于 Amazon S3、Cloudflare R2、Backblaze B2、Wasabi 和 MinIO。请使用只能访问这个存储桶的访问密钥。

点击 **测试并保存**。面板会写入一个小测试文件，读回它并删除它，然后才保存设置。

在 S3 存储中，一份备份最大 5 GB，这是单次上传的上限。

### SFTP 服务器 {#sftp-server}

使用另一台你能通过 SFTP（SSH）登录的服务器，例如存储盒或第二台 VPS，并使用一个只用于备份的账户。

选择 **SFTP 服务器** 并填写：

| 字段 | 输入什么 |
|---|---|
| **服务器** | 主机名或 IP 地址，例如 `backup.example.com` |
| **端口** | 通常为 `22` |
| **用户名** | 备份服务器上的账户 |
| **登录方式** | **密码** 或 **私钥** |
| **私钥（OpenSSH 或 PEM）** | 完整的密钥，从 `-----BEGIN` 到 `END-----`。它的公钥必须在备份服务器的 `~/.ssh/authorized_keys` 中 |
| **密码短语（仅用于加密的密钥）** | |
| **服务器上的文件夹（可选）** | 相对于账户的主文件夹，除非以 `/` 开头。需要时会创建 |

点击 **测试并保存**。面板会连接，写入、列出、读取并删除一个测试文件，然后保存设置。保存密钥后，**更改** 会在 **公钥，用于备份服务器上的 ~/.ssh/authorized_keys** 下显示它的公钥部分，方便你再次复制。

### 主机密钥固定 {#host-key-pinning}

**测试并保存** 会信任 SFTP 服务器在那一刻出示的主机密钥，并在 **受信任的主机密钥** 下显示它。之后的每次连接都必须出示完全相同的密钥，否则备份上传会失败。

在依赖这个存储之前，请把指纹与备份服务器自己的密钥进行比较。在备份服务器上运行：

```sh
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

如果备份服务器被重装了，或者它的密钥是有意更换的，点击 **更改**，然后再次点击 **测试并保存** 来信任新密钥。面板随后会警告密钥已被替换。

::: warning
主机密钥变化也可能意味着有人在拦截连接。如果你没有预料到这个变化，请在信任新密钥之前检查备份服务器。
:::

### Nefo 能备份到 Google Drive 吗？ {#google-drive}

能，从 v0.24.0 起。备份会放到你 Google Drive 中的一个文件夹里。面板只请求访问它自己创建的文件（Google 的 `drive.file` 权限）：它看不到也改不了你 Drive 中的其他任何东西。你在 Drive 中手动创建的文件夹对面板是不可见的，即使名称正确也一样。

Google Drive 需要你自己的 OAuth 客户端，建在一个 Google Cloud 项目中。它不花钱，只需创建一次。

Google Drive 只在模拟的 Google 服务上测试过，没有在真实的 Google 账号上测试过。

#### 创建 OAuth 客户端 {#create-the-oauth-client}

这些步骤中的加粗名称是 Google 的，不是面板的。

1. 打开 [Google Cloud console](https://console.cloud.google.com/)，创建一个项目，或选择一个已有项目。
2. 在 **APIs and services**（API 和服务）→ **Library**（库）下，启用 **Google Drive API**。
3. 设置 **OAuth consent screen**（OAuth 同意屏幕），用户类型选 **External**（外部），然后把它的发布状态设为 **In production**（正式发布）。
4. 在 **Credentials**（凭据）下，创建一个类型为 **TVs and Limited Input devices**（电视和有限输入设备）的 **OAuth client ID**（OAuth 客户端 ID）。
5. 保存好客户端 ID（以 `.apps.googleusercontent.com` 结尾）和客户端密钥。

::: warning
同意屏幕的发布状态为 **Testing**（测试）时，Google 会在 7 天后终止面板的访问权限，之后上传就会失败。请把它设为 **In production**。
:::

#### 连接 {#connect}

1. 在 **远程存储** 中，点击 **设置** 或 **添加存储**，并在 **类型** 中选择 **Google Drive**。**如何创建 OAuth 客户端** 会重复上面的步骤。
2. 输入 **客户端 ID** 和 **客户端密钥**。
3. 可选：更改 **Google Drive 中的文件夹**。默认为 `Nefo backups/<the server's host name>`。用 `/` 分隔文件夹；缺失的文件夹会被创建。
4. 可选：勾选 **上传前加密备份**（见 [加密副本](#encrypt-the-copies)）。
5. 点击 **连接 Google Drive**。面板会显示一个地址 `google.com/device` 和一个类似 `ABCD-EFGH` 的代码。
6. 在任何设备上（手机也可以）打开那个地址，用要保存备份的 Google 账号登录，输入代码并允许访问。
7. 在你操作期间，面板会等待，并显示代码的有效时间还剩多久。Google 一回应，面板就会创建文件夹，在里面写入、列出、读取并删除一个小测试文件，然后保存设置。

之后，**远程存储** 列表会显示文件夹、Google 账号和一个链接 **在 Google Drive 中打开**。

面板等待期间你可以离开页面：再次打开 **备份** → **远程存储** 即可看到代码。

#### 更改或重新连接 {#change-or-reconnect}

在 Google Drive 所在的行点击 **更改**：

- 要更改文件夹或加密，编辑后点击 **测试并保存**。不需要重新登录。需要时会创建新文件夹。之前上传的备份留在旧文件夹中，恢复时面板将不再在那里找到它们。
- 要使用另一个 Google 账号或另一个 OAuth 客户端，或者在访问权限被撤销之后，点击 **重新连接** 并输入新代码。**客户端密钥** 留空表示保留同一客户端已保存的密钥。

**测试并保存** 还能修复被删除或移到 Drive 回收站的文件夹：它会重新创建这个文件夹。

请保持使用同一个 Google Cloud 项目。Google 只允许每个项目访问该项目创建的文件，所以如果用另一个项目的 OAuth 客户端，面板就看不到它之前上传的备份。

#### 上传如何进行 {#how-uploads-work}

- 每份备份以 8 MB 为一块上传。如果连接中断或 Google 繁忙，面板会询问 Google 已经收到多少，然后从那里继续。放弃之前，它会重试几分钟。
- 上传之前，面板会检查 Google 账号的可用空间，备份放不下时会立即拒绝。
- 恢复时的下载也会从中断的地方继续。
- Drive 中的文件夹有与 `/var/backups/panel` 相同的子文件夹：`site/example.com/…`、`database/shop/…`。

#### 断开连接 {#disconnect}

Google Drive 所在行的 **删除** 会清除这些设置，并告诉 Google 面板放弃它的访问权限。已经上传的备份会留在你的 Google Drive 中。

#### 出了问题怎么办 {#when-something-goes-wrong}

| 提示 | 怎么办 |
|---|---|
| Google Drive 访问权限已被撤销或已过期 | 点击 **更改** → **重新连接**。如果在连接约 7 天后出现这种情况，请先把同意屏幕的发布状态设为 **In production**。 |
| Google Drive 空间已满 | 在该 Google 账号中释放空间或购买更多存储空间，然后用 **上传** 重新上传。 |
| Google Drive 文件夹 … 已被删除 / 在 Drive 回收站中 | 从 Drive 回收站恢复该文件夹（其中的备份会一起回来），或者点击 **更改** → **测试并保存** 创建一个新文件夹。 |
| Google 拒绝了该 OAuth 客户端 | 检查客户端 ID 和密钥，并确认客户端类型为 **TVs and Limited Input devices**。 |
| 验证码在输入前已过期 | 再次点击 **连接 Google Drive** 获取新的代码。 |

### 加密副本 {#encrypt-the-copies}

每个存储（S3、SFTP 和 Google Drive）都可以加密它收到的备份。这样，存储上的副本没有密码短语就无法读取，无论是服务商还是任何进入存储账户的人。这台服务器上的副本仍是普通的 `.tar.gz`。

1. 在存储的表单中，勾选 **上传前加密备份**。
2. 输入至少 12 个字符的 **密码短语**，并在 **再次输入密码短语** 中输入相同的内容。由几个词组成的一句话效果很好。
3. 点击 **测试并保存**（或 **连接 Google Drive**）。测试文件也会被加密。

::: danger
没有密码短语，加密的备份就无法恢复：你不行，面板不行，任何人都不行。请把它保存在这台服务器之外，例如密码管理器中。如果这台服务器丢失了，有了密码短语和存储，就能把备份找回来。
:::

会有什么变化：

- 加密副本的名称是备份名称加上 `.enc`：`example.com_20261126-030000.tar.gz.enc`。
- 在 **备份** 列表中，**存储位置** 列里该存储的标签会显示一把锁，而不是云朵。
- 该存储在 **远程存储** 中的行会显示 **已加密**。
- 密码短语不会再次显示。修改其他设置时，**密码短语** 留空即可保留它。

更改密码短语：

- 新的密码短语只适用于新的上传。已经上传的副本保留它们加密时使用的密码短语；它们不会被重新加密。
- 这台服务器会记住之前的密码短语（最多 10 个），所以在这里恢复仍然可以工作。
- 在另一台服务器上，你需要上传该副本时使用的密码短语。
- 如果你关闭加密，已经上传的副本仍然是加密的，这台服务器会保留它们的密码短语以便恢复。

工作原理：面板在这台服务器上一边上传一边用 AES-256-GCM 加密压缩包。密钥通过 scrypt 从密码短语派生，每个文件使用新的随机盐，所以同一份备份的两个副本看起来也不一样。压缩包按 64 KB 分段加密，每段都有编号，最后一段有标记，所以被修改、被截短或由其他副本的片段拼凑而成的副本都会被拒绝。除了面板设置中的密码短语，服务器上不保存任何密钥。文件格式见 [在新服务器上恢复](./restore-new-server#format-of-encrypted-copies)。

加密的开销很小：每次上传派生一次密钥，大约需要四分之一秒，并短暂占用 64 MB 内存；副本会多出一个 64 字节的文件头，每 64 KB 多 16 字节。对于 S3 存储，面板会读取备份两次，因为 S3 需要在上传开始之前得到加密副本的校验和。

### 上传和移除存储 {#uploading-and-removing-storage}

- 没有勾选 **同时上传到远程存储** 的备份可以稍后上传：打开它的菜单，点击 **上传**。面板会把它复制到每个还没有它的存储，并为加密的存储加密。
- **存储位置** 列显示 **本服务器**，以及每个远程副本的标签：S3、SFTP 或 Google Drive，加密的副本带一把锁。
- 移除存储设置不会删除已经上传到那里的备份。
- 存储所在行的 **查找备份** 会列出该存储上不在列表中的备份，例如在新服务器上：见 [在新服务器上恢复](./restore-new-server)。

## 恢复备份 {#restore-a-backup}

1. 前往 **备份**，在列表中找到该备份。
2. 在它所在的行点击 **恢复**。
3. 输入对话框要求的名称（域名、数据库名称、文件夹路径或应用名称），然后点击 **恢复**。

面板会先检查压缩包的 SHA-256 校验和，在改动任何东西之前拒绝损坏的文件。如果文件已经不在这台服务器上，会从远程存储下载。

如果副本是加密的，面板会在下载时用该存储的密码短语（或这台服务器记住的之前的密码短语）解密。然后像其他备份一样，对解密后的压缩包进行 SHA-256 检查。当备份只在远程存储中、而且副本是加密的时，**恢复** 对话框中会有一个 **加密密码短语（可选）** 字段。留空则使用该存储的密码短语。如果存储之后被重新设置过（例如你移除了它，又用新的密码短语重新添加），请输入上传该副本时使用的密码短语。

以下情况下，恢复会在改动任何东西之前停止，并在日志中给出提示：

- 密码短语无法解锁副本（“this copy is encrypted and the passphrase does not unlock it”，此副本已加密，密码短语无法解锁）；
- 副本被修改或损坏（“the encrypted copy is damaged or was changed”，加密副本已损坏或被修改）；
- 副本不完整（“the encrypted copy is incomplete”，加密副本不完整）。

如果多个存储上都有副本，面板会尝试下一个。

::: danger
恢复会覆盖当前的内容。备份之后所做的更改会丢失。
:::

恢复会替换什么：

| 类型 | 会发生什么 |
|---|---|
| **网站** | 网站文件夹中的所有文件都会被删除（`tmp` 和 `logs` 除外），并放回备份中的文件，属主为网站用户。备份中的每个数据库都会被清空，并从它的转储中填充。已不存在的数据库会被重新创建，关联到该网站，并使用备份中它的用户的密码（v0.24.0 之前的备份没有这个密码：这时数据库会得到新密码）。不再关联到任何网站的数据库会关联到恢复的网站。对于 WordPress，当前的数据库密码会写入 `wp-config.php` |
| **数据库** | 数据库会被删除，重新创建为空数据库，然后从转储中填充 |
| **文件夹** | 先把备份解压到当前内容旁边。只有这一步成功后，才会替换文件夹的内容，所以损坏的备份会让文件夹保持原样。备份之后新增的文件会被删除。属主、权限和符号链接都会恢复。缺失的文件夹会被创建 |
| **应用** | 应用的容器停止，它的文件夹和数据被替换，容器重新启动，然后加载数据库转储。备份中保存的密码也会恢复 |

网站备份和数据库备份中的转储，会像 **数据库** 页面上的 [导入](./databases#import) 一样加载：使用一个只能访问该数据库的临时 MariaDB 或 MySQL 用户，所以转储永远不会写入另一个数据库。

### 恢复已删除的网站 {#restore-a-website-that-was-deleted}

如果备份所属的网站在这台服务器上已经不存在（例如你删除了它），恢复会根据备份重新创建它：相同的域名和别名、PHP 版本、重写规则、文件和数据库。恢复对话框会先说明这一点。备份中没有的东西（例如证书、定时任务和 SFTP 访问）不会被创建。详情见 [在新服务器上恢复](./restore-new-server#restoring-a-website-that-doesn-t-exist-here)。

Nefo 0.24.1 及以后版本创建的备份会记录每个网站的类型，所以已不存在的网站会以同样的类型恢复：应用网站（Node.js、Python、Java）连同它的运行环境、启动命令、端口和内存上限，反向代理网站连同它的地址和选项。如果应用的运行环境没有安装，恢复会停止，并请你先在 **软件** 页面安装它。旧版本创建的备份只记录 PHP 版本：这样的网站会恢复为静态网站，所以请先用相同的域名和类型重新创建它，然后再恢复。对于 Docker 应用，请先从 [应用商店](./apps) 在同一个域名上重新安装该应用，然后恢复它的 **应用** 类型备份；如果网站文件夹中有它自己的文件（例如 Navidrome 的音乐），再恢复网站的备份。

## 在另一台服务器上恢复 {#restore-on-another-server}

装有 Nefo 的新服务器可以用 **查找备份** 找到你远程存储上的备份，把它们添加到列表中并恢复，包括网站。你需要存储的访问信息；如果副本是加密的，还需要密码短语。见 [在新服务器上恢复](./restore-new-server)。

## 应用备份 {#app-backups}

[应用商店](./apps) 中的 Docker 应用把数据保存在网站文件夹之外，即 `/var/lib/panel-apps/<name>` 中。它们使用 **应用** 类型的备份：

- 备份一个运行 Docker 应用的网站，也会按同样的计划生成一份应用备份。保留策略会把旧的应用备份与网站的备份一起删除。
- 要单独备份一个应用，在 **备份** 页面的 **立即备份** 或 **添加计划** 中选择 **应用**，或者前往 **应用商店** → **已安装** → **立即备份**。PostgreSQL 这类服务应用没有网站，所以请为它们单独设置计划。
- 应用更新之前，面板会先做一份备份。如果这份备份失败，更新不会开始。

面板会根据应用的不同，在复制文件时暂停它的容器，或者先用应用自己的工具转储它的数据库。应用备份和其他备份一样在 **备份** 页面上恢复。恢复需要该应用已安装。卸载应用后，它的备份会以它的名称和图标留在列表中：重新安装该应用（有网站的应用要装在同一个域名上），然后恢复。

## 删除备份 {#delete-a-backup}

打开备份的菜单，点击 **删除**。备份会从这台服务器和远程存储中删除。

## 备份失败时的告警 {#alerts-when-a-backup-fails}

备份或恢复失败时，面板可以通过 Telegram、邮件、Discord、Slack 或 Webhook 发送告警。前往 **设置** → **告警**，开启 **备份、恢复或证书续期失败**。见 [邮件与告警](./mail-alerts)。

对于上次运行失败的计划，**自动备份** 标签页也会显示 **失败**。
