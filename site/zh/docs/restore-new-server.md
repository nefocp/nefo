# 在新服务器上恢复

服务器丢失后，装有 Nefo 的新服务器可以用 **查找备份** 找到你远程存储（S3 兼容存储、SFTP 或 Google Drive）上的备份，并恢复它们。新服务器上不存在的网站会根据备份重新创建，包括它的域名、别名、PHP 版本、文件和数据库。此功能从 v0.24.0 起可用。

本页介绍如何查找备份、恢复会创建什么和不会创建什么、其他类型的备份，以及如何手动解密副本。备份的一般说明见 [备份](./backups)。

## 需要准备什么 {#what-you-need}

- 存储的访问信息：存储桶及其密钥、SFTP 账户，或同一个 Google Cloud 项目的 Google OAuth 客户端；
- 密码短语（如果副本是加密的）；
- 一台装有 Nefo、Web 服务器、网站所用的 PHP 版本以及 MariaDB 或 MySQL 的服务器（见 [入门步骤](./first-steps#set-up-the-server)）。

## 如何在新服务器上恢复网站？ {#restore-on-another-server}

1. 在新服务器上安装 Nefo，然后安装 Web 服务器、PHP 和 MariaDB（见 [入门步骤](./first-steps)）。
2. 前往 **备份** → **远程存储**，设置同一个存储：同一个存储桶和文件夹、SFTP 服务器和文件夹，或 Google Drive 文件夹。Google Drive 请使用同一个 Google Cloud 项目（见 [Google Drive](./backups#google-drive)）。用旧的密码短语勾选 **上传前加密备份** 是可选的：也可以在第 4 步再输入密码短语。
3. 在该存储所在的行点击 **查找备份**。面板会列出存储上不在它备份列表中的备份文件，并读取每个文件的开头部分（它的 `manifest.json`）：备份了什么、何时创建、大小、PHP 版本和数据库。其余部分不会下载。
4. 如果有些加密备份用该存储的密码短语打不开，输入它们上传时使用的密码短语，然后点击 **读取**。
5. 对某份备份点击 **添加到列表**，或点击 **全部添加到列表（…）**，括号中是面板能读取的备份数量。服务器上不会有任何改动：这些备份现在出现在 **备份** 列表中，只保存在存储上。
6. 用 **恢复** 逐一恢复，方法同 [恢复备份](./backups#restore-a-backup)。在找到的列表中点击 **恢复**，可以一次完成第 5 步和第 6 步。

面板读不了的备份会留在列表中并给出原因，例如密码短语错误、文件损坏，或者清单中写的网站与它所在的文件夹不符。**重新查找** 会再次读取存储。

在存储上找到的备份，在列表中没有记录校验和。第一次恢复时，面板会在改动任何东西之前先完整读取一遍压缩包，损坏的文件会被拒绝，同时记录下校验和。

## 恢复这里不存在的网站 {#restoring-a-website-that-doesn-t-exist-here}

备份所属的网站在这台服务器上不存在时，恢复对话框会说明这一点，恢复会创建该网站：

- 使用相同的域名和别名。如果某个别名已被另一个网站占用，网站会在不带别名的情况下创建；
- 使用相同的 PHP 版本，或这里已安装的最新版本，并在日志中给出警告；
- 备份中有相应信息时，标记为 WordPress（或其他应用），带上它的重写规则和它自己的 Web 服务器指令；
- 带上它的文件，属主为新网站的用户；
- 带上它的数据库及数据库用户。v0.24.0 及以后创建的备份会保存每个数据库用户的密码，所以网站自己的配置（`wp-config.php` 之类）可以继续使用。如果是更早的备份，用户会得到新密码：WordPress 会自动写入 `wp-config.php`；其他软件请从 **数据库** 复制密码。

不在备份中、因此不会重新创建的内容：SSL 证书（网站的 DNS 指向新服务器后，在它的 **SSL / HTTPS** 标签页重新获取）、定时任务、SFTP 账户、后台程序、重定向、密码保护，以及网站的其他设置。

Nefo 0.24.1 及以后版本创建的备份会记录每个网站的类型：应用网站（Node.js、Python、Java）会连同它的运行环境、启动命令、端口和内存上限一起重新创建，反向代理网站会连同它的地址和选项一起重新创建。请先在 **软件** 页面安装应用的运行环境；缺少运行环境时，恢复会停止并给出说明。旧版本创建的备份只记录 PHP 版本，这样的网站会被重新创建为静态网站：请先用相同的域名和类型创建它（见 [网站](./websites#create-a-website)），然后再恢复，这样恢复只会替换它的文件和数据库。

没有确认，恢复永远不会替换网站：无论网站是否存在，你都要在对话框中输入它的域名。恢复到已存在的网站上会替换它的文件和数据库，这一点和以往一样。

::: tip
网站备份除了文件和转储，还包含其数据库用户的密码。请像对待网站本身一样谨慎对待备份。加密远程副本可以让它们在存储上无法被读取。
:::

## 其他类型的备份 {#other-kinds-of-backups}

| 类型 | 在新服务器上 |
|---|---|
| **数据库** | 缺失时重新创建；备份中有用户密码时，使用备份中的密码 |
| **文件夹** | 缺失时重新创建 |
| **应用** | 先从应用商店安装该应用（会重新下载它的镜像），然后恢复 |

## 手动解密副本 {#decrypt-a-copy-by-hand}

你也可以自己从存储下载备份文件：从 S3 控制台、用 SFTP 客户端，或在浏览器中从 Google Drive 下载。加密的副本（`.tar.gz.enc`）只需要它的密码短语。在任何装有 `nefo` 程序的 Linux 服务器上用它解密：

```sh
nefo decrypt-backup example.com_20261126-030000.tar.gz.enc
```

它会询问密码短语，并在旁边写出 `example.com_20261126-030000.tar.gz`。见 [命令行](./cli#nefo-decrypt-backup)。

压缩包中，网站的文件在 `files/` 下，数据库转储在 `databases/` 下。用 `tar xzf` 解压。

## 加密副本的格式 {#format-of-encrypted-copies}

供参考，也可用于不借助 Nefo 解密副本。所有数字都是大端序。

| 偏移 | 大小 | 内容 |
|---|---|---|
| 0 | 7 | `NEFOENC`（ASCII） |
| 7 | 1 | 格式版本：1 |
| 8 | 1 | 密钥派生：1 = scrypt |
| 9 | 1 | scrypt 成本，log2(N)：16 |
| 10 | 1 | scrypt r：8 |
| 11 | 1 | scrypt p：1 |
| 12 | 1 | 加密算法：1 = AES-256-GCM |
| 13 | 1 | log2(块大小)：16，即 64 KiB |
| 14 | 2 | 零 |
| 16 | 32 | 盐，每个文件随机生成 |
| 48 | 12 | 密钥校验 |
| 60 | 4 | 字节 0 到 59 的 CRC-32（IEEE） |

- scrypt(passphrase, salt, N, r, p) 得到 44 个字节。字节 0–31 是 AES-256 密钥；字节 32–43 必须等于密钥校验，否则密码短语错误。
- 64 字节的文件头之后是各个块。压缩包按块大小切成若干段。最后一段较短，可能为空，所以段数总是 大小 ÷ 块大小 + 1（向下取整，再加一）。
- 每一段用 AES-256-GCM 加密，以 64 字节的文件头作为附加数据，nonce 为：从 0 开始的段序号（8 字节）、3 个零字节，最后一段再接 `01`，其他段接 `00`。存储形式是密文后接 16 字节的标签。
- 文件大小为 64 + 大小 + 16 × (大小 ÷ 65536 + 1)。
