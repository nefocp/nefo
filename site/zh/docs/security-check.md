# 安全检查

安全检查是 v0.24.0 新增的功能，会对服务器做 22 项快速检查：接受密码登录的 SSH、关闭的防火墙、待安装的安全更新、对互联网开放的数据库或 Redis、绕过 ufw 的 Docker 端口、任何人都能下载的网站文件、即将过期的证书，以及 PHP 设置。每项发现都有严重程度，还有一个按钮通往修复它的页面。

它在你启动时运行，默认也每天运行一次。它不会向服务器之外发送任何东西。在左侧菜单的 **安全** 分组中打开 **安全检查**。

## 运行检查 {#run-the-check}

1. 点击 **运行检查**。需要几秒钟。
2. 在 **待修复** 标签页上查看发现。每项都有严重程度：
   - **严重**：立即修复。例如，root 可以用密码通过 SSH 登录，或者某个网站对外提供数据库转储。
   - **警告**：尽快修复。例如，防火墙已关闭，或有安全更新等待安装。
   - **提示**：值得了解，通常保持原样也没问题。例如，SSH 监听 22 端口。
3. 点击某项发现的按钮，例如 **前往 防火墙与 SSH**，打开修复它的位置。然后再运行一次检查。

顶部的计数器显示仍未解决的 **严重** 问题、**警告** 和 **提示** 的数量，以及 **通过** 的检查数量。点击页面底部的 **通过**，可以查看每项没有发现问题的检查。不适用于这台服务器的检查（没有 Redis、没有网站、没有 Docker……）列在“不适用于这台服务器”下。

## 安全检查会检查哪些内容？ {#what-is-checked}

| 检查 | 严重程度 | 在哪里修复 |
|---|---|---|
| root 可以用密码通过 SSH 登录 | 严重 | **防火墙与 SSH** → SSH |
| SSH 允许其他账户用密码登录 | 警告 | **防火墙与 SSH** → SSH |
| SSH 监听 22 端口 | 提示 | **防火墙与 SSH** → SSH |
| 防火墙（ufw）未安装或已关闭 | 警告 | **防火墙与 SSH** |
| fail2ban 未安装、未运行，或没有监视 SSH（没有 `sshd` jail） | 警告 | **防火墙与 SSH** → fail2ban，或 **服务** |
| 不通过 HTTPS 访问面板 | 严重 | `/etc/nefo/config.json`（见下文） |
| 面板使用自签名证书 | 提示 | **设置** |
| 某个面板账户没有开启双因素登录 | 严重 | **账户** |
| 有安全更新等待安装 | 警告 | **系统** |
| 更新检查已超过一周，或从未运行 | 提示 | **系统** |
| 自动安全更新已关闭 | 警告 | **系统** |
| 需要重启才能完成更新 | 提示 | **设置** |
| root 以外的账户的用户 ID 为 0 | 严重 | **终端** |
| 某个账户的密码为空 | 严重 | **终端**（`passwd -l <account>`） |
| MariaDB、MySQL、PostgreSQL、Redis、Valkey、Memcached 或 MongoDB 监听 127.0.0.1 以外的地址 | 防火墙允许所有人访问该端口时为严重，否则为提示 | **数据库** |
| Redis 没有密码 | 在防火墙放行的公网地址上为严重，在其他公网地址上为警告，只监听本机时为提示 | **数据库** → Redis |
| 某个 Docker 容器在所有地址上发布端口 | 警告 | **Docker** |
| 某个网站没有 HTTPS | 警告 | **网站** → 你的网站 → **SSL / HTTPS** |
| 某个网站有证书，但不重定向到 HTTPS | 提示 | **网站** → 你的网站 → **SSL / HTTPS** |
| 某个证书已过期 | 严重 | **网站** → 你的网站 → **SSL / HTTPS** |
| 某个证书在 14 天或更短时间内过期 | 警告 | **网站** → 你的网站 → **SSL / HTTPS** |
| 某个网站对外提供本应私有的文件 | 机密文件为严重，副本和压缩包为警告 | **文件** |
| 某个网站有所有人可写的文件或文件夹 | 警告 | **文件** |
| PHP 向访客显示错误（`display_errors`） | 警告 | **软件** → PHP → **管理** |
| PHP 公开自己的版本（`expose_php`） | 提示 | **软件** → PHP → **管理** |
| WordPress 核心、插件或主题有更新等待安装 | 警告 | **网站** → 你的网站 → **WordPress** |
| WordPress 调试模式（`WP_DEBUG`）已开启 | 警告 | **网站** → 你的网站 → **WordPress** |

一些细节：

- **网络上的数据库**：检查会读取每个程序监听哪些地址。对于公网地址，它会查看防火墙：没有防火墙，或有规则允许所有人访问该端口，则为严重。防火墙只对部分地址开放的端口（例如数据库的 **远程访问**），或完全不开放的端口，为提示。私有网络的地址（10.x、172.16–31.x、192.168.x）为提示。
- **Docker** 会把自己的防火墙规则写在 ufw 的规则之前，所以 ufw 拦不住容器发布的端口。如果只有这台服务器上的网站使用该端口，请把端口发布在 `127.0.0.1` 上（例如 `127.0.0.1:8080:80`）。
- **网站对外提供的文件**：检查会列出每个网站 `public` 文件夹的顶层，并向 Web 服务器请求那些永远不该公开的文件：`.env` 文件，`.git`、`.svn` 和 `.hg` 文件夹，`.htpasswd`，数据库转储（`.sql`、`.sql.gz`、`.dump`、`.sqlite`……），`wp-config.php` 的副本，备份副本（`.bak`、`.old`、`.orig`、`.save`、`.swp`，以及以 `~` 结尾的文件名），`phpinfo.php` 和 `info.php`，以及名称看起来像网站副本的压缩包（名称中含有“backup”“www”“site”“wordpress”或域名）。出现发现意味着 Web 服务器返回了该文件。Nefo 的 Nginx 配置会隐藏点文件，所以在 Nginx 上，`.env` 文件会被找到，但不会报告。已暂停、重定向到别处、要求密码或是代理后面的应用的网站不会被请求。
- **所有人可写的文件**：检查会遍历网站文件夹（`/var/www/<domain>`），不跟随符号链接。设置了粘滞位的文件夹（例如共享的 `tmp`）没有问题。文件请用 644，文件夹用 755。
- **PHP**：检查会读取每个 PHP 版本的 `php.ini` 和 `conf.d` 文件，以及 PHP-FPM 池，看是否有为某个网站开启的 `display_errors`。
- **WordPress** 的更新信息来自 **WordPress** 页面（或网站的 **WordPress** 标签页）上次的检查。安全检查本身从不运行 wp-cli。更新网站之后，下一次检查会告诉你还剩下什么。
- **不通过 HTTPS 访问的面板**：Nefo 安装时会开启 HTTPS。如果它被关闭了，在 `/etc/nefo/config.json` 的 `"tls"` 部分设置 `"enabled": true`，然后运行 `systemctl restart nefo`。只监听 127.0.0.1 的面板不会被报告。

## 检查需要多长时间？ {#limits}

检查会读取面板自己的数据和少量文件，并且只向这台服务器自己的 Web 服务器（127.0.0.1）请求网站文件夹中存在的文件。每项检查都有上限，所以即使服务器上有很多网站，一次运行也很短：

| 上限 | 值 |
|---|---|
| 你启动的一次运行 | 最多 25 秒。届时尚未完成的检查会标为在上限处停止，结果会注明不完整 |
| 检查调用的每个程序（fail2ban、Docker、apt……） | 最多 5 秒；没有及时响应的程序会被略过 |
| 在一个网站文件夹中遍历的文件和文件夹 | 20,000 个（所有网站合计 100,000 个） |
| 在一个网站的 `public` 文件夹中读取的条目 | 5,000 个 |
| 向这台服务器的 Web 服务器发出的请求 | 共 200 个，每次 4 个并发，每个最多 3 秒 |

## 接受一项发现 {#accept-a-finding}

有些发现在你的服务器上没有问题：有 fail2ban 保护的 22 端口上的 SSH，或你有意只对一个地址开放的数据库端口。对这样的发现点击 **接受**。它会移到 **已接受** 标签页，不再计数。

已接受的发现在其事实变化时会重新出现，例如另一个账户的用户 ID 变为 0，或某个数据库开始监听另一个地址。如果它被修复后又再次出现，也会重新出现。要自己让它重新出现，打开 **已接受** 标签页并点击 **重新显示**。接受和重新显示都会写入活动日志。

## 每日检查和告警 {#daily-check-and-alerts}

开启 **每天运行**（默认）后，面板每天在后台运行一次检查，安排在它每小时的维护中，但绝不在面板启动后的前 10 分钟内运行。这样仪表盘上总是显示最近的结果。

开启 **每日检查发现新问题时告警**（默认关闭），当每日检查发现上一次检查没有的严重问题或警告时，你会在告警渠道（**设置** → **告警**）中收到消息。提示和已接受的发现永远不会发送。见 [告警](./mail-alerts#alerts)。

## 在仪表盘上 {#on-the-dashboard}

上一次检查发现严重问题或警告时，仪表盘上的 **需要注意** 和铃铛会显示“安全检查：3 个问题待修复”，并带有 **查看** 按钮。没有未解决的严重问题时，**安全风险** 卡片会显示检查上次运行的时间，点击它会打开安全检查。

要在有人登录 SSH 和面板时收到通知，见 [登录告警](./mail-alerts#sign-in-alerts)。
