# 安全

Nefo 以 root 身份运行，所以它首先保护自己的登录：随机端口上的秘密地址、从第一次启动起就使用的 HTTPS、双因素认证、登录限制和活动日志。它还管理服务器的防火墙（ufw）、fail2ban 和 SSH 设置，并带有防锁定保护；对于网站，它用 Web 应用防火墙、速率限制、封禁地址和恶意软件扫描器来保护。

本页介绍：

- 面板自身的保护：隐藏的地址、HTTPS、登录限制、双因素认证、会话和活动日志；
- [安全检查](./security-check)，它会列出让服务器暴露在外的设置，以及每项在哪里修复；
- **防火墙与 SSH** 页面上的服务器防火墙（ufw）、fail2ban 和 SSH 设置；
- 网站安全：Web 应用防火墙、速率限制、封禁地址、国家/地区拦截、文件锁定和恶意软件扫描器。

Nefo 处于测试阶段（beta），还没有经过外部安全审计。见 [安全策略](../security-policy)。

## 安全检查 {#security-check}

左侧菜单 **安全** 分组中的 **安全检查** 会对服务器做 22 项快速检查，例如 SSH 密码登录、防火墙、待安装的安全更新、对互联网开放的数据库、Docker 端口、网站误公开的文件以及证书。每项发现都链接到修复它的页面。它可以随时运行，也会每天运行一次。见 [安全检查](./security-check)。

## 面板自身的保护 {#the-panel-s-own-protection}

### 隐藏入口路径 {#hidden-entrance-path}

安装程序会选择 20000 到 49999 之间的一个随机端口，以及由 12 个小写字母和数字组成的秘密路径。面板只在这个路径下响应，例如 `https://203.0.113.10:28443/k3x9p2qa7m1z/`。该端口上的其他所有 URL 都返回 `404`，所以扫描器无法判断那里运行着面板。

如果丢失了地址，在服务器上运行：

```sh
nefo info
```

它会打印使用服务器第一个 IP 地址的 URL；面板有了域名之后（见下文），还会打印使用面板域名的 URL。如果服务器位于一个单独的公网地址之后，运行 `nefo info --host 203.0.113.10`，打印使用该地址的 URL。

端口和路径以 `listen` 和 `entrance` 保存在 `/etc/nefo/config.json` 中。面板中没有修改它们的设置。要手动修改路径，把 `entrance` 设为 8 到 32 个小写字母和数字，然后运行 `systemctl restart nefo`。

### 从第一次启动起就使用 HTTPS {#https-from-the-first-start}

面板从第一次启动起就提供 HTTPS，使用 TLS 1.2 或更新版本。它会在 `/var/lib/nefo/tls/` 中创建一张自签名证书，所以浏览器第一次会警告你。要消除警告，请为一个指向这台服务器的域名获取免费的 Let's Encrypt 证书：

1. 如果还没有安装，从 **网站** 安装 Web 服务器。Let's Encrypt 会在 80 端口上检查域名，由 Web 服务器响应。
2. 把域名的 A 记录指向服务器，不经过代理或 CDN。
3. 前往 **设置** → **证书**。
4. 输入 **面板域名**，例如 `panel.example.com`，然后点击 **获取证书**。
5. 用 `https://panel.example.com:28443/k3x9p2qa7m1z/` 打开面板，换成你自己的端口和路径。

这张证书会像网站的证书一样自动续期；续期失败后每 12 小时重试一次。要移除它，点击 **删除**：面板会改回它的自签名证书。证书的一般说明见 [SSL 证书](./ssl)。

### 登录限制 {#sign-in-limits}

- 15 分钟内失败 5 次，该地址会被锁定 15 分钟。登录页面随后会显示“失败次数过多。请 … 秒后重试。”
- 错误的密码和错误的双因素验证码都会计入。在 **账户** 页面的密码和 2FA 表单中输错当前密码也会计入。
- IPv6 地址按 /64 网段计数，因为一个用户通常控制整个 /64。
- 成功登录会清除计数。
- 用户名错误和密码错误给出相同的消息，耗时也相同，所以登录页面不会透露存在哪些用户名。
- 面板计数的是连接到它的地址，并忽略 `X-Forwarded-For`。如果你在面板前面放了一个代理，所有访客会共用一个计数。

密码以 bcrypt 哈希值保存，从不以明文保存。

::: tip
如果把自己锁在外面了，请等 15 分钟。计数保存在内存中，所以在服务器上重启面板（`systemctl restart nefo`）也会清除它。
:::

### 会话和退出登录 {#sessions-and-signing-out}

- 一次登录持续 12 小时。之后即使你一直在操作，也需要重新登录。
- 要退出登录，打开右上角的账户菜单，点击 **退出登录**。
- 修改密码会让你在所有设备上退出登录。在服务器上运行 `nefo reset-password` 也是如此。
- 会话 Cookie 不能被脚本读取，只通过 HTTPS 发送，并且只发送到面板自己的路径。

### 安全响应头 {#security-headers}

每个页面都带有严格的内容安全策略（Content Security Policy），只允许来自面板自身的脚本。面板还会发送 `X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`（让秘密路径不会出现在其他网站的日志中），以及关闭摄像头、麦克风和定位的 `Permissions-Policy`。每项更改都需要一个其他网站无法发送的请求头，从而阻止跨站请求伪造。

## 双因素认证 {#two-factor-authentication}

双因素认证（2FA）在每次登录时都要求输入身份验证器应用中的 6 位验证码，所以光有被盗的密码是不够的。任何支持标准基于时间的验证码的应用都可以，例如 Google Authenticator、Authy 或 2FAS。2FA 关闭期间，面板会把“双因素登录已关闭”列为严重问题。

### 开启 2FA {#turn-on-2fa}

1. 在左侧菜单中前往 **账户**。也可以打开账户菜单，点击 **密码与 2FA**。
2. 在 **双因素认证** 下，点击 **设置**。
3. 用应用扫描二维码，或者把 **设置密钥** 输入应用。应用中显示的账户名为 Nefo。
4. 输入应用显示的 6 位验证码，然后点击 **开启**。

从此以后，登录页面会在密码之后要求输入 **双因素验证码**。

验证码每 30 秒变化一次。面板也接受上一个和下一个验证码，以防两边的时钟略有偏差。每个验证码只能使用一次：如果验证码被拒绝，请等待下一个。

### 关闭 2FA {#turn-off-2fa}

在 **账户** 的 **双因素认证** 下，输入你的 **密码** 和当前的 **验证码**，然后点击 **关闭**。

### 如果丢了手机 {#if-you-lose-your-phone}

Nefo 没有备用验证码。你需要通过服务器恢复：以 root 身份通过 SSH 登录并运行：

```sh
nefo reset-password --disable-2fa
```

这会为 `admin` 账户设置新的随机密码，关闭 2FA，让所有会话退出登录，并打印新密码。用它登录，修改密码，然后重新设置 2FA。见 [命令行](./cli)。

::: warning
没有手机时，服务器的 root 权限是重新进入面板的唯一途径。请妥善保管你的 SSH 密钥或 root 密码，或者服务商的 Web 控制台。
:::

## 修改面板密码 {#change-the-panel-password}

1. 前往 **账户** → **修改密码**。
2. 输入 **当前密码**，然后输入两次 **新密码**（**再次输入新密码**）。它的长度必须为 12 到 72 个字符。
3. 点击 **修改密码**。

你会在所有设备上退出登录。请用新密码重新登录。

## 活动日志 {#activity-log}

**账户** → **最近活动** 显示最新的 100 条记录，包括时间、操作、用户、IP 地址和详情。可以显示 **全部** 记录或只显示 **失败**，也可以在筛选框中输入内容搜索。页面顶部显示你上次登录的时间，以及日志中有多少次失败的登录。

日志记录：

- 登录、退出登录和失败的登录，以及原因（用户名或密码错误，或 2FA 验证码错误）；
- 修改密码、从命令行重置密码，以及开启或关闭 2FA；
- 在面板中所做的更改：网站、证书、数据库、文件、备份、定时任务、服务、防火墙规则、SSH 设置和密钥、软件和 Docker；
- 打开和关闭终端，以及打开了多长时间；
- 面板重启和服务器重启。

证书的自动续期以用户 `system` 记录。记录保留 90 天。每条记录也会写入面板的服务日志，你可以用 `journalctl -u nefo` 读取。fail2ban 从那里读取失败的登录。

## 防火墙（ufw） {#firewall-ufw}

Nefo 用 ufw 管理服务器的防火墙。前往 **防火墙与 SSH** → **防火墙（ufw）**。

如果页面提示没有安装 ufw，请在服务器上安装它。面板不会安装它：

```sh
apt install ufw
```

### 开启防火墙 {#turn-on-the-firewall}

1. 点击 **开启防火墙** 并确认。
2. 面板会先放行 SSH 端口（注释 `SSH`）和面板的端口（注释 `Nefo`）。安装了 Web 服务器时，它还会为网站放行 80 和 443 端口（注释 `Websites`），OpenLiteSpeed 提供 HTTP/3 时还会放行 443/UDP。然后它开启 ufw。即使你在防火墙关闭期间为这些端口之一添加过规则（例如只限你的地址的规则），它也会添加这些规则，所以开启防火墙永远不会把你锁在外面。如果只想保留你自己的规则，之后删除那条对所有人开放的规则（见 [防火墙会拒绝什么](#what-the-firewall-refuses) 的最后）。

你可以在开启防火墙之前 [添加规则](#add-a-rule)，例如为服务器上另一个程序需要的端口添加规则。防火墙关闭期间，页面会在 **开启防火墙** 下方的 **规则（ufw 命令）** 列中以 ufw 命令的形式显示它们，例如 `ufw allow 8080/tcp`，每对 IPv4 和 IPv6 规则只显示一次。开启防火墙时，它们就会生效。ufw 只在开启时才给规则编号，所以要删除其中某条，请先开启防火墙。

除非有规则允许，所有其他入站端口都是关闭的。防火墙开启后再安装 Web 服务器时，Nefo 会在那时开放 80 和 443 端口。

如果你的服务商有云防火墙（安全组），也要在那里开放同样的端口。Nefo 无法更改它。

### 添加规则 {#add-a-rule}

1. 点击 **添加规则**。
2. 选择 **允许** 或 **拒绝**。
3. 在 **端口，例如 8080** 中输入一个端口，或 `6000:6010` 这样的范围。
4. 选择 **协议**：TCP、UDP 或 TCP + UDP。范围只能用一种协议：选 TCP + UDP 时会变成 TCP。
5. 在 **来源** 中输入一个 IP 地址或 `198.51.100.0/24` 这样的网段。留空表示允许或拒绝所有人。
6. 可选：添加最多 60 个字符、不含引号的 **备注**。
7. 点击 **添加**。

页面会在列表上方显示你自己的 IP 地址，方便你只为自己开放某个端口。

ufw 从上到下检查规则，并使用第一条匹配的规则。在 **来源** 中填了地址的 **拒绝** 规则会放在列表顶部，这样即使后面有规则对所有人开放该端口，它也会生效。其他规则添加在末尾。

::: tip
如果只想让某个地址无法访问一个网站，请改用该网站的 **阻止访问** 设置（见下文）。
:::

列表中也会显示你在命令行上用 ufw 添加的规则。**限制** 放行一个端口，但如果某个地址在 30 秒内打开 6 个连接，会暂时拒绝它（`ufw limit`）。**回绝** 像 **拒绝** 一样拒绝，但会立即告诉对方。

### 删除规则 {#delete-a-rule}

点击规则所在行末尾的垃圾桶图标并确认。如果在你打开页面之后规则发生了变化，面板会拒绝并请你重新加载，所以它永远不会删错规则。

### 防火墙会拒绝什么 {#what-the-firewall-refuses}

以下保护措施可以防止你把自己锁在外面：

- 当一条放行 SSH 端口或面板端口的规则是你从当前地址（显示在列表上方）进入的最后一条通道时，它会显示 **受保护**。这里无法删除它。如果另一条规则也放行你的地址，就可以删除这条规则。
- **来源** 为空的、针对 SSH 端口或面板端口的 **拒绝** 规则会被拒绝。针对某个地址或网段的 **拒绝** 规则是允许的。

要只让你自己的地址访问面板：为面板端口添加一条 **允许** 规则，在 **来源** 中填入你的地址，然后删除对任何地址开放该端口的规则（及其 IPv6 副本）。如果之后你的地址变了，请用服务商的 Web 控制台运行 `ufw allow <port>/tcp`。

远程数据库访问的规则（MariaDB 和 MySQL 的 3306 端口，PostgreSQL 集簇的端口，默认 5432）由 **数据库** 页面添加和删除。请在那里修改它们。见 [数据库](./databases#allow-remote-access) 和 [PostgreSQL](./postgresql#postgresql-remote-access)。

## 防暴力破解（fail2ban） {#brute-force-protection-fail2ban}

fail2ban 会封禁不停登录失败的地址，包括 SSH 和面板。

### 安装 fail2ban {#install-fail2ban}

1. 前往 **防火墙与 SSH** → **防暴力破解（fail2ban）**。
2. 点击 **安装 fail2ban**。安装在后台运行，并带有实时日志。

Nefo 会在 `/etc/fail2ban/jail.d/panel.conf` 中设置两个 jail：

| Jail | 监视 | 封禁条件 | 封禁时间 |
|---|---|---|---|
| `sshd` | SSH 登录，包括 SFTP | 10 分钟内失败 5 次 | 1 小时 |
| `panel` | 失败的面板登录，或在地址被锁定期间被拒绝的面板登录 | 10 分钟内 10 次 | 1 小时 |

被封禁的地址无法访问该 jail 保护的端口。面板自己的登录限制（15 分钟内失败 5 次）先起作用。在被锁定期间仍不停尝试的地址，随后会被 `panel` jail 在防火墙中封禁。

面板会重写这个文件以及它在 `/etc/fail2ban/filter.d/panel.conf` 中的过滤器，所以不要手动编辑它们。更改 SSH 端口时，`sshd` jail 会随之更改。

### 查看和解封地址 {#see-and-unblock-addresses}

表格列出每个 **受保护的服务**、它的 **最近失败次数** 和 **当前封禁** 的地址，以及总共封禁的次数。要解封一个地址，点击它旁边的 **解封**。

如果 fail2ban 已安装但已停止，请在 **服务** 页面启动它。

::: tip
如果你把自己从 SSH 封禁了，从你当前的网络登录面板并点击 **解封**。也可以在面板的 **终端** 中运行 `fail2ban-client set sshd unbanip 203.0.113.10`。
:::

## SSH 设置 {#ssh-settings}

前往 **防火墙与 SSH** → **SSH**。

| 设置 | 选项 |
|---|---|
| **端口** | 1 到 65535 |
| **root 登录** | **仅限 SSH 密钥（推荐）**、**密钥或密码**、**不允许** |
| **允许密码登录** | 开启或关闭，对每个账户都适用 |

点击 **保存**。面板会把它的设置写入 `/etc/ssh/sshd_config.d/00-panel.conf`，这个文件优先于其他 SSH 设置文件。它还会关闭键盘交互式登录。在重启 SSH 之前，它会用 `sshd -t` 测试新设置。如果测试失败，旧文件会被放回去，什么都不改变。

::: warning
保存后请保持当前的 SSH 会话打开。先打开一个新连接，确认能够登录，再关闭旧会话。
:::

### SSH 设置会拒绝什么 {#what-the-ssh-settings-refuse}

- 会导致任何人都无法再通过 SSH 登录的设置。例如：在没有任何账户有 SSH 密钥时关闭密码登录；root 没有密钥时把 root 登录设为 **仅限 SSH 密钥**；或者没有其他账户能登录时把 root 设为 **不允许**。
- 已被占用的端口：面板自己的端口、80、443，或任何其他程序正在监听的端口。
- SSH 由 systemd 套接字激活启动时的新端口。这时页面会显示 **套接字激活**，端口字段被锁定。请在命令行上更改端口。

为了判断是否还有人能登录，面板会查看 root 以及带登录 shell 的普通用户账户（UID 1000 及以上）：它们在 `~/.ssh/authorized_keys`（或 `AuthorizedKeysFile` 设置的文件）中的密钥、它们的密码，以及 `AllowUsers`、`DenyUsers`、`AllowGroups` 和 `DenyGroups`。它不读取 `Match` 块。页面会列出现在谁能登录、以及用什么方式（密钥或密码）。root 没有密钥时，还会显示一条警告，并带有 **添加密钥** 按钮（见 [SSH 密钥](#ssh-keys)）。

不能从 **服务** 页面停止 SSH，只能重启或重新加载它。

::: warning
把 root 登录设为 **不允许** 时，你需要另一个能使用 `sudo` 的账户，否则你虽然能登录，却无法通过 SSH 管理服务器。Nefo 不会创建这个账户，也不会检查它能否使用 `sudo`。
:::

### 更改 SSH 端口 {#change-the-ssh-port}

1. 输入新的 **端口**，点击 **保存** 并确认。
2. 如果防火墙已开启，面板会在 SSH 切换到新端口之前开放新端口（注释 `SSH`）。如果安装了 fail2ban，它的 `sshd` jail 也会切换到新端口。
3. 如果你的服务商有云防火墙，也要在那里开放新端口。
4. 测试一个新连接，例如 `ssh -p 2222 root@203.0.113.10`。
5. 旧端口的防火墙规则会保留，并且不再受保护。新端口可用后，在 **防火墙（ufw）** 下删除它。

网站的 SFTP 账户也通过同一个端口连接。

### SSH 密钥 {#ssh-keys}

SSH 设置下方的 **SSH 密钥** 按账户分组，列出 root 和普通用户账户（UID 1000 及以上、带登录 shell）的公钥。Nefo 从 `~/.ssh/authorized_keys` 或 `AuthorizedKeysFile` 设置的文件中读取它们。每个密钥显示它的类型和长度（例如 `ed25519` 或 `rsa 4096`）、注释、SHA256 指纹，以及它的选项（如果有，例如 `from="…"` 或 `command="…"`）。DSA 密钥或小于 2048 位的 RSA 密钥会标为 **弱**：当前的 OpenSSH 会拒绝它们。请先添加新密钥，再移除弱密钥。

网站的 SFTP 账户不会列在这里：它们的密钥在每个网站的 SFTP 设置中。

#### 添加密钥 {#add-a-key}

1. 如果还没有密钥对，在你的电脑上生成一个。在 Windows 10 及以后版本的 PowerShell 中也是同样的命令：
   ```sh
   ssh-keygen -t ed25519
   ```
   私钥保存在 `~/.ssh/id_ed25519`，留在你的电脑上。公钥保存在 `~/.ssh/id_ed25519.pub`。
2. 打印公钥，复制以 `ssh-ed25519` 开头的整行：
   ```sh
   cat ~/.ssh/id_ed25519.pub
   ```
3. 在面板中，在 **SSH 密钥** 下点击 **添加密钥**。
4. 选择 **账户**，把这一行粘贴到 **公钥** 中，然后点击 **添加密钥**。
5. 从一个新终端测试它，例如 `ssh root@203.0.113.10`。

Nefo 会把密钥添加到该账户 `~/.ssh/authorized_keys` 的末尾。文件夹或文件缺失时，它会创建它们，属于该账户，模式为 700 和 600。它会拒绝：

- 私钥，例如以 `-----BEGIN OPENSSH PRIVATE KEY-----` 开头的密钥。如果你不小心把私钥粘贴到了某个地方，请生成一个新的密钥对；
- 多于一行的内容。在 PuTTYgen 中，请复制 **Public key for pasting into OpenSSH authorized_keys file**（用于粘贴到 OpenSSH authorized_keys 文件的公钥）框中的内容；
- DSA 密钥，以及小于 2048 位的 RSA 密钥；
- 该账户已有的密钥；
- 是符号链接、或者不是普通文件或文件夹的 `authorized_keys` 文件或 `.ssh` 文件夹。账户可能把它指向服务器上的另一个文件，所以 Nefo 既不读取也不更改它。

#### 移除密钥 {#remove-a-key}

点击密钥旁边的垃圾桶图标并确认。确认对话框会用密钥的类型、指纹和注释指明是哪个密钥。如果在当前设置下，没有这个密钥就没有人能通过 SSH 登录，面板会拒绝：请先添加另一个密钥，或者允许密码登录。

添加和移除密钥都会记录在活动日志中，包括账户和密钥的指纹。

### 关闭密码登录 {#turn-off-password-sign-in}

1. 在 [SSH 密钥](#ssh-keys) 下，为 root 或你登录用的账户添加你的公钥。
2. 打开一个新终端，用密钥登录。如果 SSH 要求输入密码，说明没有用上密钥：请检查你是否把它添加到了你登录的那个账户。
3. 关闭 **允许密码登录**，然后点击 **保存**。如果没有任何人有密钥，面板会拒绝（见 [SSH 设置会拒绝什么](#what-the-ssh-settings-refuse)）。
4. 保持当前会话打开，在关闭它之前再检查一次新连接。

即使关闭了 SSH 的密码登录，网站的 SFTP 账户也会保留它们自己的登录方式（密码或密钥）。

只要 root 还能用密码登录，面板就会把“root 可以通过 SSH 用密码登录”列为严重问题。

## 网站安全 {#website-security}

每个网站都有自己的安全设置。前往 **网站**，点击网站名称或 **设置** 打开网站，然后使用 **安全** 下的标签页。

### Web 应用防火墙 {#web-application-firewall}

Web 应用防火墙（WAF）是 ModSecurity 加 OWASP Core Rule Set，两者都是免费的开源软件。它检查每个请求，阻止 SQL 注入、跨站脚本（XSS）、文件包含、已知的扫描器和其他常见攻击。它适用于 Nginx、Apache 和 OpenLiteSpeed。

1. 安装一次：**软件** → **Web 防火墙（ModSecurity）** → **安装**。在你开启之前，网站的防火墙保持关闭。如果发行版没有适用于该 Web 服务器的 ModSecurity 模块，卡片会说明，并且不提供安装：Ubuntu 22.04 上没有 Nginx 的模块，但 Apache 和 OpenLiteSpeed 可以；从 Ubuntu 24.04 起 Nginx 也可以。
2. 前往 **网站** → 你的网站 → **Web 防火墙（WAF）**。
3. 选择一种模式：
   - **关闭**
   - **仅检测：记录攻击，不拦截**
   - **拦截攻击**：访客会得到 HTTP 403。
4. 点击 **保存**。

先用仅检测模式运行几天，在开始拦截之前检查事件中有没有误报。运行 WordPress 或使用 WordPress、Drupal 重写预设的网站，会自动获得规则集中针对这些应用的例外。

**最近的防火墙事件** 列出这个网站上被规则标记的最新 50 个请求：时间、IP 地址、请求、匹配的规则，以及它是 **已拦截** 还是只 **已记录**。事件来自 `/var/log/panel-waf/audit.log`，它每天轮转，保留 7 天。

只检查请求的前 13 MB，所以大文件上传仍然可以工作。如果你在 **软件** 页面移除了 WAF，每个网站会保留它的模式，重新安装后再次生效。

### 速率限制和封禁地址 {#rate-limit-and-blocked-addresses}

前往 **网站** → 你的网站 → **阻止访问**。

- **速率限制（每位访客每秒请求数，0 = 关闭）**：只计算 PHP 和应用的请求，不计算图片、CSS 或脚本。允许最多五倍于限制的突发请求；超过之后，访客会得到 HTTP 429。10 适合大多数网站，最大值是 1000。只有 Nginx 有这个设置：在 Apache 和 OpenLiteSpeed 上不显示。
- **封禁的 IP 地址**：每行一个 IPv4 或 IPv6 地址或地址段，例如 `203.0.113.7` 或 `198.51.100.0/24`，每个网站最多 200 个。被封禁的访客会得到 HTTP 403。

点击 **保存**。两者都可以单独工作，不需要 Web 应用防火墙，并且适用于所有类型的网站，包括反向代理网站。同一个标签页上还有 **密码保护**，见 [网站](./websites#suspend-redirect-or-password-protect-a-website)。

### 恶意软件扫描 {#malware-scan}

扫描器会在网站的文件中查找 Web shell、后门、隐藏代码和注入的脚本。在你隔离文件之前，它不会改动任何东西。

1. 前往 **网站** → 你的网站 → **恶意软件扫描**。
2. 点击 **立即扫描**。扫描在后台运行，并带有实时日志。

扫描器读取网站的文件夹，例如 `/var/www/example.com`。它会跳过 `.git` 文件夹和超过 5 MB 的文件，并且不跟随符号链接。它检查 PHP 文件（以及其他名称的文件中的 PHP 代码）、JavaScript 和 HTML 文件，以及图片。

| 发现 | 严重程度 |
|---|---|
| 已知的 Web shell | 严重 |
| 运行访客发送的代码 | 严重 |
| 调用访客指定的函数 | 严重 |
| 运行访客发送的 shell 命令 | 严重 |
| 运行隐藏（编码）的代码 | 高 |
| 解码访客发送的隐藏数据 | 高 |
| 用访客的输入构造函数 | 高 |
| 允许访客选择文件存放位置的上传程序 | 高 |
| 混淆的脚本注入 | 高 |
| 隐藏在图片中的 PHP 代码 | 高 |
| 通过 preg_replace /e 执行代码 | 待查 |
| 长段编码数据，旁边有解码它的代码 | 待查 |
| 高度混淆的文本，旁边有运行它的代码 | 待查 |
| 上传文件夹中的 PHP 文件 | 待查 |

每项发现都显示文件、行号和一小段摘录。上传文件夹中只包含注释的 PHP 文件（例如 WordPress 写着“Silence is golden”的 `index.php`）不会被报告。

面板保留每个网站最近一次的扫描结果。它不按计划扫描：需要时请自己启动扫描。

### 隔离和恢复 {#quarantine-and-restore}

点击某项发现旁边的 **隔离**，把文件移出网站，放到只有 root 能读取的 `/var/lib/panel-quarantine` 中。面板会记录文件的属主和权限。

在 **已隔离的文件** 下：

- **恢复** 把文件放回原来的位置，带着它原来的属主和权限。如果那个路径上现在已有文件，或者文件夹已不存在，恢复会被拒绝。
- **删除** 在你确认后彻底删除该文件。

删除网站时，它的已隔离文件也会被删除。

::: warning
隔离网站需要的文件（例如插件文件）可能会让网站无法正常工作。请先查看摘录；如果是误报，请恢复该文件。
:::

### 用 ClamAV 扫描 {#scan-with-clamav}

ClamAV 是一个可选的附加扫描引擎。

1. 在 **软件** 页面安装 **ClamAV 杀毒软件**。安装后的几分钟内，它的病毒库会在后台下载。
2. 在 **恶意软件扫描** 上，勾选 **同时用 ClamAV 扫描（较慢，需要约 1.4 GB 可用内存）**，然后点击 **立即扫描**。

ClamAV 扫描时需要约 1.4 GB 可用内存，所以适合 2 GB 或以上内存的服务器。如果可用内存不够，面板会跳过 ClamAV，并在报告中说明。ClamAV 以最低的 CPU 优先级运行，并跳过超过 25 MB 的文件。它的发现标为高。

### 国家/地区拦截和文件锁定 {#country-blocking-and-file-lock}

每个网站还有 **国家/地区拦截**，可以拒绝来自你列出的国家/地区的访客，或者只放行这些国家/地区；以及 **文件锁定**，它让网站的代码对它的 PHP 和 SFTP 账户只读，只有它必须写入的文件夹除外。见 [国家/地区拦截与文件锁定](./website-protection)。
