# 网站

在 Nefo 中，网站是由服务器唯一的 Web 服务器（Nginx、Apache 或 OpenLiteSpeed）提供服务的一个域名：PHP 网站、静态网站、代理后的应用（Node.js、Python 或 Java），或者到另一个地址的反向代理。每个网站都有自己的 Linux 用户、文件夹和可选的 SFTP 账户，并且可以在它的设置中克隆、备份或删除。

本页介绍 Web 服务器、如何创建网站，以及网站的每一项设置：域名、PHP、重写规则、访问选项、SFTP、流量统计、日志、克隆和删除。证书有单独的页面：[SSL 证书](./ssl)，[国家/地区拦截和文件锁定](./website-protection) 也是。

## 应该选择哪个 Web 服务器？ {#choose-the-web-server}

一台服务器同一时间只运行一个 Web 服务器，Nefo 会为它配置每个网站。添加第一个网站之前，**网站** 页面会请你选择一个：

| Web 服务器 | 适合的情况 | 空闲时的内存 |
|---|---|---|
| Nginx | 你的网站不需要 `.htaccess` 文件。它是最轻量的选择。 | 约 15 MB |
| Apache | 你的网站依赖 `.htaccess` 文件，例如 WordPress 插件或从共享主机迁来的网站。 | 约 40 MB |
| OpenLiteSpeed | 你想要 `.htaccess` 文件中的重写规则，以及 WordPress 的 LiteSpeed Cache 插件。它还支持 HTTP/3。 | 约 26 MB |

安装方法：

1. 打开 **网站**。
2. 在 **安装 Web 服务器** 下，选择 Nginx、Apache 或 OpenLiteSpeed。
3. 点击 **安装 Nginx**（按钮上显示的是你选择的服务器）。

Nefo 会安装 Web 服务器，以及发行版自带的 PHP 版本和 PHP-FPM，然后在防火墙（ufw）中开放 80 和 443 端口，在 OpenLiteSpeed 上还会为 HTTP/3 开放 443/udp。这需要一到三分钟。OpenLiteSpeed 来自 LiteSpeed 自己的软件源，它的 WebAdmin 控制台保持关闭。

三种 Web 服务器都为每个网站在单独的 PHP-FPM 池中运行 PHP。只有 Nginx 能限制每位访客的请求数；其他设置在三者上都一样。

### 换成另一个 Web 服务器 {#switch-to-another-web-server}

Nefo 无法把现有的网站迁到另一个 Web 服务器，因为每个网站的配置都是为已安装的那个写的。要更换：

1. 删除所有网站（见 [删除网站](#delete-a-website)）。如果还需要它们，请先备份：见 [备份](./backups)。
2. 打开 **软件**，找到 **Nginx、Apache 或 OpenLiteSpeed** 卡片。
3. 在当前的 Web 服务器上点击 **卸载**，输入它的名称（`nginx`、`apache` 或 `openlitespeed`）并确认。
4. 在你想要的 Web 服务器上点击 **安装**。

卸载会保留 `/var/www` 中的网站文件夹、证书和 Let's Encrypt 账户。PHP 仍然保持安装。Adminer 会被移除，因为它需要 Web 服务器；Nefo 为网站添加的防火墙规则（80 和 443 端口）会被删除。

服务器上已安装另一个 Web 服务器时（即使是你自己安装的），Nefo 也会拒绝安装 Web 服务器：两者都需要 80 和 443 端口。这时 **软件** 页面会把它显示为“已安装，面板未使用”。请先移除它。

## 创建网站 {#create-a-website}

1. 把域名的 DNS A 记录指向服务器的 IP 地址，例如 `203.0.113.10`。
2. 打开 **网站**，点击 **添加网站**。
3. 在 **域名** 中输入名称，不带 `http://` 或 `www.`，例如 `example.com`。
4. 如果网站也要响应 `www`，保持勾选 **同时响应 www.example.com**。域名只有两部分时（例如 `example.com`），Nefo 会替你勾选。
5. 选择 **类型**（见下表）。
6. 点击 **创建网站**。

Nefo 随后会显示“example.com 已就绪。请把文件上传到 /var/www/example.com/public。”在你替换之前，会由一个欢迎页面响应。

| 类型 | 网站做什么 |
|---|---|
| **PHP 8.3**（每个已安装的 PHP 版本一项） | 提供你的文件，并用该 PHP 版本运行 `.php` 文件。 |
| **静态（仅 HTML）** | 提供 HTML、CSS、JavaScript 和其他文件。没有 PHP。 |
| **代理后的应用（Node.js、Python、Java…）** | 把每个请求转发给一个监听这台服务器某个端口的程序。 |
| **反向代理到另一个地址** | 把每个请求转发到你给出的地址：另一台服务器，或者这台服务器上不由 Nefo 运行的服务。见 [反向代理网站](#reverse-proxy-websites)。 |

网站创建后不能更改类型：静态网站不能变成 PHP 网站，应用网站不能变成 PHP 网站或静态网站，反向代理网站也不能变成其他类型。请改为创建一个新网站。要安装 WordPress 或其他应用，见 [应用商店](./apps)。Docker 应用会在那里得到自己的网站。

Nefo 会拒绝无效的域名（国际化域名请用 punycode 书写，即 `xn--…`）、已被另一个网站使用的名称，以及文件夹已存在于 `/var/www` 中的域名。

### 应用网站（Node.js、Python、Java） {#app-websites-node-js-python}

对于 **代理后的应用（Node.js、Python、Java…）** 类型，表单还会询问两项：

- **应用监听的端口（127.0.0.1）**：1024 到 65535 之间的一个端口。Nefo 会拒绝面板自己的端口、3306（MariaDB）、6379（Redis）、7809（Git Webhook 监听程序），以及另一个应用网站使用的端口。
- **启动命令（可选）**：一行，最多 1000 个字符，例如 `node server.js`。Nefo 以网站的 Linux 用户身份在网站的 `app` 文件夹中运行它，并设置 `PORT`、`HOST=127.0.0.1` 和 `NODE_ENV=production`。它作为 systemd 服务 `panel-app-<user>.service` 运行，停止 3 秒后会重新启动。如果程序以其他方式启动（例如在 Docker 中），请让命令留空。

把你的代码放到 `/var/www/example.com/app` 中，可以通过 [SFTP](#sftp-access)，或者用 [Git 部署](./git-deploy)（它会把应用网站部署到这个文件夹）。然后在网站的设置中：

1. 在 **运行环境** 标签页上，选择 **运行环境**：**服务器默认（/usr/local/bin 中的 node）**、你在 **软件** 页面安装的某个 Node.js 版本、Python（`app/.venv`，需要在 **软件** 页面安装 Python），或你在 **软件** 页面安装的某个 Java 版本，例如显示为“Java 21 (OpenJDK 21.0.9)”。同一个标签页可以更改 **启动命令（可选）**。点击 **保存**。
2. 在 **概览** 标签页的 **应用程序** 下，点击 **安装依赖**。对于 `package.json`，Nefo 会运行 `npm ci`（没有 `package-lock.json` 时运行 `npm install`）。对于 Python，它会创建虚拟环境 `app/.venv`，并用 pip 安装 `requirements.txt`。它以网站用户的身份运行，最多 20 分钟。
3. 点击 **重启**（或 **启动**），带着依赖运行应用。

网站有启动命令时，会出现 **应用程序** 卡片。卡片上还有 **停止** 和 **应用日志**。在 **反向代理** 标签页上可以更改端口。Web 服务器把请求转发到该端口上的 `127.0.0.1`，并在 `X-Real-IP` 和 `X-Forwarded-For` 中带上访客的地址，WebSocket 连接也可以工作。如果要转发到另一台服务器，或者这台服务器上不由 Nefo 启动的服务，请改为创建 [反向代理网站](#reverse-proxy-websites)。

存在 Java 应用网站后，网站列表中会在其他类型的筛选器旁边出现 **Java** 筛选器。

#### Java 应用网站 {#java-app-websites}

对于 Java 程序，把 **启动命令（可选）** 设为启动它的命令，例如 `java -jar app.jar`，并把 `app.jar` 放到 `/var/www/example.com/app` 中。在 **运行环境** 中选择 Java 版本。请先在 **软件** 页面安装 Java（见 [Java](./software#java)）。

- 应用的服务会得到该版本的 `JAVA_HOME`，它的 `bin` 文件夹排在 `PATH` 的最前面，所以 `java` 就是这个版本。除了每个应用网站都有的 `PORT` 和 `HOST=127.0.0.1`，它还会得到 Spring Boot 读取的 `SERVER_PORT`（同一个端口）和 `SERVER_ADDRESS=127.0.0.1`。这样，Spring Boot 应用不需要自己的设置，就能监听正确的端口，并且只在这台服务器上监听。其他框架读取 `PORT`，或者需要在它们自己的设置中写上它。
- 选择 Java 运行环境时会出现 **内存限制（MB）**。它通过 `JDK_JAVA_OPTIONS` 设置 Java 的最大堆（`-Xmx`），范围为 32 到 65536 MB，启动命令运行的每个 `java`（包括启动脚本）都会读取它。留空时，Java 最多使用服务器内存的四分之一。进程占用的内存会比它的堆稍多一些。Java 会在 **应用日志** 的开头打印 `NOTE: Picked up JDK_JAVA_OPTIONS: -Xmx512m`。
- 网站的 [Git 部署](./git-deploy) 脚本以同样的 `JAVA_HOME` 和 `PATH` 运行，所以 `./mvnw package` 或 `./gradlew build` 会用网站的 Java 版本构建。内存限制不作用于它们。
- Java 网站不提供 **安装依赖**：请在部署脚本中，或在上传之前构建 jar。
- 有网站使用的 Java 版本不能在 **软件** 页面卸载。请先选择其他运行环境，或删除该网站。

## 反向代理网站 {#reverse-proxy-websites}

反向代理网站会把每个请求转发到你选择的地址：另一台服务器上的网站或应用，或者这台服务器上不由 Nefo 运行的服务，例如你自己启动的程序，或你自己的 Compose 项目中的容器。这个网站和其他网站一样，有自己的域名、HTTPS 证书、访问选项和 Web 防火墙。它适用于 Nginx、Apache 和 OpenLiteSpeed。

1. 打开 **网站**，点击 **添加网站**。
2. 输入 **域名**，选择类型 **反向代理到另一个地址**。
3. 在 **转发到** 中输入地址：`http://` 或 `https://`、主机名或 IP 地址、可选的端口和可选的路径，例如 `http://198.51.100.7:8080` 或 `https://backend.example.com/app`。
4. 选择 **发送的 Host 请求头**：这个网站的域名，或上游的主机名。
5. 点击 **创建网站**。

Nefo 会显示“example.com 已创建。域名指向这台服务器后，它会转发到 …”。地址会带着端口保存，所以 `https://backend.example.com/app` 会显示为 `https://backend.example.com:443/app`。

请求的路径接在地址的路径之后：对于 `http://198.51.100.7:8080/app`，访问 `https://example.com/shop?page=2` 会到达 `http://198.51.100.7:8080/app/shop?page=2`。

### 选项 {#the-options}

在网站的 **反向代理** 标签页上更改它们，然后点击 **保存**。新建的反向代理网站默认开启 WebSocket 和 X-Forwarded-\* 请求头，超时时间为 60 秒。

| 选项 | 作用 |
|---|---|
| **转发到** | 地址，同上。 |
| **发送的 Host 请求头** | 网站的域名：发送访客请求的域名，大多数代理后的应用都期望这样。**上游的主机名**：发送上游自己的名称（端口不是 80 或 443 时带上端口），适用于只响应自己名称的服务器。这时，重定向（`Location`）中上游自己的地址会被改为网站的地址。 |
| **WebSocket** | 转发 WebSocket 连接（聊天、实时更新、终端）。 |
| **X-Forwarded-\* 请求头** | 告诉上游访客的地址，以及请求是否通过 HTTPS 发来：`X-Forwarded-For`、`X-Forwarded-Proto`、`X-Forwarded-Host` 和 `X-Real-IP`。关闭时，这些请求头会被删除，包括访客自己发送的。 |
| **超时时间（秒）** | 上游最多可以用多长时间响应，5 到 3600 秒。连接本身必须在 30 秒内建立（如果超时时间更短，则以它为准）。上游更慢时，访客会看到错误页面：Nginx 为 504，Apache 为 502。 |
| **忽略上游的证书（自签名）** | 地址为 `https://` 时显示。接受上游的任何证书。 |

::: warning
**忽略上游的证书（自签名）** 会让到上游的连接保持加密，但任何能拦截它的人都可以冒充上游。只对你自己网络中使用自签名证书的上游使用它。
:::

没有这个选项时，Nginx 和 Apache 会根据服务器的证书颁发机构（`/etc/ssl/certs/ca-certificates.crt`）检查 `https://` 上游的证书，检查的名称是 Host 请求头中的名称：网站的域名，或者你选择的上游主机名。自签名或过期的证书会让访客看到错误页面（Nginx 为 502，Apache 为 500）。

### Nefo 会拒绝什么 {#what-nefo-refuses}

- 不是 `http://` 或 `https://` 加主机名或 IP 地址、可选端口（1 到 65535）和路径的地址，例如带有用户名、查询字符串（`?`）、片段（`#`）、空格、路径中有 `..` 的地址，或者 `0.0.0.0` 和 `::` 这两个地址；
- 找不到的主机名（“找不到主机名 …。请检查，或改用其 IP 地址。”）；
- 面板本身：这台服务器上面板的端口或 `7809`（Git Webhook 监听程序），无论你写的是 `127.0.0.1`、`localhost`、服务器自己的某个 IP 地址，还是指向它们的名称；
- 这台服务器上的 80 和 443 端口：网站会转发给 Web 服务器自己；
- 小于 5 或大于 3600 的 **超时时间（秒）**。

### 值得了解 {#good-to-know}

- 使用 Nginx 时，主机名在请求到来时才用 `/etc/resolv.conf` 中的 DNS 服务器查询，所以开机时解析不了的名称永远不会妨碍 Nginx 启动。这些查询不读取 `/etc/hosts`：对于只有 `/etc/hosts` 知道的名称，请使用它的 IP 地址。
- HTTPS、重定向到 HTTPS 和 HSTS 与其他网站一样：见 [SSL 证书](./ssl)。
- **暂停**、**重定向**、密码保护、封禁的 IP 地址、速率限制、[国家/地区拦截](./website-protection#block-or-allow-countries) 和 Web 防火墙都在请求到达上游之前起作用。
- 重写规则、自定义 404 页面、防盗链和文件锁定的标签页不适用于反向代理网站，会被隐藏。你自己的指令（Web 服务器配置标签页）仍然有效。
- 网站仍然有它的文件夹 `/var/www/example.com` 和 Linux 用户，供 SFTP 和备份使用，但它不提供这些文件。

### 使用 OpenLiteSpeed 时 {#with-openlitespeed}

OpenLiteSpeed 的转发方式与 Nginx 和 Apache 不同。**反向代理** 标签页会在一条说明中提到这一点，那里也不显示 **忽略上游的证书（自签名）**：

- 它从不检查 `https://` 上游的证书：不开这个选项，自签名证书也能用。
- 不应用 **超时时间（秒）**：OpenLiteSpeed 对代理的响应没有时间限制。
- 它不在 `X-Forwarded-For` 中发送访客的地址：它发送 `X-Forwarded-Host`，HTTPS 请求还会发送 `X-Forwarded-Proto`。关闭 **X-Forwarded-\* 请求头** 时，Nefo 会删除 `X-Forwarded-For`（`X-Real-IP` 总是会被删除）；OpenLiteSpeed 仍会发送 `X-Forwarded-Host`。
- WebSocket 连接到达上游时不带地址的路径（是 `/live`，而不是 `/app/live`），并且不适用于 `https://` 上游。
- 路径、上游的 Host 请求头、密码和封禁地址与其他 Web 服务器一样。

## 打开网站的设置 {#open-a-website-s-settings}

在列表中点击域名，或点击该行末尾的 **设置**。设置会在一个面板中打开，标签页分为四组。有些标签页只对部分网站显示：

| 分组 | 标签页 |
|---|---|
| **基础** | **概览**、**域名**、**PHP**（PHP 网站）、**运行环境**（应用网站）、**反向代理**（反向代理网站） |
| **安全** | **SSL / HTTPS**、**Web 防火墙（WAF）**、**阻止访问**、**国家/地区拦截**、**文件锁定**（Docker 应用和反向代理网站没有）、**防盗链**（反向代理网站没有）、**恶意软件扫描** |
| **配置** | **重写规则**（PHP 和静态网站）、**页面缓存**（Nginx 和 OpenLiteSpeed 上的 PHP 网站）、**Nginx 配置**（以你的 Web 服务器命名）、**重定向**、**反向代理**（应用网站：端口）、**404 页面**（反向代理网站没有） |
| **运维** | **WordPress**（WordPress 网站）、**Git 部署**（Docker 应用没有）、**SFTP**、**备份**、**监控**、**流量**、**日志**、**到期与暂停** |

**概览** 标签页显示网站的 **文件夹**（带 **在文件管理中打开**）、它的 **Linux 用户**、域名、PHP 版本或运行环境、Web 服务器、HTTPS 和防火墙的状态。点击 **添加备注** 可以写一行（最多 200 个字符）显示在列表中域名下方的文字，例如客户名称。

## 网站的 Linux 用户和文件夹 {#the-website-s-linux-user-and-folders}

每个网站都有自己的 Linux 用户，所以一个被入侵的网站无法读取或修改其他网站。用户名来自域名：`example.com` 变为 `example_com`，`blog.example.com` 变为 `blog_example_com`（名称被占用时加 `_2`、`_3`……）。该用户没有密码，也没有 shell，除非你开启 [SFTP](#sftp-access)，否则不能通过 SSH 登录。网站的 PHP 和它的应用以这个用户运行，PHP 只能打开网站文件夹内的文件。

| 路径 | 存放什么 |
|---|---|
| `/var/www/example.com/public` | Web 文件夹（文档根目录）。你的网站文件放在这里。 |
| `/var/www/example.com/logs` | `php-error.log`，网站的 PHP 错误。 |
| `/var/www/example.com/tmp` | PHP 的临时文件、正在上传的文件和会话。 |
| `/var/www/example.com/app` | 仅应用网站：程序的代码。 |
| `/var/log/nginx/example.com.access.log` 和 `.error.log` | Web 服务器为该网站写的日志（Apache 上为 `/var/log/apache2`，OpenLiteSpeed 上为 `/var/log/openlitespeed`）。 |
| `/var/lib/nefo/certs/example.com` | 网站的证书。 |
| `/var/cache/nginx/nefo/example.com` | 仅 Nginx：开启时的 [页面缓存](#page-cache)。 |

Nefo 写入的 Web 服务器和 PHP-FPM 文件以“Managed by Nefo. Do not edit”（由 Nefo 管理，请勿编辑）开头。Nefo 会重写它们，所以请在面板中修改。

## 域名和别名 {#domains-and-aliases}

在 **域名** 标签页上，**额外域名** 列出打开同一个网站的其他名称，每行一个，例如 `www.example.com`。一个网站最多可以有 20 个。每个名称都必须指向这台服务器，并且只能属于一个网站。

`*.example.com` 这样的通配符会响应每个子域名。它的证书需要通过 Cloudflare 进行 DNS 验证：见 [SSL 证书](./ssl)。

如果域名的 DNS 在 Cloudflare，同一个标签页上的 **将 DNS 指向此处…** 会在预览之后，为所有这些名称创建或更新 A（和 AAAA）记录：见 [DNS（Cloudflare）](./dns#point-a-website-to-this-server)。

如果网站有 HTTPS，而你更改了它的名称，Nefo 会提示“域名已更改。请获取新证书，让 HTTPS 覆盖所有域名。”点击 **续期证书**。

## PHP 版本和设置 {#php-version-and-settings}

PHP 网站的 **PHP** 标签页有以下设置：

| 设置 | 默认值 | 允许的值 |
|---|---|---|
| **PHP 版本** | 创建时选择的版本 | 任何已安装的 PHP 版本 |
| **内存限制（MB）** | 256 | 32 到 4096 |
| **最大上传（MB）** | 64 | 1 到 4096（Web 服务器的请求大小限制随之调整） |
| **脚本最长运行时间（秒）** | 300 | 10 到 3600 |
| **PHP 工作进程** | 5 | 1 到 200 |
| **工作进程模式** | **按需启动（节省内存）** | 或 **保持部分就绪（繁忙网站更快）** |

**PHP 工作进程** 是网站的 PHP 同时处理多少个请求。每个工作进程最多可以使用内存限制那么多的内存，所以工作进程数 × 内存限制应该放得进服务器的内存。

为了安全，Nefo 在每个网站上禁用 `exec`、`passthru`、`shell_exec`、`system`、`proc_open`、`popen` 和 `pcntl_exec`，因为它们会让被入侵的网站在服务器上运行程序。只有应用确实需要时，才在 **允许为安全起见而禁用的函数** 下勾选某一个。

点击 **保存**。如果 PHP-FPM 或 Web 服务器拒绝结果，Nefo 会放回之前的设置。要安装其他 PHP 版本或扩展、ionCube Loader，或者更改 `php.ini`，见 [软件](./software)。

## 重写规则和你自己的指令 {#rewrite-rules-and-your-own-directives}

在 **重写规则** 标签页上，**重写规则** 提供常见应用的现成规则：PHP 网站有 **默认（前端控制器：index.php 或 index.html）**、WordPress、Laravel、Symfony、CodeIgniter 4、Drupal、Joomla、OpenCart、Nextcloud、Moodle 和 phpBB，任何网站都可以用单页应用和静态网站（简洁 URL）。标签页会显示你所选预设的规则。在 Nginx 上，预设会替换默认的 `location /` 块。在 Apache 上，网站自己的 `.htaccess` 文件可能会替换预设的前端控制器；在 OpenLiteSpeed 上，前端控制器在网站的 `.htaccess` 规则之后运行。在这两者上，预设中的保护规则都无法被 `.htaccess` 文件撤销。

**静态网站（简洁 URL）** 提供不带 `.html` 结尾的页面，正如 VitePress（使用 `cleanUrls`）这样的网站生成器所链接的那样：`/docs/install` 提供 `docs/install.html`，`/docs/` 提供 `docs/index.html`。其他文件按原样提供，不存在的页面仍然返回 404。

phpBB 预设适用于你自己安装的 phpBB。它把不是文件的地址发给 phpBB 的 `app.php`，并且从不提供 phpBB 的设置文件（`config.php`、`common.php`）、它的 `cache`、`files`（附件）、`store`（备份）、`includes`、`phpbb` 和 `vendor` 文件夹，以及 `images/avatars/upload`：这些都返回 403。

下一个标签页以你的 Web 服务器命名，例如 **Nginx 配置**。在 **Nginx 指令**（或 **Apache 指令**、**OpenLiteSpeed 指令**）中，你可以用 Web 服务器的语法添加你自己的指令，最多 32 KB：

- Nginx 把它们加在网站的 `server` 块内、重写规则之前。
- Apache 把它们加在网站的 `VirtualHost` 块末尾。
- OpenLiteSpeed 把它们加在网站的 `virtualHost` 块末尾。

在改动任何东西之前，Web 服务器会检查新配置。如果它拒绝，Nefo 会显示错误，网站继续像以前一样工作。点击 **显示完整配置文件** 可以查看 Nefo 生成的内容。

关于 `.htaccess` 文件：Apache 会读取它们。OpenLiteSpeed 只使用其中的重写规则，Nefo 会在它们变化后几秒内把规则复制到网站的配置中。Nginx 会忽略它们。

## 页面缓存 {#page-cache}

在 Nginx 上，PHP 网站的 **页面缓存** 标签页会为它开启 Nginx 的 FastCGI 缓存：Nginx 会保存 PHP 生成的每个页面，并再次提供它，而不必运行 PHP 或查询数据库。打开 **页面缓存** 开关。

- 页面保存 10 分钟，不存在的页面（404）保存 1 分钟。如果 PHP 出错或不再响应，Nginx 会提供它还保存着的最后一份副本。
- 以下情况 Nginx 每次都会询问 PHP：GET 和 HEAD 以外的请求（表单）、带 `?` 的地址、带登录或购物车 Cookie 的访客（WordPress 的 `wordpress_logged_in_`、`wp-postpass_`、`comment_author_`，WooCommerce 的 `woocommerce_items_in_cart`、`wp_woocommerce_session_`，以及 PHP 自己的 `PHPSESSID`），以及 `/wp-admin/`、`/wp-login.php`、`/xmlrpc.php`、`/wp-json/`、`/wp-cron.php`、`/cart/`、`/checkout/` 和 `/my-account/` 下的页面。PHP 标为私有、或带 Cookie 发送的页面也不会保存。
- 每个网站在 `/var/cache/nginx/nefo/example.com` 中有自己最多 256 MB 的缓存。一小时内没人请求的页面会被丢弃。

修改页面后，点击 **清除缓存**：所有访客会立即得到新版本。否则，未登录的访客可能在最多 10 分钟内看到旧页面。关闭缓存或删除网站会删除它的文件夹。

要检查它是否工作，在隐私窗口中打开一个页面两次，或者运行两次 `curl -sI https://example.com/`：`X-Cache-Status` 响应头会先显示 `MISS`，再显示 `HIT`（上面那些请求为 `BYPASS`）。静态文件没有这个响应头：Nginx 本来就直接提供它们。

在 OpenLiteSpeed 上，标签页会说明它内置了自己的页面缓存 LSCache：WordPress 请安装 LiteSpeed Cache 插件，其他应用用 `.htaccess` 中的缓存规则开启它。在 Nefo 中，Apache 没有页面缓存，也没有这个标签页。

## 暂停、重定向或用密码保护网站 {#suspend-redirect-or-password-protect-a-website}

**暂停。** 关闭列表中 **运行** 列的开关，或 **概览** 标签页上的 **网站运行中**。访客随后会得到 HTTP 503 和“This website is temporarily unavailable.”（此网站暂时无法访问）。文件和设置都会保留，证书也会继续续期。要暂停多个网站，勾选它们，在 **批量操作** 下选择 **暂停**，然后点击 **应用**；**恢复运行** 会让它们重新运行。

**重定向。** 在 **重定向** 标签页上，勾选 **将所有请求重定向到另一个地址**，并输入 **地址**，例如 `https://example.org`。这是保留路径的永久重定向（301）：`/page` 会跳转到新地址后接 `/page`。重定向只在网站运行时有效。

**密码。** 在 **阻止访问** 标签页的 **密码保护** 下，勾选 **使用密码保护**，并输入 **用户名** 和 8 到 72 个字符的 **密码**。浏览器会在显示网站之前要求输入它们。之后密码留空表示保留当前的密码。Let's Encrypt 验证和 Git Webhook 仍然可以访问网站。

同一个标签页还可以封禁 IP 地址，并在 Nginx 上限制每位访客的请求数：见 [安全](./security#rate-limit-and-blocked-addresses)。要拦住整个国家/地区，见 [国家/地区拦截](./website-protection#block-or-allow-countries)。

## 自定义 404 页面和防盗链 {#custom-404-page-and-hotlink-protection}

**404 页面。** 在 **404 页面** 标签页上，勾选 **使用我自己的 404 页面**，并把你的页面上传为 `public/404.html`。由你的应用自己处理的页面（例如 WordPress 或 Laravel 的页面）保留它们自己的 404 页面。

**防盗链。** 在 **防盗链** 标签页上，勾选 **图片和媒体防盗链**。这样，其他网站嵌入你的 `jpg`、`jpeg`、`png`、`gif`、`webp`、`avif`、`svg`、`ico`、`bmp`、`mp4`、`webm`、`mp3`、`ogg` 和 `pdf` 文件时会得到 HTTP 403。你自己的网站、搜索引擎（Google、Bing、DuckDuckGo 和 Yahoo）以及直接打开文件的访客总能得到它。在 **允许显示这些文件的其他网站** 下最多可以列出 20 个其他网站，每行一个。

## 到期日期 {#expiry-date}

在 **到期与暂停** 标签页上，设置 **到期日期**，然后点击 **保存**。网站在那一天结束之前（服务器时间）都能工作；之后 Nefo 会自动暂停它。它每小时检查一次。点击 **永不** 可以去掉日期。在最后 7 天内，列表会在域名下方显示“到期”和日期。这对付费到某个日期的客户网站很方便。

同一个标签页上有 **暂停此网站**，可以立即暂停网站。

## SFTP 访问 {#sftp-access}

SFTP 让你或客户用 FileZilla、WinSCP 或任何 SFTP 应用上传文件。这样上传的文件属于网站用户，这正是应该的。它需要安装 OpenSSH 服务器。

1. 打开网站的 **SFTP** 标签页，勾选 **允许此网站通过 SFTP 登录**。
2. 选择账户的登录方式：
   - **生成新的强密码**
   - **自己设置密码（至少 12 个字符）**，最多 128 个字符
   - **保留当前密码**（已设置密码时）
   - **不设密码：只能用 SSH 密钥登录**
3. 可选：粘贴 **SSH 公钥（可选）**，每行一个，格式与 `authorized_keys` 相同，最多 50 个。`command=` 这样的选项会被去掉。
4. 点击 **保存**。生成的密码只显示一次：请立即复制。
5. 用显示的 **主机**、**端口**、**用户名** 和 **文件夹** 连接。主机是你打开面板时使用的地址，端口是服务器的 SSH 端口。标签页还会显示完整的地址，例如 `sftp://example_com@panel.example.com/var/www/example.com`。

该账户被限制在网站的文件夹内。它只能看到 `/var/www/example.com`，路径与面板和 PHP 中相同，并且不能运行命令或转发端口。服务器的密码策略可能会拒绝你选择的密码；这时 Nefo 会说明原因。网站的 [文件被锁定](./website-protection#lock-a-website-s-files) 期间，SFTP 账户只能更改可写文件夹。

关闭 SFTP 会删除密码和密钥，并结束已打开的会话。

## 流量统计 {#traffic-statistics}

**流量** 标签页读取 Web 服务器为该网站写的访问日志。选择 **时间段**：**今天**、**7 天**、**14 天** 或 **30 天**。它显示：

- **请求数**、**访客**（不同的 IP 地址）、**带宽**、**错误率**（4xx 和 5xx）和 **机器人**
- 每小时或每天的请求数和访客数
- **热门页面**、**主要 IP 地址**、**来源**、**浏览器** 以及 **机器人和脚本**

证书验证和面板自己的 [监控](#monitoring) 检查不计入。服务器大约保留 14 天的日志，所以更早的流量无从得知。对于非常大的日志，只读取最新的 5,000,000 行。网站列表中的 **7 天访问量** 列也来自同样的日志。

## 日志 {#logs}

**日志** 标签页显示以下日志的最新几行：

- **访问日志（Nginx）** 和 **错误日志（Nginx）**（以你的 Web 服务器命名）
- **PHP 错误**，适用于 PHP 网站（`/var/www/example.com/logs/php-error.log`）
- **应用日志**，适用于应用网站和 Docker 网站

## 监控 {#monitoring}

**监控** 标签页每隔几分钟检查一次网站是否响应，不响应时会给你发送告警。打开 **监控此网站**；第一次检查会立即运行。

面板像任何访客一样，通过 DNS 请求网站的公开地址；网站有证书时使用 `https://`，否则使用 `http://`。所以错误的 DNS 记录、Cloudflare 错误页面或过期的证书也会被发现。跳转到网站自己域名的重定向（例如 `http://` 到 `https://`，或到 `www.`）会被跟随。跳转到其他域名的重定向算作有响应。

| 设置 | 作用 | 默认值 |
|---|---|---|
| **检查间隔** | 多久检查一次：每分钟，或每 2、5 或 10 分钟 | 每 5 分钟 |
| **路径** | 要请求的页面，例如 `/health`；可以带查询字符串 | `/` |
| **页面必须包含的文本** | 可选；不区分大小写 | 空 |
| **将 404 等 4xx 响应计为宕机** | 4xx 响应算作检查失败 | 关闭 |

以下情况检查失败：

- 10 秒内没有响应、域名无法解析、连接被拒绝，或者证书已过期、不受信任或属于另一个域名
- 响应是 500 或以上的 HTTP 错误。4xx 响应算作正常，除非你把 4xx 响应计为宕机
- 页面的前 256 KB 中没有页面必须包含的文本

连续 2 次检查失败后，网站状态为 **宕机**；一次检查成功后恢复正常。这时面板会向 **设置** → **告警** 中的每个渠道发送告警（见 [告警](./mail-alerts#alerts)）：

- 宕机时，附上原因，例如“example.com is down (HTTP 502, 2 checks in a row)”（example.com 宕机，HTTP 502，连续 2 次检查失败），只要它一直宕机，每 6 小时再发一次
- 恢复正常时，附上宕机了多长时间
- 它提供的证书在 14 天内到期时，每天最多一次

标签页显示状态和上次检查、24 小时和 7 天的可用率、平均响应时间、最近 24 小时响应时间的图表，以及最近的失败及其原因。响应时间计算到响应头到达为止，包括建立连接的时间。在网站列表中，宕机的受监控网站会在它的 **运行** 列中以红色显示 **宕机**，铃铛中也会列出它。

- 检查发送的用户代理为 `Nefo-Monitor/1.0`。它们不计入 **流量** 标签页。
- 结果保留 7 天。删除网站会删除它们。
- 已暂停的网站不检查。
- 检查在这台服务器上运行。它们无法报告整台服务器宕机，也无法报告访客与服务器之间网络上的问题：要监控这些，请添加一个外部监控服务。

## Web 防火墙、恶意软件扫描、国家/地区拦截、文件锁定和备份 {#web-firewall-malware-scan-country-blocking-file-lock-and-backups}

- **Web 防火墙（WAF）**：为这个网站使用 ModSecurity 加 OWASP Core Rule Set：**关闭**、**仅检测：记录攻击，不拦截** 或 **拦截攻击**。请先在 **软件** 页面安装防火墙。见 [安全](./security#web-application-firewall)，那里也介绍了 **恶意软件扫描** 标签页。
- **国家/地区拦截**：拒绝来自某些国家/地区的访客，或者只放行某些国家/地区。**文件锁定**：让网站的代码对它的 PHP 和 SFTP 账户只读，只有它必须写入的文件夹除外。见 [国家/地区拦截与文件锁定](./website-protection)。
- **备份**：**立即备份**，或设置 **每天 03:00** 的计划备份。见 [备份](./backups)。

## 克隆网站 {#clone-a-website}

**克隆** 会把网站复制到一个新域名：用现有网站开始一个新网站，或者在副本上尝试修改。它适用于 PHP 网站、静态网站、反向代理网站、应用网站（Node.js、Python、Java），以及 [应用商店](./apps) 中的 Docker 应用。

1. 打开网站的 **概览** 标签页，在 **克隆此网站** 下点击 **克隆…**。
2. 输入 **副本的域名**。
3. 保持勾选 **复制与此网站关联的数据库**，把它们也复制过去。WordPress（它的数据库总会被复制）和 Docker 应用（它的数据总会被复制）不显示这个复选框。
4. 点击 **克隆**。复制期间网站会继续运行，复制作为带日志的任务运行。复制 Docker 应用的数据时，它会短暂停止。
5. 把新域名的 DNS 指向这台服务器，然后在它的 **SSL / HTTPS** 标签页上开启 HTTPS。副本一开始使用 `http://`。

### PHP 网站、静态网站和反向代理网站 {#php-static-and-reverse-proxy-websites}

副本会得到：

- 一个同样类型的新网站（相同的 PHP 版本、静态，或者以相同选项反向代理到相同的地址），有它自己的 Linux 用户，以及相同的应用、PHP 设置、重写规则和你自己的指令。在你的指令中，旧网站的文件夹会被替换为新文件夹；
- 网站文件夹 `/var/www/example.com` 的副本，属于新用户，不含 `logs`、`tmp` 和 Git 部署密钥（`.ssh`）。符号链接作为链接复制；指向旧网站文件夹内某处的链接，现在指向新网站中的同一位置。在 `public/.user.ini` 中，旧文件夹会被替换为新文件夹；
- 对于每个关联的数据库（MariaDB、MySQL 或 PostgreSQL），一个同类型的新数据库和用户，带有它数据的副本，并关联到新网站；
- 网站的后台程序，处于停止状态（见下文）。

副本就绪后，Nefo 会显示新的 MariaDB 和 MySQL 数据库的连接信息（PostgreSQL 的在 **数据库** 页面上）。应用自己的配置文件（例如 `.env` 或 `config.php`）中写的仍然是旧的数据库和用户：请把它们改为新的。提到旧文件夹的文件（例如应用设置的缓存）也还是旧的。

### 应用网站 {#app-websites}

应用网站的副本还会得到：

- 一个由 Nefo 选择的独立端口，应用会在 `PORT` 中得到它。自己设置端口的应用必须改为使用新端口；
- 相同的 **运行环境** 和 **启动命令（可选）**；在命令中，旧网站的文件夹会被替换为新文件夹。副本的服务 `panel-app-<user>.service` 会在文件和数据库复制完成后启动；
- `node_modules` 及其链接（`node_modules/.bin`），以及一个能在新文件夹中工作的 Python 虚拟环境 `app/.venv`：它的脚本、`pyvenv.cfg` 和 `.pth` 文件中的路径都指向副本的文件夹。依赖不会重新安装；
- 网站的后台程序，命令、文件夹和变量都相同（指向旧文件夹的路径已替换），但处于 **已停止** 状态：在副本使用它自己的数据库和队列之前，它们会处理原网站的数据。请在 **后台程序** 页面启动它们。

运行环境必须仍然已安装：如果某个 Node.js 版本、Python 或 Java 已从 **软件** 页面移除，在复制开始前就会被拒绝。

### Docker 应用 {#docker-apps}

Docker 应用网站的副本是一个新网站，里面是该应用的一个新安装：

- 与原网站相同的版本和镜像（即使应用商店中有更新的版本），有它自己的容器和端口，内存上限相同；
- `/var/lib/panel-apps/<name>` 中应用数据的副本，在原应用停止时制作：Nefo 停止它，复制数据，然后立即重新启动它。在副本中，属于原网站用户的文件会属于新网站的用户；
- 与原应用相同的账户和密码（复制的数据就是用它们创建的），和任何应用一样显示在 **应用商店** → **已安装** 下；
- 对于从面板获取地址的应用（应用的 `url`、`DOMAIN` 等设置），应用的地址会设为新域名。如果应用把地址保存在它自己的设置中，请在那里修改。

Nefo 会先检查副本需要的内存和磁盘（大约是应用数据的大小，再加 512 MB）。

Nefo 会拒绝克隆：

| 应用 | 原因 |
|---|---|
| n8n | 副本会把处于激活状态的工作流（计划和触发器）再运行一遍。请导出工作流，并导入到一个新的 n8n 中。 |
| Odoo | 副本也会运行计划动作和邮件服务器：它会发送同样的邮件，并收取和删除同一个邮箱的邮件。请备份它，或者安装一个新的 Odoo。 |
| 在应用商店出现之前安装的应用 | 请先更新它（**应用商店** → **已安装**），然后再克隆。 |

Uptime Kuma 这类监控应用的副本会检查同样的网站，并发送同样的通知：请在其中一个里暂停你不需要的部分。

### WordPress {#wordpress}

WordPress 网站像 [预发布副本](./wordpress#make-a-staging-copy) 一样复制：它的数据库总会被复制，`wp-config.php` 会指向副本，网站的地址会在所有地方被替换，所以副本立即就能工作。会请求搜索引擎不要收录它；如果副本是一个独立的网站，请在 WordPress 的 **Settings → Reading**（设置 → 阅读）中更改。与预发布副本不同，克隆不能推送回它来源的网站。

### 不会复制的内容 {#not-copied}

别名、证书、密码保护、重定向和防火墙设置、国家/地区拦截、文件锁定、定时任务、Git 部署设置、SFTP 访问、监控和备份计划。

如果某一步失败，Nefo 会移除它为副本创建的一切：网站、它的 Linux 用户、新数据库、复制的后台程序，以及 Docker 应用的新容器及其数据。原网站会继续运行。

## 删除网站 {#delete-a-website}

1. 打开网站的 **概览** 标签页。
2. 在 **删除此网站** 下，点击 **删除**。
3. 对话框会在 **一同移除：** 下列出随网站一起删除的内容（它的 Docker 应用和数据、SFTP 账户、定时任务、后台程序、监控、Git 部署设置、备份计划）。
4. 保持勾选 **先备份网站**（默认），或取消勾选。
5. 勾选 **同时删除它的数据库** 也会删除关联的数据库。不勾选时（默认），它们会留在 **数据库** 页面上，不关联任何网站。
6. 输入域名进行确认，然后点击 **备份并删除**（不备份时为 **删除**）。

### 先做的备份 {#the-backup-made-first}

勾选 **先备份网站** 时，Nefo 会先在这台服务器上做一份普通备份：网站的文件以及它的 MariaDB、MySQL 和 PostgreSQL 数据库；对于 Docker 应用，它的数据作为第二份 **应用** 类型的备份。只有备份成功后，网站才会被删除。如果备份失败，任务会停止，并提示“the backup failed, so example.com was not deleted”（备份失败，因此没有删除 example.com），什么都不会被移除。

- 备份名为 `example.com_before-delete_<date>-<time>.tar.gz`（Docker 应用的数据为 `<user>_before-delete_….tar.gz`），位于 `/var/backups/panel/site/example.com/`。
- 和你手动做的每份备份一样，它会一直保留，直到你在 **备份** 页面删除它。计划只删除它们自己生成的备份，而网站的计划会随网站一起移除，所以没有任何东西会删除它。
- 它只保存在这台服务器上：不会上传到远程存储。如果你想要一份远程副本，请从 **备份** 页面上传它。
- 删除作为带日志的任务运行。它的日志会写明备份的名称。

::: warning
没有备份的话，网站的文件（以及勾选了 **同时删除它的数据库** 时它的数据库）就无法找回。取消勾选 **先备份网站** 时，对话框会说明这一点。
:::

### 删除的网站能找回吗？ {#bring-a-deleted-website-back}

能，用删除前做的备份（或该网站的任何其他备份）。在 **备份** 页面上，恢复 `…_before-delete_…` 备份，并输入域名进行确认。恢复会重新创建网站，包括它的域名、别名、PHP 版本、重写规则、文件和数据库。被删除的数据库会带着它原来的密码回来，恢复的文件中写的就是这个密码；你保留的数据库会重新关联到该网站。

不会重新创建的内容：证书（在 **SSL / HTTPS** 标签页上重新获取）、定时任务、SFTP 访问、后台程序、重定向和密码保护。恢复会创建什么，见 [在新服务器上恢复](./restore-new-server#restoring-a-website-that-doesn-t-exist-here)。

Nefo 0.24.1 及以后版本创建的备份会记录网站的类型，所以应用网站（Node.js、Python、Java）会连同它的运行环境、启动命令、端口和内存上限一起恢复，反向代理网站会连同它的地址和选项一起恢复；请先在 **软件** 页面安装应用的运行环境。旧版本创建的备份只记录 PHP 版本，所以这样的网站会恢复为静态网站：请先用相同的域名和类型重新创建它，然后再恢复。对于 Docker 应用，请先从 **应用商店** 在同一个域名上重新安装该应用，然后恢复它的 **应用** 类型备份。

### Nefo 会移除和保留什么 {#what-nefo-removes-and-keeps}

Nefo 会移除：

- 网站文件夹 `/var/www/example.com` 及其中的所有文件，包括 Git 仓库及其部署密钥
- Linux 用户和用户组，以及 SFTP 访问
- Web 服务器配置、密码文件和你自己的指令
- PHP-FPM 池、应用服务，或者 Docker 应用及其容器、数据和未使用的镜像
- 该网站的证书、页面缓存和 Web 服务器日志
- 网站的后台程序、以它的用户运行的定时任务、它的备份计划、监控和 Git 部署设置
- 网站在 **文件** 中的回收站，以及它被恶意软件扫描器隔离的文件
- 关联的数据库（如果你勾选了 **同时删除它的数据库**）

Nefo 会保留你已经做好的备份：它们留在 **备份** 页面上。

WordPress 预发布副本：删除有预发布副本的正式网站会保留副本，但副本无法再推送到正式网站；对话框会说明这一点。删除预发布副本不会改动它的正式网站。

网站的 Git 部署正在运行时，Nefo 会拒绝删除它（“服务器上正在运行另一个任务。请等待它完成。”）。勾选备份时，任务会等待在备份期间开始的部署完成。如果某个清理步骤失败，网站仍会从面板中移除，Nefo 会在“部分清理步骤失败：”下列出失败的步骤（先做备份时，在任务日志中列出）。

通过 API：`DELETE /api/sites/{id}`，请求体为 `{"confirm": "example.com", "delete_databases": false, "backup_first": true}`。带 `backup_first` 时，它返回 202 和任务。不带时，网站会立即被删除（返回 200 和警告）。
